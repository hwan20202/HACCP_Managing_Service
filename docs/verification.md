- Windows 11의 실제 서비스 등록·권한·재부팅 후 자동 시작
- 실제 Ubuntu 샌드박스 실행
- 회사 도메인·DNS·방화벽·HTTPS 인증서와 직원 PC의 인증서 신뢰
- 실제 운영 자료를 사용한 업무 기능 및 복구 훈련

Windows·macOS·Ubuntu용 GitHub Actions 설정은 준비했지만 GitHub에 연결하거나 실행하지 않았습니다. 이 기록은 **macOS에서 검증한 결과**이며 Windows·Ubuntu 실행 완료를 의미하지 않습니다.

## 다시 확인하기

### 시제품 데이터 Git 포함 검증 (2026-10-08)

- 초기 개발 테스트용 `data/legacy-prototype/src/js/data.js`를 Git 추적 예외로 추가했습니다. 자료 폴더의 추적 대상은 이 파일과 `data/README.md`뿐입니다.
- Git 스테이징 영역의 파일만 별도 임시 폴더로 내보냈습니다. 기존 `.env`·DB·PDF·엑셀 없이 `init`으로 새 환경과 DB를 생성했습니다. Python 의존성은 기존 가상환경을 사용했습니다.
- 이 임시 폴더에서 코드·형식·의존성 검사, Django 검사와 자동 테스트 19개가 통과했습니다.
- 임시 개발 서버의 `/`가 준비 안내 대신 시제품 HTML을 제공하고, `/prototype/data.js` 응답이 원본과 바이트 단위로 일치하는 것을 확인했습니다. `/test/`·정적 파일·헬스체크 및 비공개 경로 차단 HTTP 검사도 통과했습니다.
- 기존 자료 40개의 SHA-256이 보존 목록과 일치했습니다. 시제품 데이터의 체크아웃 시 줄바꿈 변환도 비활성화했습니다.

### 검사 명령

README에 따라 설치 후 가상환경의 Python으로 다음을 실행합니다.

```text
python scripts/project.py check
python scripts/smoke_process.py
```

`smoke_process.py`는 빈 포트에 임시 개발 서버를 실행하고 HTTP 검증 후 종료합니다. 운영 경로는 `docs/deployment.md`의 세 터미널 절차를 사용합니다.
