## macOS CI 시간 초과 진단과 수정 (2026-10-09)

`7cb7bb9`의 [실패 실행](https://github.com/hwan20202/HACCP_Managing_Service/actions/runs/37858814802)에서도 Windows·Ubuntu는 통과하고 macOS의 `smoke_process.py`만 약 20초 후 `Server startup timed out.`으로 실패했습니다. CI Python은 3.14.7이며, 로컬 검증은 macOS 26.5.2 / Python 3.14.4에서 수행했습니다.

| 조건 | 결과 |
|---|---|
| 수정 전, 로컬 기본 환경 | 전체 HTTP 검사 약 0.26초에 통과. 자연 재현되지 않음 |
| 수정 전, 자식 서버의 `socket.getfqdn("127.0.0.1")`에 35초 지연 주입 | 역방향 DNS 호출을 확인했고 20.31초 후 동일한 시간 초과 발생 |
| 수정 후, 같은 지연 조건 | 해당 DNS 호출 없이 전체 HTTP 검사 약 0.39초에 통과. Django 시작 검사도 실행 |
| 시작 실패 진단 | 잘못된 설정 모듈을 지정하자 실제 `ModuleNotFoundError`와 자식 프로세스 종료 코드 출력 |
| 회귀 검사 | 역방향 DNS를 호출하면 실패하도록 설정한 실제 HTTP 테스트 1개 및 기존 Django 테스트 19개 통과. Ruff 검사·형식 검사 통과 |

Django 개발 서버가 사용하는 Python HTTP 서버는 시작 중 `socket.getfqdn()`을 호출합니다. [actions/setup-python #1223](https://github.com/actions/setup-python/issues/1223)에는 macOS 15·26 러너에서 같은 조회가 30초 이상 지연되는 현상이 보고되어 있습니다. 현재 증상과 맞는 유력한 원인이지만, 기존 CI가 서버 출력을 버렸으므로 해당 실패 실행의 내부 호출 위치까지 확인한 것은 아닙니다.

수정은 자동검사 전용 서버에서 이 DNS 조회를 생략하도록 한정했습니다. 서버 출력 보존, 시작 15초 후 호출 위치 진단, 마지막 연결 오류 표시도 추가했습니다. 시작 대기 한도는 20초를 유지하며 CI의 HTTP 검사 단계 전체에는 2분 상한을 설정했습니다.

**수정본의 GitHub CI는 아직 실행하지 않았습니다.** 커밋·push 후 세 OS 결과를 확인해야 해결을 확정할 수 있습니다. 기존 이슈 #1은 그 결과를 확인할 때까지 해결 완료로 표시하지 않습니다.

## 다시 확인하기

### 문서·구성 일치 확인 (2026-10-09)

`a3c28bc`의 코드와 검토 중인 문서를 기준으로 Git 추적 파일만 임시 폴더에 복사해 확인했습니다. 기존 환경 파일·DB·PDF는 복사하지 않았으며, Python 의존성과 Caddy 실행 파일은 로컬에 설치된 버전을 사용했습니다.

- README의 초기화·전체 검사·정적 파일 수집 성공. 자동 테스트 19개, Ruff 검사·형식 검사 통과.
- 초기화 반복 시 환경 파일 보존 확인. 별도 환경 파일과 공백이 있는 데이터 경로에서도 DB·정적 파일 생성 위치 일치.
- Django 개발 서버와 Caddy → Waitress 경로에서 초기 화면·`/test/`·참조 자산 16개·시제품 데이터의 원본 바이트·헬스체크·비공개 경로 차단 확인. 별도로 준비하지 않은 기준서 PDF는 예상대로 404.
- HTTPS 설정의 배포 점검은 문서에 적힌 `security.W005`, `security.W021`만 발생.
- README의 새 업무 앱 생성 절차를 임시 폴더에서 실행하고 Django 설정 검사 통과.
- 문서 간 로컬 링크 13개 확인. 기존 자료 40개의 SHA-256 일치, Git의 자료 추적 대상은 README와 시제품 `data.js` 두 파일임을 확인.

이 확인은 로컬 macOS에서 수행했습니다. Python 설치 명령 자체, 실제 회사 HTTPS 인증서, 대상 Windows 서비스 등록·재부팅은 이번 확인 범위에 포함되지 않습니다.

### 시제품 데이터 Git 포함 검증 (2026-10-08)

- 초기 개발 테스트용 `data/legacy-prototype/src/js/data.js`를 Git 추적 예외로 추가했습니다. 자료 폴더의 추적 대상은 이 파일과 `data/README.md`뿐입니다.
- Git 스테이징 영역의 파일만 별도 임시 폴더로 내보냈습니다. 기존 `.env`·DB·PDF·엑셀 없이 `init`으로 새 환경과 DB를 생성했습니다. Python 의존성은 기존 가상환경을 사용했습니다.
- 이 임시 폴더에서 코드·형식·의존성 검사, Django 검사와 자동 테스트 19개가 통과했습니다.
- 임시 개발 서버의 `/`가 준비 안내 대신 시제품 HTML을 제공하고, `/prototype/data.js` 응답이 원본과 바이트 단위로 일치하는 것을 확인했습니다. `/test/`·정적 파일·헬스체크 및 비공개 경로 차단 HTTP 검사도 통과했습니다.
- 기존 자료 40개의 SHA-256이 보존 목록과 일치했습니다. 시제품 데이터의 체크아웃 시 줄바꿈 변환도 비활성화했습니다.

### 검사 명령

README에 따라 설치 후 가상환경의 Python으로 다음을 실행합니다.


`smoke_process.py`는 빈 포트에 임시 개발 서버를 실행하고 HTTP 검증 후 종료합니다. 운영 경로는 `docs/deployment.md`의 세 터미널 절차를 사용합니다.
