## 시작 상태

- 이번 한 번만 별도 새 QA 경로에 migrate → 문서 양식 → `seed_qa_inventory --stage run`을 실행한다. 이전 DB·첨부 전체는 백업하고 원래 경로에도 보존한다. 사용자가 추가한 기록과 잘못 투입한 홍삼분말 기록은 새 데이터에 복사하지 않는다.
- 시작 자료: 품목 24, BOM 3, LOT 33, 수불 58, 문서 93, 완료 생산배치 3개. 완료 배치는 녹용분말·한동 효력환·녹용추출분말이다. 생산 완료가 문서 결재 완료를 의미하지 않는다.
- `QA_REF` 담당자를 선택한다. 신규 배치 메모는 `수동QA-날짜-이름-번호`로 구분한다. 서버 자료를 테스트하며 로컬 개발 DB와 혼동하지 않는다.

- 테스트 중 Seeder·초기화·flush·선별 삭제를 재실행하지 않는다. 취소·정정 이력과 기존 문서는 유지한다.

### Q03 서버 검증 우회 시도 (PC 브라우저 개발자 도구)

QA 사이트에서 인증된 상태로 실행한다. `batchId`는 **직접 만든 진행 중 녹용분말 배치 ID**, `lotId`는 사용 가능한 홍삼분말 LOT ID, `staffId`는 QA 담당자 ID로 바꾼다. 품목/배치 ID를 임의로 추측하지 말고 API 조회나 화면의 네트워크 응답으로 확인한다. 전후 캡처는 같은 LOT 재고, 오늘 수불, 배치 투입 행을 비교한다.

```javascript
const batchId = /* 진행 중 녹용분말 배치 ID */ 0;
const lotId = /* 홍삼분말 LOT ID */ 0;
const staffId = /* QA_REF 담당자 ID */ 0;
if (!batchId || !lotId || !staffId) throw new Error('실제 QA ID를 먼저 입력하세요');
const csrf = decodeURIComponent(document.cookie.match(/(?:^|;\s*)csrftoken=([^;]+)/)?.[1] || '');
const response = await fetch(`/api/v1/inventory/batches/${batchId}/usages/`, {
  method: 'POST', credentials: 'same-origin',
  headers: {'Content-Type': 'application/json', 'X-CSRFToken': csrf},
  body: JSON.stringify({lot_id: lotId, quantity: '0.1', staff_id: staffId,
    idempotency_key: crypto.randomUUID()}) // bom_line_id를 의도적으로 생략
});
console.log(response.status, await response.json()); // 400 + BOM 원료 제한 안내
```

다른 BOM의 `bom_line_id`를 명시해도 거부되어야 한다. 테스트 전후 재고·수불·투입 행을 캡처한다. 정상 대체 원료 시험에는 위 코드를 재사용하지 말고 화면을 사용한다.

## 확정하지 않은 업무 기준

- 가용재고 조회/시작 검사는 현재 상태의 확인이다. **예약이 아니다.** 여러 배치가 같은 재고로 시작 검사를 통과할 수 있으나 실제 투입은 다시 검증하고 한 트랜잭션으로 차감한다.
- 완료 시 산출 없음·필수 재고 원료의 순투입량 0 이하·보류를 차단한다. 계획 대비 정확한 투입 일치, 실제 수율 상하한, 허용 오차, 공정용수 기록 완료 여부는 업무 기준이 확정되지 않아 강제하지 않는다.
- 재고 관리 제외 원료는 LOT 투입 대상이 아니다. 대체 원료는 등록된 BOM 관계와 kg/g 환산을 따른다.
- 추천은 소비기한 오름차순 → 입고/제조일 → LOT ID. 날짜 없는 LOT은 날짜 있는 LOT 뒤다. 추천 결과를 사용자가 확인한다.
- 계획 배치 삭제, 재고 예약, 포장·출고, 역할별 권한, CCP 이탈 자동 HOLD는 이번 구현 범위가 아니다.
