# 실제 자료 기반 QA 데이터 선정

## 사용 원칙과 검토 범위

사용자가 제공한 v6_2·v7은 둘 다 참고본이다. 버전 번호로 우선순위를 정하지 않는다. 원본 엑셀·Google Sheets는 수정하지 않았으며, 이번 검토로 최종 마스터를 만들거나 실제 자료를 로컬 DB에 적재하지 않았다.

두 로컬 엑셀의 저장된 셀 값과 BOM을 대조했다. 수식은 재계산하지 않았다. Google Sheets는 탭 목록을 확인한 뒤 `한동 효력환(240731)!A1:Z35`, `녹용추출분말!A1:Z25`를 표본으로 읽었다. 효력환 투입량은 `A6:H23`의 서식 없는 숫자로 추가 확인했다. Google 문서 전체 37개 탭을 모두 검토한 결과는 아니다.

기본 원칙은 확정된 회의 정책 > 참고본의 설명·예시다. 두 참고본의 일치도는 QA 후보 선정에 사용하고, 일치한다는 이유만으로 미확정 업무 사실을 확정하지 않는다.

## 1. 비교 결과

| 대상 | 결과 | 해석 |
|---|---|---|
| 원료 코드 행 | v6_2 176개, v7 175개 | v6_2에만 `1000038 정제수` 존재 |
| 공통 원료 175개 | 코드별 약어·표준명·제조국 값 일치 | 이 필드의 공통 후보. 공급처·상태·모든 주석까지 동일하다는 뜻은 아님 |
| 반제품 코드 행 | 양쪽 85개 | 코드별 제품명·식품유형·1환 중량·소비기한 문구 일치 |
| 반제품 BOM | v6_2 344행, v7 322행 | 85개 제품을 투입코드·1kg 사용량·단위·대체코드의 집합으로 비교 |
| BOM 후보 | 제품 63개 일치, 22개 다름 | 행 순번만 바뀐 것은 차이로 세지 않음. 22개는 우선 자동 적재 대상에서 제외 |

정제수 처리가 여러 차이를 만든다. 차이가 난 22개 제품 모두가 배합 오류라는 뜻은 아니다. 공정용수는 재고 비관리하되 BOM에서 참고하는 현재 모델과, v7의 '정제수를 BOM에서 제거'하는 표현은 구분한다. 정제수 처리 정책을 이 파일에서 새로 바꾸지 않는다.

양쪽의 소비기한 유무 열 위치도 다르다. v6_2는 원료 마스터 O열과 P열의 유무·근거, v7은 D열의 유무를 사용한다. 위치만으로 비교하거나 가져오면 안 된다. v6_2의 유무 근거에 '추정/PM 확인'이 포함되어 있어, 참고본 Y/N을 실제로 확인된 정책으로 일괄 확정하지 않는다.

녹용추출분말의 상위 배합은 일치하지만 투입품 `3000033 녹용추출액(고형분1.5%)`의 자체 제조 BOM은 두 참고본에서 다르다. 따라서 첫 QA에서는 이 투입품을 구매 입고 또는 명시적 기초재고로 준비하고, 그 자체 제조 배합은 재현하지 않는다. 구매분과 자체 생산분이 동일 규격인지는 별도 확인 대상이다.

`3000024 녹용추출분말(K)`의 배합 수치는 일치하지만, 투입 추출액의 품목 분류에 확인 필요 주석이 있으므로 초기 후보에서 보류한다. 제품명이 비슷해도 고형분 0.3%와 1.5%를 동일 품목으로 합치지 않는다.

## 3. 실제 대장으로 확인한 시나리오

### 효력환: 5kg 제조와 환 단위 물류 기록

Google `한동 효력환(240731)!A6:H23`에는 2024-09-03 생산, 생산량 5kg, 18개 투입품이 있다. 사양벌꿀 2.25kg, 효모·산수유분말·당귀뿌리 각각 0.4kg, 녹용분말 0.2kg 등이다. 표준 1kg BOM을 5배 한 사용량과 대응한다.

0.5% 원료 두 개는 표시상 각각 0.03kg이지만 실제 숫자는 각각 **0.025kg**이다. 표시값을 다시 합산하면 반올림 차이가 생기므로 서식 없는 실제 숫자로 투입 합계를 계산한다.

오른쪽 물류 기록 `J6:R8`은 1,323환 입고 후 560환·56환·707환 출고로 잔량 0이다. 이는 5kg 생산 기록과 단위·기록 시점이 다르다. 5kg를 1,323개로 곧바로 치환하지 않는다. 환당 3.75g을 적용하면 1,323환은 4.96125kg이나, 이를 벌크 생산 실적으로 확정하려면 포장 과정의 손실·선별 포함 여부를 확인해야 한다.

### 추출분말: 원료 반제품 투입·부분 사용·여러 LOT

Google `녹용추출분말!A7:H8`에는 2025-01-05 추출액 22.06kg + 덱스트린 7.94kg, 생산량 30kg가 기록돼 있다. 참고본 BOM의 73.53%/26.47%와 소수점 표시 수준에서 대응한다.

`J7:R13`에는 첫 재고 30kg에서 0.2kg씩 두 번 사용한 뒤 29.6kg가 남고, 다음 입고 42.5kg 이후 70kg 사용·잔량 2.1kg가 기재되어 있다. 29.6+42.5-70=2.1로 총량은 맞지만, 소비기한별 LOT에서 정확히 얼마씩 차감했는지는 대장이 직접 보여주지 않는다. FEFO로 29.6kg·40.4kg를 차감하는 것은 **QA에서 정한 기대 동작**으로 구분한다.

또한 `A11:H12`의 생산량 43kg와 물류 입고 42.5kg는 다르다. 이 차이를 임의의 손실 또는 단순 오기로 확정하지 않는다. 물류 출하는 현재 MVP 밖이므로, 해당 수량 패턴을 생산 투입으로 바꿔 시험할 경우 '실제 출하 재현'이 아닌 '실제 기록에서 수량 패턴을 가져온 가상 생산 투입'이라고 표시한다.

## 4. 참고본에서 그대로 가져오지 않을 정책

| 설명·예시 | 처리 |
|---|---|
| v7 `원료입고_LOT!A2`: 같은 날 같은 회사 2회 입고를 한 행으로 | 현재 확정 범위는 입고 건별 LOT·중복 접미사 유지. 합치지 않음 |
| v7 `포장기록_데모!A2`: 포장일로 LOT·소비기한 새 생성 | PM의 제조 시작일·분할 포장 LOT 유지 방향과 충돌. 포장 기능도 MVP 밖이므로 제외 |
| 옛 제조대장의 '포장일로부터 24개월' 문구 | 과거 기록 설명으로 보존. 신규 QA 날짜 계산은 합의된 제조 시작일 기준 정책 사용 |
| 참고본의 Y/N과 추정 근거 | QA 시나리오 상태로 명시해 사용할 수 있으나 실제 원료의 확인된 유무로 자동 확정하지 않음 |
| 기준서 우선이라는 옛 안내 | PM의 제조방법설명서 우선 답변과 구분. 충돌 배합은 원문 없이 임의 선택하지 않음 |
| 동일 자료의 LOT 예시 또는 전역 일자 순번 | 현재 품목별·배치별 채번 정책을 대신하지 않음 |

## 5. 준비할 QA 묶음

실제 자료에서 확인한 품목·배합과 테스트를 위해 만든 날짜·입고 수량·판정은 별도 표시한다.

| 시나리오 | 준비 데이터 | 기대 결과 |
|---|---|---|
| 소비기한 있는 원료 반복 입고 | 같은 원료·소비기한으로 입고 3건 | 소비기한 채번, 접미사 -2·-3, 입고·문서 개별 유지 |
| 소비기한 없는 원료 | 명시적 NONE, 입고일 2종 | 입고일 채번, 없음 표시, 오래된 입고 순 추천 |
| 미확인 거부 | 신규 RAW 입고에 날짜·상태 누락 | 입고 거부, LOT·재고·문서 부분 생성 없음 |
| 동일 품목 다중 공급처 | 같은 품목, 서로 다른 공급처·LOT | 공급처는 입고별 보존, 재고 추천은 품목 내 비교 |
| 녹용분말→효력환 | 원료 녹용 생산 투입, 반제품 산출 후 효력환 투입 | 재고 차감·산출과 정·역추적 연결 |
| 구매 반제품→추출분말 | 고형분1.5% 추출액 구매 입고, 덱스트린 | 구매 반제품에도 입고 문서 생성, 2품목 투입 |
| 분할 산출·재시도 | 같은 배치 2회 산출, 두 번째 요청 재전송 | 같은 LOT 누적, 중복 수불 없음 |
| 다일 공정 | 시작일과 완료일 다르게 | LOT·소비기한은 제조 시작일 기준 |
| 부적합·HOLD·만료·재고 부족 | 별도 테스트 LOT | 허용되지 않은 투입 거부·재고 보존 |
| 정정·취소 | 후속 참조 유무·문서 상태가 다른 건 | 기존 정정·취소 정책과 롤백 검증 |

과거 날짜를 그대로 넣으면 현재일 기준 만료 LOT이 될 수 있다. 역사 재현용과 현재 화면 조작용 데이터를 분리하고, 현재용 날짜를 이동할 때 모든 관련 날짜를 일관되게 이동한다. 아직 결정하지 않은 CCP 자동 HOLD나 취소 문서 정책을 테스트 데이터로 암묵 확정하지 않는다.

## 6. 적재 전 주의사항 및 남은 입력

현재 로컬 DB에는 `1000001` 등 실제 자료와 번호가 같은 가상 품목이 있다. 예를 들어 가상원료A와 실제 벌꿀(국산)은 같은 코드라도 다른 물건이다. 기존 가상 마스터 위에 실제 마스터를 덮어쓰지 않는다. 실제 자료 기반 QA는 별도 데이터 디렉터리·DB를 만들고, 기존 샘플 데이터를 섞지 않는 방식이 적합하다.

사용자가 최종 엑셀을 만들 필요는 없다. 이 자료는 품목·BOM과 생산 사례를 준비하는 데 충분하다. 실제 입고일·공급처·소비기한·수량·판정이 있는 원료수불대장이 있으면 현실적인 입고 패턴을 더할 수 있다. 없으면 입고값은 가상으로 명시해 준비한다. 자체 생산·구매분의 동일 품목 여부는 규격·고형분·단위·대체 가능성을 확인한 경우에만 실제 사례로 취급한다.
