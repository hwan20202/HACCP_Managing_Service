# 생산일지 조회 데이터 반영

2026-10-23 · 작업 브랜치 `fix/inventory-receipt-guidance`

문서 담당자 요청 P1~P5·M1~M11 중 배합비(M8a)를 제외한 생산·수불 제공 데이터를 구현했습니다. 문서 영역의 `sources.py`와 생산일지 화면 반영은 담당 영역에서 진행합니다.

## 반영 사항

- 품목에 nullable 문자열 `manufacturing_report_number`를 추가했습니다. 외부 보고번호를 등록하는 값이며 내부 키로 생성하지 않고 UNIQUE 제약도 없습니다. 기존 품목은 NULL입니다.
- 품목 API와 기준정보 CSV 가져오기에서 보고번호를 지원합니다. 앞자리 0을 보존하고 공백은 NULL로 처리합니다. 해당 컬럼이 없는 기존 CSV로 갱신할 때는 보고번호를 보존합니다.
- `v_doc_batch`의 기존 컬럼·순서·의미를 유지하고 `food_type`, `manufacturing_report_number`를 끝에 추가했습니다.
- `v_doc_batch_bom_line`은 배치가 참조하는 BOM의 모든 구성 행을 제공합니다. 미투입 원료·재고 비관리 원료도 포함하고 `bom_line_id`, `line_no`, 원산지, 단위, 계획 기준량을 제공합니다. 계획량이 없으면 기준량은 NULL이며, 산출 후에도 계획 기준을 유지합니다.
- 기준량은 기존 서비스와 동일하게 소수점 6자리까지 올림합니다. SQLite 정수 곱셈의 overflow로 실수가 되는 문제를 피하도록 정수 몫·나머지로 계산합니다.
- `v_doc_batch_usage`는 투입별 실제 품목·원래 BOM 행·LOT·원 수량·정정 반영 수량·발생일을 제공합니다. 과거 미연결 기본 원료는 동일 배치 BOM의 품목 id로 연결합니다. 대체 원료는 원래 원료와 실제 원료·단위를 구분합니다.
- 최초 작업일은 순투입량이 양수인 행만 대상으로 산정하도록 계약에 명시했습니다. 전량 정정된 기록은 뷰에 보존됩니다. 정제수 등 미집계 원료는 문서에서 직접 입력합니다.

뷰별 전체 컬럼과 조회 예시는 [연동 인터페이스](inventory-document-interface.md)의 ‘생산일지 추가 계약’에 있습니다. 품목 전용 신규 입력 화면과 배합비 필드는 이번 작업에 포함하지 않습니다.

## 검증

- 신규 Django 테스트 10건: 미투입·정제수·순서·원산지·계획량 NULL·계획/실산출 구분·큰 수량 정밀도·BOM 없음·부분/전량 정정·투입일·대체 원료 kg/g·과거 연결·보고번호 API/CSV 보존을 확인했습니다.
- 격리 메모리 DB에서 0008 → 0009 → 0008 → 0009 적용을 확인했습니다. 기존 배치 뷰의 컬럼 순서와 기존 품목을 보존하며 재적용할 수 있습니다.
- 로컬 DB를 `data/backups/before-document-sources-20261023-204351.sqlite3`로 백업한 뒤 미적용 상태였던 0008과 신규 0009를 적용했습니다. 기존 모든 업무 테이블의 기존 컬럼 값을 적용 전후 비교해 동일함을 확인했고 SQLite integrity check를 통과했습니다. 보고번호는 모두 NULL로 유지했습니다.
- 로컬 DB에서 배치 뷰 4행, BOM 뷰 22행, 투입 뷰 23행을 조회했습니다. 로컬 HTTP 서버에서 품목 목록·상세 API의 보고번호 필드 노출을 확인했습니다.
- Ruff 검사·포맷 검사와 `makemigrations --check --dry-run`을 통과했습니다.
- `scripts/project.py check` 전체 검사를 통과했습니다. 스크립트 테스트 15건 통과, Django 테스트 1,051건 중 1,015건 통과·환경 조건에 따른 36건 건너뜀입니다. 최초 샌드박스 실행의 임시 디렉터리/localhost 권한 오류는 실행 권한을 조정한 재실행에서 해소됐습니다. 기존 개발 DB의 문서 역할 설정 경고는 이번 변경과 별개로 남아 있습니다.
