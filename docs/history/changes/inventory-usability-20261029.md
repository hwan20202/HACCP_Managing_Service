# BOM 저장 및 수불대장 사용성 개선

## BOM

- 단위 환산·숫자 표기를 정규화하여 변경 없는 저장을 화면과 API에서 차단한다. 원료·대체 원료의 나열 순서만 달라도 새 버전을 생성하지 않는다.
- 사용 상태·메모 변경은 기존 버전과 원료 행을 유지하며 감사 이력을 기록한다. 상태 변경은 담당자와 사용 여부만으로 PATCH할 수 있다.
- 목록에는 조회·수정, 새 버전, 삭제, 활성화를 표시한다. 모든 활성화 버튼은 같은 문구를 쓰고, 활성 상태만 연한 하늘색으로 구분하며 품목 내 맨 위에 표시한다. 최신 원격 `main`을 기준으로 품목별 펼침·접기와 펼친 상태 유지를 복원했다. 생산 연결 이력이 있는 BOM의 삭제는 비활성화한다.
- 활성화 확인 후 품목의 다른 버전은 비활성으로 전환한다. 전환은 저장과 같은 트랜잭션에서 처리하며 각 버전의 감사 이력을 남긴다. 기존 생산지시의 BOM 참조와 진행 상태는 유지하고, 이후 신규 생산지시는 활성 버전을 기본으로 선택한다.
- 현재 활성화된 버튼을 다시 누르면 비활성화 여부를 확인한다. 비활성화해도 연결된 생산지시는 기존 배합을 유지한다.
- 비활성 버전에 진행 중인 생산지시가 연결돼 있으면 상태 아래 작은 회색 한 줄로 `생산지시 연결 · 완료까지 기존 배합 유지`를 표시한다. 여러 건은 첫 생산지시와 나머지 건수로 요약하고, 툴팁에는 전체 생산지시를 표시한다. 진행 중인 생산이 없어지면 안내도 사라진다. 신규 생산 선택에서는 전환 즉시 비활성화되므로, 별도의 미래 비활성화 예약으로 안내하지 않는다.
- 새 버전 저장 시 `저장 후 활성화`, `비활성으로 저장`, `취소`를 선택한다. 비활성 저장은 기존 활성 버전을 유지하며, 취소는 저장하지 않는다.
- 저장 방식은 `새 버전으로 저장 (권장)`과 `이 버전에 덮어쓰기`로 구분한다. 미사용 버전은 확인 후 덮어쓸 수 있다. 생산에 연결된 버전은 덮어쓰기 선택을 비활성화하고 사유를 표시하며 API에서도 명시적인 덮어쓰기를 거부한다.

## 수불대장

- 전체·입고·출고, 검색, 조회 기간, 이전·다음 달, 표시 단위를 기본으로 노출한다.
- 기간 단축 선택과 날짜 직접 입력을 조회 기간 메뉴에 모은다. 직접 입력은 적용 시 검증하며 잘못된 기간은 현재 조건을 바꾸지 않는다. 최근 기간은 월말·윤년을 고려한다.
- 취소 입고 표시, 정렬 설정을 상세 조건에 배치한다. LOT 번호는 기본 검색이 포괄하므로 별도 상세 조건을 두지 않는다. 적용 중인 상세 조건은 접힌 상태에서도 요약한다.
- 표 머리글에서도 정렬 방향을 전환할 수 있다. 엑셀·인쇄는 내보내기, 나머지 보조 작업은 더보기로 묶는다.

## 활성 BOM 정책 (품목당 0~1개)

- 활성 BOM은 새 생산계획에 자동 적용되는 버전이며 품목당 0개 또는 1개다. `0010`이 기존 중복 활성을 기본 선택 규칙대로 정리하고, `0011`이 부분 유니크 인덱스 `ux_boms_one_active_per_item`으로 DB에서 보장한다. 저장은 다른 버전을 먼저 비활성화한 뒤 새 버전을 저장한다. 동시 변경 충돌은 409로 안내한다.
- 이전 버전을 쓰는 기존 생산지시는 `bom_id`로 고정되어 비활성이어도 끝까지 진행된다. BOM 관리에는 `활성`, `이전 버전 · 진행 중 N건`(계획·진행 상태만 집계), `비활성`으로 표시한다.
- 활성 BOM이 없으면 생산계획 등록을 거부하고 계획 화면에 BOM 관리로 가는 안내를 표시한다. 계획 화면에서 확인한 BOM이 그사이 바뀌면 등록을 거부하고 새 버전을 안내한다. 명시한 `bom_id`(과거 기록 입력)는 적용일 검사를 하지 않는다.
- 시작 전 계획이 이전 버전이면 상세를 열 때와 생산 시작 때 `BOM이 v1 → v2로 변경되었습니다` 창을 띄운다. `POST /api/v1/inventory/batches/{id}/switch-bom/`은 한 트랜잭션에서 기존 계획을 취소하고 계획일·수량·제조일·메모를 복사해 활성 BOM으로 재지시한다. 배치번호는 새로 정하고 원료 배정은 복사하지 않으며, 양쪽 감사 이력에 상대 배치번호를 남긴다.
- BOM 목록 응답에 `open_batch_count`, 배치 상세에 `bom_is_active`·`active_bom`, 계획 미리보기에 `bom_problem`을 추가했다.
