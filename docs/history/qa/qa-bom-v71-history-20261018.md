## 입고 LOT 분리와 재고 표시

10/18 사용자 설명 및 제공된 9/30·10/7 회의 정리 2.1: PM은 동일 LOT 관리도 허용했고, 성적서 등이 다르면 구분하도록 했다. 입고별 LOT 분리는 구현 편의로 선택한 방식이다. 현업의 의무 규칙과 구분한다.

현재 내부 LOT별 잔량을 유지하면서 품목별 합계에서 총재고를 보여주는 것은 일관된 설계다. 예: 덱스트린 입고 10/0.4/0.3kg → 수불 3건, 내부 LOT 3개, 품목 총재고 10.7kg. 총재고와 사용 가능 재고는 구분해야 한다. 한 입고분이 보류·부적합이면 총재고에 포함되어도 사용 가능량에는 포함되지 않는다.

화면은 품목별 총재고·사용 가능·사용 불가와 LOT별 잔량을 함께 보여준다. 후속 사용자 요청에 따라 수불대장 `현재고` 탭을 왼쪽 품목 합계 / 오른쪽 선택 품목 LOT 목록으로 변경했다. LOT 관계는 변경하지 않았다.

같은 소비기한은 같은 제조 LOT라는 증거가 아니다. 접미사를 지우거나 소비기한만으로 합산한 행을 실제 LOT처럼 선택·차감하면 추적이 모호해진다. 향후 같은 공급처 제조 LOT를 묶어 보고 싶다면, 합산 표시 아래에 내부 LOT/입고분을 유지하고 실제 투입을 어느 입고분에서 차감했는지 기록해야 한다. 공급처·성적서 동일 여부와 구분 기준은 별도 합의할 항목이다.

## 추가 데이터와 적재 방식

새 명령: `seed_qa_history`. 기존 QA 기준 묶음에 별도로 추가한다. 기존 `seed_qa_inventory`를 날짜를 바꿔 재실행하는 방식은 사용하지 않는다.

- 기본 실행은 적재 계획만 출력한다. `--apply`에서만 DB 백업 후 한 트랜잭션으로 추가한다.
- `qa_dataset/reference-v1`이 있는 개발·허용된 전용 QA DB만 대상이다. 운영 설정과 허용되지 않은 QA는 거부한다.
- `qa_dataset/history-v1` 완료 기록으로 재실행 중복을 방지한다. 적재 후 사용자 거래가 있어도 다시 초기값으로 맞추지 않는다.
- 기존 거래·재고·문서·품목·BOM을 덮어쓰지 않는다. 실제 코드 1000004/1000005/1000040/3000014와 기존 검토 1kg BOM을 확인한 뒤 재사용한다.
- 기존 LOT와 구분되는 새 LOT만 입고·사용·정정한다. 직원 `QA_HISTORY`, 공급처 `QA_HISTORY_1/2`, 요청키·메모·공급처 LOT의 `QA-HISTORY-`로 가상 거래를 식별한다.
- 과거 날짜에 유효한 채번 규칙이 없으면 현재 규칙의 형식을 복제한 **과거 QA용 규칙을 추가**한다. 기존 규칙의 날짜·형식을 수정하지 않는다.
- 모든 날짜·수량·공급처·검사 결과는 QA 가정이다. 현재 검토 BOM을 명시 선택한 합성 이력이며 실제 과거 거래/당시 유효 BOM 재현이 아니다.
- 보고서 `DATA_DIR/qa/QA-HISTORY-v1.json`에 LOT 번호·품목·잔량·월별 기대값·수동 QA 배치 ID를 기록한다. 기존 사용자 거래를 포함한 화면 전체 합계와 추가 묶음만의 합계를 혼동하지 않는다.

2026-10-18 기준: **2025-10·11월, 2026-03·05·08·09·10월**에 입고 및 제조 투입·분할 산출을 준비한다. 매월 1일 원료 입고, 1일 1kg 투입, 2일 0.4+0.6kg 산출·완료다. 매월 입고량은 10~16kg으로 다르다. 3·6개월·1년 조회에 포함되는 거래가 달라지게 배치했다. 월초 1~2일에 명령을 실행하면 미완료된 현재 월은 제외한다.

9/30 입고 2kg → 10/1 조정 출고 0.5kg 별도 사례는 **10월 이월 2 / 출고 0.5 / 기말 1.5kg**를 확인한다. 정정·반품·폐기·취소는 서버 서비스로 미리 생성한 이력이며 일반 화면에 모든 입력 기능이 있다는 뜻은 아니다.

## 서버 적재 준비 명령

이번 작업에서는 서버 접속·배포·서버 DB 적재를 하지 않는다. 아래 명령은 새 코드가 배포된 뒤 사용한다. 기존 기준 묶음의 재설치/초기화는 필요 없다.

```bash
# 기존 서버의 전용 QA 환경 파일을 사용. 적재 허용 설정 필요.
export HACCP_ENV_FILE=/etc/biodot/qa.env

# 기본: 조회/계획 확인, DB 변경 없음
.venv/bin/python backend/manage.py seed_qa_history --settings=config.settings.qa --date 2026-10-18

# 실제 추가: 직전 DB 백업 후 적재
.venv/bin/python backend/manage.py seed_qa_history --settings=config.settings.qa --date 2026-10-18 --apply
```

실제 서버의 환경 파일·가상환경 경로에 맞춰 실행한다. 쓰기 작업이 없는 시간에 앱 계정으로 실행하고, 기존 배포 절차의 DB+첨부 백업도 유지한다. 추가 명령의 DB 백업은 첨부 백업을 대신하지 않는다. 소스 변경은 아직 커밋/배포 패키지에 포함하지 않았다.

## 후속 요청: 품목/LOT 동시 표시와 데이터 보존

- 원료·부자재·완제품 수불대장 → **현재고** 탭: 품목별 합계와 선택 품목의 LOT별 현재고를 동시에 표시한다. 품목명을 선택하면 오른쪽 목록이 바뀌고, LOT를 선택하면 해당 수불 내역으로 이동한다.
- 총재고·사용 가능·사용 불가, LOT별 판정·소비기한·사용 우선순위·입고일/제조일을 확인한다. 전체 LOT·수불 이력 버튼에서 기존 상세창도 사용할 수 있다.
- 검색으로 선택 품목이 사라지면 첫 결과로 선택을 옮긴다. 결과가 없으면 LOT 목록도 비운다. 소진 LOT 포함 옵션을 제공한다. 소비기한/LOT 검색 결과와 품목 전체 합계의 범위 차이를 화면에 명시한다.
- 현재고 엑셀은 품목 합계와 오른쪽에 표시된 선택 품목 LOT 목록 두 시트다. 좁은 화면에서는 두 표가 위아래로 표시된다.
- JavaScript 구문 검사와 기존 UI 로직 검사에 품목 전환·검색 후 선택 복원·빈 결과 검사를 추가해 통과했다.
- 별도 로컬 서버와 전용 헤드리스 Chrome에서 동시 표시, 품목 선택, 상세창, 상세창 사용 후 다른 품목 LOT 이동, 검색·빈 결과, 두 시트 다운로드 데이터, 800px 세로 배치를 확인했다. JavaScript 예외 0건. 1600px/800px 캡처를 직접 검토하고 LOT 현재고가 첫 화면에 보이도록 열을 정리했다.
- 같은 검증 DB에서 원료 수불을 이번 달/3개월/6개월/1년으로 조회한 실제 화면 행 수는 49/54/56/60이었다. 기준 묶음과 추가 묶음을 함께 본 결과라 위의 추가 묶음만 집계한 24/33/37/45와 다르다.
- 서버 DB에는 아직 추가하지 않았다. 코드 배포만으로 추가 데이터가 생기지 않는다. **기존 QA 데이터 디렉터리를 유지한 일반 재배포 + 별도 `seed_qa_history --apply`**가 필요하다. 현재 로컬 검증 DB를 서버 DB 위에 덮어쓰지 않는다.
- 일반 재배포 스크립트는 DB/첨부를 백업하고 기존 데이터 경로를 유지하며 업무 테이블 fingerprint가 달라지면 중단한다. `--fresh-data-once`는 새 데이터 공간으로 전환하는 별도 옵션이므로 이번 추가 배포에는 사용하지 않는다. 과거 테스트 기록이 새 화면에서 빠져 보이면 기간·검색·소진 LOT 제외 조건도 확인한다.
