# 원료 일괄 투입 — 로컬 검증 (2026-10-19)

생산 시작 후 **남은 원료 일괄 투입 → 실제 수량·LOT 검토 → 확인한 원료 일괄 등록**을 사용합니다.
기존 원료별 ‘투입량 확인’도 유지합니다. 배포하지 않았습니다.

- 기존 BOM 기준량(산출 등록 전에는 계획량, 이후에는 산출량)에서 정정이 반영된 기등록량을 차감합니다.
- 재고 관리 원료 중 남은 수량이 있는 행만 제안합니다. 정제수 등 비재고 원료와 이미 충족된 행은 제외합니다.
- 기준량·기등록량·이번 실제 투입량·LOT 배분을 한 표에서 확인합니다. 실제 수량 수정, 선택 제외, 수동 LOT 분할, 등록 대체 원료 자동 배분을 제공합니다.
- 수량 변경 뒤에는 LOT를 다시 자동 배분하거나 수동 합계를 맞춥니다. 자동 재배분은 선택 원료의 수동 배분을 새 제안으로 바꿉니다.
- 배분은 기존 원료/대체 원료와 소비기한·입고일 우선순위를 유지합니다. 같은 LOT를 여러 BOM 행에서 사용할 때 합산 재고를 초과해 제안하지 않습니다. 자동 제안은 BOM 행 순서에 따른 배분이며 최적 조합 탐색은 하지 않습니다. 필요하면 대체 원료/LOT를 직접 조정합니다.
- 저장 전에는 실제 재고를 예약하거나 차감하지 않습니다. 원료별 합계 불일치·부족 시 등록을 차단합니다.
- 저장은 기존 투입 API의 단일 트랜잭션으로 처리합니다. 원료 하나라도 실패하면 이번 요청 전체가 취소됩니다.
- 검토 이후 투입·산출로 기준량이나 기등록량이 달라지면 재조회를 안내합니다. 실제 LOT 상태·가용재고도 저장 시 다시 검사합니다.
- 저장 응답 유실 후 재시도는 동일 요청 키·동일 내용으로 처리해 중복을 막습니다. 요청 이후 입력은 고정하고, 닫을 때 최신 배치를 다시 읽습니다.
- 한 요청은 기존 제한인 LOT 100행 이내입니다. 초과하면 선택 원료를 나눠 처리합니다.

기존 DB, 기록, 문서·첨부를 수정하거나 초기화하지 않습니다. DB 마이그레이션은 없습니다. 입고 건별 LOT 분리, 수량 환산, 재고 사용 가능 판정과 산출 정책은 유지합니다.

## 확인 결과

- Django 재고·core 테스트: 250개 통과. 파일 DB 동시성 2개는 별도 실행 대상으로 제외한 결과입니다.
- 파일 SQLite 동시성 3개 통과: 동일 키 재요청, 재고 경합, 서로 다른 키로 같은 검토 내용을 동시에 등록할 때 두 번째 요청 차단.
- 새 서비스 회귀 테스트 7개: 잔량 제안, 18개 중 기존 3개 보존/남은 15개 저장, 재요청 중복 방지, 변경된 기록 거절, 뒤 원료 실패 시 전체 롤백, 합계 불일치, 공유 대체 원료 kg/g 환산, API 유효성 검증 등을 포함합니다.
- 프런트 로직: 공유 LOT 합산 초과·환산 정밀도·합계 불일치·선택 제외·표 렌더링 통과.
- 실제 Chrome: 18개 BOM에서 3건 보존/15건 제안, 수량 수정, 부족 안내, 수동 합계 오류, 14개 선택 저장, 응답 유실 후 중복 없는 재시도, 남은 1개 저장, 실제 재고 확인. 800px 화면에서 페이지 가로 넘침 없음. JavaScript 예외 없음.
- 브라우저 검증 데이터와 스크린샷: `tools/bulk-production-qa/`. 기존 DB의 복사본에만 테스트 기록을 추가했습니다.

## 재현

서버 테스트는 `config.settings.test`의 격리 DB를 사용합니다. Windows에서는 테스트 임시 폴더를 쓰기 가능한 경로로 지정합니다.

```powershell
$env:TEMP=(Resolve-Path tools/bulk-production-qa/tmp).Path
$env:TMP=$env:TEMP
.venv/Scripts/python.exe backend/manage.py test apps.inventory apps.core --settings=config.settings.test
$env:HACCP_TEST_FILE_DB='1'
.venv/Scripts/python.exe backend/manage.py test apps.inventory.test_qa_concurrency --settings=config.settings.test_filedb
node scripts/test_qa_frontend.cjs
```

브라우저용 데이터는 `scripts/prepare_bulk_production_qa.py --source-db <로컬 DB 경로>`로 새 복사본을 만듭니다. 원본은 읽기 전용으로 엽니다. 출력의 `data_dir`를 `HACCP_DATA_DIR`로 지정한 개발 서버(기본 8034)와 전용 Chrome CDP(9344)를 준비한 후 `node scripts/test_bulk_production.cjs`를 실행합니다. 서버 포트는 `BULK_QA_BASE=http://127.0.0.1:<port>`로 바꿀 수 있습니다. 이 브라우저 검증은 테스트 기록을 실제로 저장하므로 반드시 생성한 복사본으로 실행합니다.
