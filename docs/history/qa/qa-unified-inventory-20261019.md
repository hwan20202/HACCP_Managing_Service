# 수불대장·현재고·품목 상세 통합 — 2026-10-19

사용자의 6개 통합 요구사항을 적용한 최종 화면 구성이다. 이전 현황/기간말 열 설계는 아래 구성으로 대체한다. 원격 접속·배포·기존 개발 DB 마이그레이션·시드·거래 수정은 하지 않았다.

## 화면

- 원료·부자재·완제품 수불대장은 `수불 내역 / 현재고` 두 탭을 유지한다.
- 수불 내역은 선택 기간·검색·입출고 구분·선택 LOT를 적용한 거래 목록이다. 거래 구분, 입출고 수량, **거래 직후 LOT 잔량**, 단위, 처리자, 사유와 관련 기록을 표시한다.
- 현재고는 품목별 총재고·사용 가능·사용 불가·LOT 수를 표시한다. 별도 LOT 패널은 제거했다. 검색·부족 품목·소비기한·표시 단위 조건은 유지한다. LOT/공급처 검색으로 품목을 찾더라도 수량은 해당 품목의 전체 합계이므로 화면에서 범위를 구분한다.
- 두 탭의 품목명은 동일한 **품목 상세**를 연다. 상단은 품목명·코드·조회 시점·현재 총재고/사용 가능/사용 불가, 중단은 소진 LOT를 포함한 전체 LOT의 현재 잔량·상태·소비기한, 하단은 편집 가능한 기간과 수불 이력이다.
- 상세창의 기간 변경은 원래 수불대장의 기간에도 반영된다. 현재고 탭에서 열어도 시작일·종료일을 확인/변경할 수 있다. 현재 재고는 항상 조회 시점 기준으로 다시 가져오며, 선택 기간으로 재계산하지 않는다.
- 상세창의 LOT 선택은 전체 LOT 목록을 유지하고 아래 이력과 기간 요약만 좁힌다. `전체 LOT 보기` 또는 상세창의 `전체`로 복원한다. 선택을 수불대장에 적용하는 버튼도 제공한다.
- 필요할 때 펼치는 `LOT별 기간 요약`에 LOT당 한 줄로 이월 / 기간 입고 합계 / 기간 출고 합계 / **조회 종료일 잔량**을 표시한다. 입출고 표시 필터와 무관한 전체 수불 계산값이다. 거래 행에는 종료일 잔량을 반복하지 않는다.
- 별도 `재고·수불 현황` 사이드바 메뉴와 진입 버튼·렌더링은 제거했다. 예전 페이지 ID로 호출하는 경우에만 원료 수불대장으로 연결한다.

## 기존 업무 연결과 데이터

수불 API가 각 거래에 기존 입고 ID·제조배치 ID/번호를 읽기 전용으로 덧붙인다. 입고 기록은 조회 전용 창으로 열고, 제조배치는 기존 생산 화면, 문서는 기존 LOT 문서/배치 CCP 화면으로 이동한다. 정정 행은 정정 대상 거래의 배치 연결을 보존한다. 새로운 문서 작성·정정·취소 입력 화면은 추가하지 않았다.

`ledger_sources.py`는 입고·투입·산출 테이블을 읽기만 한다. LOT 생성·채번·입고 건별 분리·재고 계산·서비스의 저장 규칙·테이블 정의는 변경하지 않았다. 첨부 파일을 처리하는 코드는 변경하지 않았다.

## 다운로드

| 위치 | 내용 | 파일명 범위 |
|---|---|---|
| 수불 내역 탭 | 화면 필터에 맞는 수불 한 시트 | 메뉴·시작일·종료일·입출고 구분·검색/선택 LOT |
| 현재고 탭 | 화면에 해당하는 품목별 현재고 한 시트, 명시된 기준 단위 | 메뉴·조회일·검색·부족 품목/소비기한 조건 |
| 품목 상세 | 현재 재고 요약 / 전체 LOT 현재고 / LOT별 기간 요약 / 수불 내역 | 품목코드·기간·입출고 구분·선택 LOT |

상세 다운로드의 현재 재고 두 시트는 품목 전체/소진 LOT 포함이며 기간과 무관하다. 기간 요약·수불은 선택 LOT와 기간을 적용한다. 수량은 숫자 셀이고 각 시트에 기준과 범위를 표시한다. 기간 변경 중 부모 화면의 과거 결과를 내려받지 않도록 캐시를 무효화한다.

## 로컬 검증

- 수불 앱 **215개 중 213개 통과, 2개 건너뜀**, 실패·오류 0. 읽기 전용 연결 정보와 정정 거래의 원래 배치 연결, 재고·거래 직후 잔량 보존 회귀 포함.
- 메뉴·기본 화면·문서 메뉴 연결 관련 core 앱 **30개 통과**.
- 기존 수불 검증 fixture가 자정~오전 9시에 당일 09:00를 미래로 넣어 실패하는 문제를 발견했다. fixture의 발생 시각을 현재 이하로 제한해 시간대에 관계없이 검증하도록 수정했다. 업무의 미래 거래 차단 정책은 그대로다.
- Python Ruff·format, JavaScript 구문, UI 로직 검증 통과.
- `scripts/test_inventory_unified.cjs`: 기존 업무 DB와 분리된 로컬 QA DB에서 세 메뉴/두 탭, 메뉴·패널 제거, 공통 상세 요약·전체 LOT·0재고, 기간 변경/유효성, LOT 필터/전체 복원, 종료일 잔량과 현재고 차이, 탭/상세 다운로드, 입고·배치·문서 이동, 지연 응답 및 작은 화면을 검사한다. 실제 저장 작업은 하지 않는다.
- 브라우저 수량 예: 덱스트린 현재 총재고 23.9 / 사용 가능 22.7 / 사용 불가 1.2kg. 별도 월경계 LOT의 9/30 종료일 잔량 2kg와 조회 시점 현재 잔량 1.5kg를 구분했다.
- 검증 DB의 전체 저장 테이블을 읽어 정렬한 전후 SHA-256이 동일했다: `fe88dabceae5bc359ab69c8ba78b9368141c0af2aa5e6e505700607e35fdf133`. 기존 기록을 수정하지 않았으며 실제 개발/서버 DB는 검증 대상으로 사용하지 않았다.
- 결과·캡처는 Git 제외 `tools/unified-inventory-qa/`에 저장한다. 전체 입고/생산 저장 브라우저 시나리오는 이번에 재실행하지 않았다.
