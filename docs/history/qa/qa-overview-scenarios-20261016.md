# 재고·수불 통합 화면 추가와 배포 시나리오 검증

> 최신 변경(2026-10-19): 별도 현황 메뉴를 제거하고 두 탭·공통 품목 상세창으로 통합했다. [현재 동작과 검증](qa-unified-inventory-20261019.md)을 참고한다. 아래는 10/16 버전의 구현·검증 기록이다.

## 화면

멘토가 전달한 예시의 목적은 **품목별 입출고와 LOT별 현재 잔량을 한 화면에서 대조**하는 것이다. 기본 화면을 `재고·수불 현황`으로 바꾸어 왼쪽에는 품목별로 묶은 날짜·LOT·입고·출고·발생 후 LOT 잔량, 오른쪽에는 품목코드·품목명·LOT·현재고·상태를 표시한다. 좁은 화면에서는 두 표가 같은 페이지에서 위아래로 배치된다. 품목별 합계는 보조 탭이다.

검색은 양쪽 표에 적용한다. 오른쪽 LOT 선택은 내부 `lot_id`로 왼쪽 내역만 좁히고, 오른쪽 목록은 유지한다. 같은 번호를 가진 다른 품목의 LOT를 혼동하지 않는다. 기간·입고/출고 필터는 왼쪽에만 적용하며 오른쪽은 항상 조회 시점 현재 재고다. 소진 LOT는 오른쪽에서 기본 제외하지만 왼쪽 이력에는 남고, 상세 조건에서 오른쪽에도 표시할 수 있다. 기간 이전 잔량은 왼쪽에 이월로 표시한다.

통합 화면의 엑셀은 `입출고 내역`, `LOT별 현재고` 두 시트다. 화면의 검색·선택·입출고 조건과 일치시키고, 현재고 시트에는 기간과 무관한 현재 잔량임을 표시한다. 품목별 합계 탭은 별도 합계 시트로 내려받는다.

## 로컬 실행 결과

기존 업무 DB·호스팅 QA와 분리된 새 로컬 QA 데이터에서 실행했다. 예시 자료는 실제 업무자료가 아닌 가상 품목 `QA_UI_AAA`, `QA_UI_BBB`다. 반복 입고/출고를 재현하기 위해 기초재고와 조정 서비스를 사용했고 직접 SQL로 업무 기록을 작성하지 않았다.

## 서버 배포와 검증 범위

이번 버전의 배포 스크립트는 서비스 전환 전에 **임시 데이터 디렉터리와 메모리 테스트 DB**로 위 51건을 실행한다. 기존 QA 환경 파일·업무 DB를 테스트 대상으로 사용하지 않으며, 실패하면 코드 전환을 시작하지 않는다. 데이터 격리는 별도 단위 검사로 확인했다.

통과 후 기존 방식으로 쓰기 중지 → DB·첨부 백업 → 같은 데이터 경로에 코드/정적 파일 반영 → 업무 데이터 해시 불변 확인 → 재시작 → 내부 준비 상태·HTTPS 접근 제한을 확인한다. Seeder·QA 초기화·양식 재설치는 일반 배포에서 실행하지 않는다. 결과 파일 `deployment.json`에 `isolated_regressions: passed`와 `business_data_preserved: true`를 기록한다.

이번 세션에서 `root@175.118.124.141:22`는 연결되지만 SSH 인증이 거부됐다. 따라서 **이 버전의 원격 배포, 서버에서의 51건 실행, 배포 후 실제 사이트 브라우저 검증은 미실시**다. 로컬 검사 성공을 서버 검사 성공으로 보고하지 않는다. 실제 iPad/Safari, 사용자별 현업 입력, 문서 결재·첨부 전체 흐름은 이번 Chrome 화면 검사 범위를 벗어난다.
