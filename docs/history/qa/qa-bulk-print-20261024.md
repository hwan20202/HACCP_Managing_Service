# 생산지시서·수불대장 직접 인쇄와 다중 선택

2026-10-24 · 현재 작업 브랜치 로컬 구현·검증

별도 HTML 미리보기 창에서 인쇄 버튼을 다시 누르던 단계를 제거했습니다. 출력 문서를 화면 밖 iframe에 작성한 뒤 로딩·글꼴 준비를 기다려 브라우저 인쇄를 자동 호출합니다. Chrome 인쇄 창에서 프린터 또는 PDF 저장을 선택합니다. 팝업 창을 열지 않으며, 인쇄 종료·취소 시 iframe을 정리합니다. 이미 열린 인쇄 작업이 있으면 중복 호출하지 않습니다.

## 선택과 정렬

- 평소에는 생산 목록·수불 내역·현재고의 인쇄 체크박스와 선택 안내를 숨깁니다. 상단 ‘인쇄 / PDF’를 눌렀을 때만 선택 모드로 전환해 ‘전체 선택 · 선택 N개 인쇄 · 취소’를 표시합니다. 선택이 없으면 선택 인쇄 버튼을 비활성화합니다. 일반 조회 화면에서 선택 열이 공간을 차지하지 않습니다.
- 생산 목록의 체크박스로 여러 배치를 선택하거나 조회 목록 전체를 선택합니다. 선택 개수를 표시하며, 체크박스를 눌러도 배치 상세는 열리지 않습니다. 배치 상세의 ‘이 배치 인쇄 / PDF’는 선택 모드 없이 현재 배치 1건을 바로 출력합니다. 새 계획 등록으로 전환하면 인쇄 선택을 해제합니다.
- 생산지시서는 선택한 배치의 최신 상세를 조회한 뒤 제조일(없으면 계획일), 배치번호, id 순으로 정렬합니다. 조회를 5건씩 묶고, 하나라도 실패하면 일부 문서만 인쇄하지 않습니다. BOM 계획 소요량과 실제 투입·산출을 포함하며 상단 표시 단위도 반영합니다. 배치마다 새 페이지에서 시작합니다.
- 수불 내역·현재고 표에서 여러 품목을 선택합니다. 수불 표의 체크박스는 개별 이동이 아닌 **해당 품목**을 선택하며, 같은 품목의 다른 행에도 선택이 반영됩니다. 전체 선택은 현재 화면 페이지뿐 아니라 조회 결과의 모든 품목을 대상으로 합니다. 페이지 이동 시 선택을 유지하고 새 조회 결과에 없는 선택은 제거합니다.
- 수불 출력은 선택한 품목의 전체 조회 기록을 품목코드·거래일·수불 id 순으로 정렬하고 품목별로 새 페이지를 시작합니다. 현재고는 품목코드 순으로 한 표에 모읍니다. 조회 전체를 출력하려면 선택 모드에서 전체 선택을 사용합니다.
- 인쇄 창을 닫거나 취소하면 브라우저 `afterprint` 이벤트에서 선택 모드와 선택 항목을 정리하고 일반 화면으로 돌아갑니다. 선택 모드의 취소 버튼 또는 상단 ‘인쇄 선택 취소’로도 즉시 닫을 수 있습니다. 조회·인쇄 준비에 실패하면 선택을 유지해 재시도할 수 있습니다. 수불의 탭 전환·조건 초기화 시에는 선택 모드를 종료합니다.
- 기간·입출고 구분·취소 표시·LOT 범위·표시 단위를 유지합니다. 품목 상세창에서 출력할 때는 부모 화면의 다중 선택을 적용하지 않고 상세창의 선택 기간·LOT·입출고 범위를 사용합니다. 화면 페이지 수로 출력 행을 자르지 않습니다.
- 데이터·재고·문서를 수정하지 않는 기능입니다. DB 변경·마이그레이션은 없습니다.

## 검증

- `scripts/project.py check` 통과: 스크립트 테스트 15건, Django 테스트 1,052건 중 1,016건 통과·환경 조건에 따른 36건 건너뜀. 로컬 로그 `tools/bulk-print-check.log`.
- `test_bulk_print_frontend.cjs`: 기본 화면의 체크박스 없음, 선택 모드 진입·취소·인쇄 종료 후 복귀, 빈 선택 비활성화, 상세 단건 직접 출력, 복수 선택, 정렬, 품목 필터링, 전체 선택, 조회 변경 시 선택 정리, HTML 이스케이프, 배치 조회 실패 시 부분 출력 방지를 확인했습니다.
- 기존 수불 페이지·인쇄 범위 테스트를 새 직접 인쇄 방식에 맞췄습니다. `test_inventory_browsing_frontend.cjs`, `test_navigation_frontend.cjs`, `test_qa_frontend.cjs`, `test_inventory_feedback_frontend.cjs`, `test_receipt_frontend.cjs`, `test_production_units_frontend.cjs`, `test_production_holds_frontend.cjs` 통과.
- 실제 Chrome에서 배치 2개, 수불 품목 2개(5행), 현재고 품목 2개를 선택해 각각 하나의 문서로 전달되는 것을 확인했습니다. 페이지 로딩·iframe 작성·자동 인쇄 호출·종료 후 정리는 실제 코드를 사용했으며, headless 검증에서는 네이티브 인쇄 함수만 대체해 호출 횟수와 출력 HTML을 검사했습니다. 별도 팝업이나 두 번째 인쇄 버튼은 없으며 콘솔 예외도 없었습니다.
- 선택 화면 캡처와 출력 HTML은 로컬 `tools/bulk-production-qa/`의 `production-multi-print-selection.png`, `inventory-multi-print-selection.png`, `production-combined-print.html`, `inventory-combined-print.html`에 있습니다. 복제 QA DB를 읽기 전용으로 조회했으며 원본 DB·원격 서버는 변경하지 않았습니다.

사용 경로: 로컬 localhost:8046에서 상단 ‘인쇄 / PDF’ → 목록에서 항목 선택 → ‘선택 N개 인쇄’. 상세 단건 출력은 상세의 인쇄 버튼으로 바로 실행합니다. PR·병합·배포는 실행하지 않았습니다.
