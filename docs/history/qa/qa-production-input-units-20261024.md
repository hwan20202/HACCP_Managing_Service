# 생산 BOM 표시·투입 단위 연동

2026-10-24 · 로컬 구현 및 검증

상단 표시 단위를 kg/g으로 선택하면 BOM 표뿐 아니라 개별 원료 투입·여러 원료 일괄 투입의 입력 단위도 같은 기본값을 사용합니다. 특정 원료는 입력 영역에서 별도 kg/g을 선택할 수 있습니다. 상단 단위를 다시 선택하면 현재 열린 모든 원료 입력을 그 선택에 맞춥니다. 기준 단위 선택 시에는 각 품목의 기준단위를 사용하며, 개·장 등 질량이 아닌 단위는 그대로 유지합니다.

원료별 총량·LOT 배분량·가용량·합계·부족량을 같은 입력 단위로 표시합니다. 일괄 투입에서 해당 원료의 단위를 별도로 바꾸면 기준량·기등록량도 그 단위로 표시하며, LOT 재배분 후에도 원료별 선택을 보존합니다. 등록된 투입 기록의 수량도 상단 표시 단위를 따릅니다.

초안은 계속 BOM 원료·LOT 각각의 기준단위 문자열로 보관합니다. 화면 단위를 바꿔도 실제 수량·배분·요청 키는 바뀌지 않고 저장할 때 기준단위로 전달합니다. 단위 환산은 문자열·정수 기반으로 처리하며, 기준단위 소수점 6자리를 초과한 입력은 저장을 차단합니다. kg에서 g으로 0을 표시할 때 불필요한 0이 붙던 공통 환산 표시도 수정했습니다.

## 검증

- `test_production_units_frontend.cjs`: 상단 기본값, 원료별 예외, 상단 재선택 시 동기화, 혼합 kg/g LOT, 0 표시, 수량 보존, 소수점 제한, 개 단위 유지.
- 기존 `test_qa_frontend.cjs`, `test_production_holds_frontend.cjs`, `test_navigation_frontend.cjs`, `test_inventory_feedback_frontend.cjs`, `test_inventory_browsing_frontend.cjs`, `test_receipt_frontend.cjs` 통과.
- `test_production_units_browser.cjs`: 복제 로컬 QA DB와 실제 Chrome에서 개별 원료 30g → 0.03kg 저장 및 재고 차감, 일괄 투입 20g → 0.02kg 저장, 행별 단위 변경·재배분·상단 재선택을 확인했습니다. 브라우저 예외 없음.
- 로컬 캡처: `tools/bulk-production-qa/production-unit-g.png`. 원본 업무 DB·원격 서버는 수정하지 않았습니다.

생산량 산출 입력은 이번 BOM 원료 투입 단위 연동의 대상이 아닙니다. 기존 산출 입력 단위 선택을 유지합니다.
