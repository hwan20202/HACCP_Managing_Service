# 문서·결재(documents) 결정 사항

`backend/apps/documents`·`approvals`·`document_workflow`·`doc_requirements`·`doc_effects`(문서 영역)의 동작 기준을 주제별로 모았습니다. 결정 로그 D-001~D-160(2026-10-09 ~ 10-14)을 정리한 것입니다.

- **확정**: 합의되어 코드에 들어간 것 · **확정(구현 예정)**: 설계까지 합의, 구현 전 · **가정**: 합의 전 기본값으로 구현(바꿀 곳 표시) · **대기**: 결정이 나야 진행
- 오른쪽 "결정" 칸의 `D-nnn`은 커밋 메시지·개발 기록의 결정 번호입니다. 기호 설명은 [document-dev-process.md](document-dev-process.md), 화면 사용법은 [document-user-guide.md](document-user-guide.md), 생산·수불 연동 명세는 [document-inventory-interface.md](document-inventory-interface.md).

## 1. 구조와 원칙 — 확정

| 항목 | 내용 | 결정 |
|---|---|---|
| 도메인 경계 | 문서(`documents`)·결재(`approvals`)는 서로 import하지 않음. 둘을 묶는 처리(상신·승인·반려·일괄)는 워크플로우(`document_workflow`)가 공개 서비스 함수만 불러 한 트랜잭션으로. 외부(수불·생산)가 부르는 진입점은 작성 요구(`doc_requirements`). 문서 → 외부 호출은 후속 처리(`doc_effects`, 테이블 없음)가 생명주기 신호를 받아 수행 — 다른 앱은 `doc_effects`를 import하지 않음. 경계는 import 검사 테스트로 확인 | D-004, D-079 |
| 문서는 기록 | 문서에는 문서가 판정한 내용만. LOT 상태는 수불만 가지며 문서는 저장·표시·조회하지 않음 | D-073 |
| 상태 변경 | 서비스 함수 안에서 조건부 UPDATE로 검사와 잠금을 함께. 문서 단위 버전(`document.version`)으로 동시 수정 감지 — 쓰기 요청은 `expected_version` 필수, 다르면 409 `VERSION_CONFLICT` | D-026, D-038 |
| 트랜잭션 | SQLite `transaction_mode: IMMEDIATE`(운영·테스트 같음). "트랜잭션 첫 SQL은 쓰기" 규칙(D-067)은 수불 병합 뒤 필요 없음 — 남은 코드는 무해해서 둠 | D-129 |
| 로그인 | MVP 범위 아님. 현재 사용자는 `X-Staff-Id` 헤더, 없는·비활성 직원은 거부 | D-020, D-128 |
| 오류 응답 | `/api/v1/` 공통 `{code, message, details}`. 도메인 오류 코드 그대로 응답, 어긋난 데이터는 전체 롤백 후 409(자동 복구 없음) | D-038 |
| 시각 | UTC 저장, 응답은 +09:00 | D-021 |
| 개발 도구 | 개발 콘솔(`HACCP_DEV_CONSOLE`)·임시 메뉴(`HACCP_TEMP_ENTRY`)는 따로 켜고 끔. 운영 설정에서 개발 콘솔은 존재하지 않음. 임시 화면은 사이드바 "개발 검증 (임시)"(문서함·결재함 자리는 `HACCP_DOC_MENU` — P10 줄) | D-010, D-011 |

## 2. 문서 — 확정

| 항목 | 내용 | 결정 |
|---|---|---|
| 상태 | `draft` 작성중 / `completed` 작성완료 / `submitted` 결재중 / `approved` 승인 / `rejected` 반려 / `correcting` 정정 중 / `skipped` 작성 안 함 | D-048, D-076, D-106 |
| 작성자·담당자 | 작성자(`created_by`, 자동)와 담당자(`assignee_id`, 선택)는 다름. 작업일(`work_date`) = 실제 업무를 한 날, 미래 허용 | D-012, D-016, D-018 |
| 수정 | 바뀐 부분만(PATCH, 섹션 행 단위 추가·변경·삭제). 바뀌지 않은 행의 기록 시각·기록자 보존. 수정 가능 상태 = 작성중·반려·정정 중 | D-014, D-021 |
| 저장과 검사 | 저장은 형식만 검사, 필수값·행 개수·양식 규칙은 **작성완료 때** 검사 | D-052 (C-2), D-055 |
| 작성완료 | 작성완료는 잠김, [작성 재개]로 작성중 복귀(작성완료 시각·사람 지움). 상신은 작성완료에서만 | D-054, D-055 |
| 삭제 | 논리 삭제만(`deleted_at`·`deleted_by`). 작성중이고 상신 이력 없을 때만. **입고·생산 작성 요구 문서는 삭제 불가**. 주기 문서(D10·D12·D11)는 삭제 가능 — 삭제 때 `record_key`를 비워 그 날짜를 다시 만들 수 있음(규칙 대상 날은 다음 주기 생성 때 다시 만들어짐) | D-017, D-021, D-052, D-149 |
| 목록 | 기본 기간 최근 7일. D03은 입고일마다, D10·D12는 주(월~금)마다 묶음 줄 하나. 주 묶음 줄 정렬 날짜 = 그 주 가장 늦은 작업일 | D-015, D-097, D-108, D-138 |
| 양식 | 양식 버전 내용(`schema_json`)은 만든 뒤 바꾸지 않음. 결재 스냅샷은 양식을 `template_id`·버전으로 참조 | D-032 |
| CCP 일지 | 측정 행 = 날짜+시각, 날짜 기본값 = 작업일. 세 양식 모두 시작 행이 가장 이르고 종료 행이 가장 늦어야 작성완료(`phase_order`). 판정은 화면 표시 계산 + 서버 저장 계산 | D-051, D-055, D-057 |
| 개선조치 | 모든 양식에 있음. 문서 상태와 무관하게 언제든 쓰기·수정(확인자 포함), 논리 삭제. 조치자·확인자(여러 명 지정, 1명 확인)는 선택. 부적합이 있으면 작성완료에 1건 이상. 상신 당시 개선조치는 결재 요청 상세에 표시. 수불은 `source_document_id`(문서 참조)까지만 | D-049, D-054, D-055, D-063 |

## 3. 결재 — 확정

| 항목 | 내용 | 결정 |
|---|---|---|
| 결재선 | 병렬·칸형. 칸 하나에 1명, 처리 순서 없음, 전원 승인이면 최종 승인. 작성자도 결재자 가능. 상신 때 사용자가 직접 지정(칸 최대 10, 역할 이름 20자·선택, 같은 사람 중복 불가) | D-006, D-030, D-031, D-033 |
| 상신 | 현재 사용자 누구나. 첫 상신 기본 결재선 3칸(담당·검토·승인) — **P12에서 2칸으로 바꿈**(D-126), 재상신은 직전 결재선 | D-037 |
| 승인·반려 | 승인 의견 선택(500자), 반려 사유 필수. 반려 시 남은 대기 칸은 미처리 종료(`skipped`). 끝난 회차 처리는 `REQUEST_CLOSED`("이 회차는 이미 끝났습니다…") | D-031, D-033, D-102 |
| 승인본 | 결재 회차마다 상신 시점 문서 스냅샷 보관(`approval_request.snapshot_json`). 회차는 만든 뒤 바꾸지 않음 | D-007 |
| 회수·결재선 변경 | 지원하지 않음. 상신 취소는 P10 | D-037, D-116 |
| 일괄 결재 | 묶음 상세·결재함에서 여러 건 일괄 승인·상신, 점검자 일괄 지정. 대상 양식 설정 `HACCP_BATCH_TYPES`(기본 D03·D10·D11·D12), 밖이 섞이면 요청 전체 400 `not_batchable`. 최대 50건, 한 요청 = 트랜잭션 1개 + 문서마다 세이브포인트(4xx는 그 항목만 실패, 응답 항상 200). 일괄 반려 없음. 일괄 상신 결재선 기본값 = 묶음의 최근 회차 결재선, 승인 의견은 모든 칸에 같게 | D-084, D-097, D-098, D-109 |
| 결재 대상 표시 | 상신 때 문서 대상 요약(`target_summary`, 예: `LOT … · 품명 · 매입처`)을 요청에 저장 | D-088, D-098 |

## 4. 작성 요구 (입고·생산) — 확정

| 항목 | 내용 | 결정 |

| 방식 | 사건형 문서는 수불·생산이 부르는 함수로만 생성(양식 선택에서 숨김 `requirement_only`, 작업일 고정). 같은 대상 재호출은 기존 문서 반환(`record_key` 유니크) | D-046, D-052 |

## 5. 육안검사와 판정 연동 — 확정

| 입고 때 검사 값 | 수불 입고 화면에서 검사까지 입력하면 새 D03에 채움(형식은 문서 쪽 D03 양식). 기존 행은 덮어쓰지 않음 | D-080 |

## 9. 수불 통합 (C2) — 확정

| 항목 | 내용 | 결정 |
|---|---|---|
| 통합 방식 | `main`(수불 `feature/inventory`)에서 `feature/document-integration`을 만들고 문서 브랜치 병합. **수불 코드(`apps/inventory`·`docs/inventory-*`)는 문서 쪽이 고치지 않음** | D-081, D-128 |
