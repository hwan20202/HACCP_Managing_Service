# 문서·결재 기능 사용설명서

HACCP 문서 영역(문서 작성·결재·작성 요구·파일·점검표)이 **지금 제공하는 기능**을 화면 사용 순서대로 정리했습니다. 각 기능의 "요구사항"은 시스템이 지키는 규칙(언제 되는지, 무엇이 막히는지)입니다. 모든 내용은 단계마다 실제 화면으로 해 본 **사용 테스트**(아래 "확인" 줄)에서 통과한 것만 적었습니다.

- 기준 코드: `feature/document-integration`(스프린트 3 C5 완료 `1802444` — P8 점검표 + 파일 업로드 + P9 주기 문서 만들기 + P10 문서함·결재함·상신 취소까지) + P11 CCP 대시보드 + **P14 역할 기반 결재·작성 권한**(`feature/role-based-approval-submit`, [1.6](#16-역할과-권한))
- 결정 근거: [document-decisions.md](document-decisions.md) · 기호·단계 설명: [document-dev-process.md](document-dev-process.md)
- 아직 없는 기능은 마지막 [12장](#12-아직-없는-기능)에 모았습니다.

## 1. 시작하기

### 1.1 들어가는 곳

| 메뉴 (사이드바 **개발 검증 (임시)**) | 하는 일 |
|---|---|
| 문서함 `n` | [작성 필요](오늘 쓸 것 — [1.4](#14-문서함--작성-필요-탭))·[전체 문서](문서 목록)·새 문서·문서 상세(결재 영역 포함)·묶음 상세. 숫자 = 작성 필요 전체 |
| 결재함 `n` | 내 결재 대기·처리 완료, 결재 요청 상세, 여러 건 선택 승인. 숫자 = 내 칸(내가 처리할 결재 대기) |
| CCP 대시보드 `n` | 하루치 CCP 측정을 생산 배치별로 — 이탈·개선조치·특이사항, 개선조치 확인 대기, [확인]([1.5](#15-ccp-대시보드)). 숫자 = 내 확인 대기(날짜 무관) |
| 역할 보기 | HACCP팀장, 양식마다 담당자·작성 권한자·결재 칸, 설정 경고 — 읽기만([1.6](#16-역할과-권한)) |
| 생산 기준정보 | 공정 목록·공정 템플릿 관리 — 생산일지에 넣을 공정과 순서([10.5](#105-생산-기준정보--공정공정-템플릿)) |
| 작성 요구 | 테스트용 입고(LOT 생성)·생산 시작 — 수불·생산 앱이 할 호출을 흉내 냄 (개발 설정에서만) |
| 개발 콘솔 ↗ | API를 직접 부르고 DB 변화·흐름을 확인 (개발 설정에서만, [11장](#11-개발-콘솔-개발-설정-전용)) |

문서함·결재함·CCP 대시보드의 자리는 서버 설정 `HACCP_DOC_MENU`로 정합니다: `dev`(기본) = 위 개발 검증 섹션, `haccp` = **HACCP 관리** 섹션 맨 위(개발 검증 탭이 꺼져 있어도 보임). 숫자는 화면을 열 때·사용자를 바꿀 때·저장·상신·결재 등을 한 뒤 다시 셉니다. 예전 주소(`temp-doc`·`temp-approval`)도 같은 화면으로 열립니다.

> 확인: P10 S5 C1·C2·C18·C19 · Mac M-2·M-6

### 1.2 현재 사용자

- 로그인은 아직 없습니다. 화면 오른쪽 위 **현재 사용자**("이름(코드) · 역할 요약", 예: `개발직원5(DEV-005) · HACCP팀장`)를 고르면, 그 사람으로 요청이 나갑니다(`X-Staff-Id` 헤더).
- 사람은 화면 어디서나 "이름(코드)"로 보입니다. 비활성 직원은 지난 기록에 "이름(코드) 비활성".
- 고른 사용자는 새로고침해도 유지됩니다(브라우저 탭 단위).
- 고르지 않으면 쓰기 버튼(작성·상신·승인 등)이 꺼집니다. 비활성 직원, 없는 직원은 거부됩니다.

**요구사항**
- 직원 목록은 수불 앱의 `staff`를 그대로 씁니다. 비활성 직원은 현재 사용자·결재자·담당자·확인자로 쓸 수 없습니다.

### 1.4 문서함 — 작성 필요 탭

**사용 순서**: 문서함 → [작성 필요](기본 탭 — 마지막에 연 탭을 기억) → 줄의 [열기] / [만들기].

**요구사항**
- 기준일(기본 오늘, 미래 불가)로 **오늘 · 주간 · 월간 · 연간 · 수시** 칸을 계산합니다. 오늘 = 점검표(D10·D12)와 그날 입고·생산 문서, 주간 = 그 주 D11. 월간·연간·수시는 지금 해당 양식이 없습니다.
- 들어가는 문서: **작성중·반려·정정 중**. 작성완료·결재중·승인·작성 안 함은 빠집니다.
- **문서 없음**(점선 배지): 규칙상 만드는 날인데 문서가 아직 없는 줄 — [만들기]를 누르면 바로 만들어 작성 폼으로 갑니다.
- D03은 입고일마다 한 줄(누르면 육안검사 묶음 상세). D10 줄에는 날짜 규칙으로 `주 항목`(금요일)·`월 항목`(그 달 첫째 월요일) 꼬리표.
- 칸 맨 아래 "지난 미완료 n건"(최근 30일)을 펼쳐 봅니다. 더 오래된 미완료는 위쪽 요약 줄 옆 "30일 넘은 미완료 n건 → 전체 문서" 링크(빨간 글씨, 있을 때만 — 전체 문서 탭을 그 전 1년으로 엶).
- **상신 대기** 칸: 작성완료했지만 상신하지 않은 문서(상신 취소 포함). 숫자 배지에는 셈하지 않습니다.
- **내 문서**: 내가 그 문서의 점검자이거나 그 양식의 담당자·작성 권한자인 줄만(작성자는 보지 않음 — [1.6](#16-역할과-권한)). 문서 없음 줄은 빠집니다.
- 주기 규칙 파일이 깨졌으면 위에 노란 줄이 나오고 "문서 없음"만 빠집니다.

> 확인: P10 S5 C3~C9 · S6 U-1·U-5·U-6 · Mac S5 M-3·M-4, S6 M-2·M-5

### 1.5 CCP 대시보드

> P11 S5 r1(D-167) — 배치 영역 화면. 처음 S5 화면에서 바뀐 점은 맨 아래 1.5.6에 있습니다.

하루 동안의 CCP 측정 상황, 한계기준 이탈과 개선조치, 특이사항을 생산 배치별로 한눈에 보고, 내가 확인할 개선조치를 [확인]하는 화면입니다.

**사용 순서**: 사이드바 [CCP 대시보드] → 기준일 확인(기본 오늘) → **전체 요약 줄**로 오늘 상황 파악 → 문제가 있는 **배치 영역**을 펼쳐 봄 → **이탈·개선조치 칸**에서 [확인] / [개선조치 쓰기] / [열기].

| 이름 | 하는 일 |
|---|---|
| **조회 막대** | 기준일(하루, 미래는 고를 수 없음 — 화면을 열 때마다 오늘로), [새로 고침](자동 갱신 없음), 마지막 조회 시각, 현재 사용자 |
| **① CCP 현황** | 기준일에 CCP 일지가 있는 생산 배치들 |
| **전체 요약 줄** | 모든 배치를 합친 배지 + [모두 펼치기]·[모두 접기]. 화면을 내려도 ① 위에 붙어 있어 늘 보임. 그 아래에 열 이름 줄은 없음(품목마다 공정이 달라 고정 열을 두지 않음) |
| **배치 영역** | 생산 배치 하나. 이름은 **품목명(배치번호)** — 예: `유자차(PB-1019-03)`. 같은 품목을 하루에 두 번 생산해도 괄호의 배치번호로 구분. 이름 아래 생산 상태 배지와 생산 정보(계획·산출 수량, 시작 시각) |
| **배치 요약 줄** | 접힌 배치 영역. 한 줄에 품목명(배치번호) · **공정 결과**(그 품목의 적용 공정 순서대로 `공정 이름 결과 [문서 상태]`를 → 로 잇기 — 결과마다 공정 이름이 붙어 있어 열 이름이 없어도 됨) · 이탈·개선조치·특이사항 배지 · 최근 측정 시각 |
| **영역 머리** | 펼친 배치 영역의 맨 위. 배치 요약 줄과 같은 내용(▾). 그 아래 **영역 배지**(그 배치의 배지 전체) |
| **공정 카드** | 그 배치에 적용하는 CCP 공정마다 1장, **품목마다 다른 적용 공정·순서**대로(작성 요구 규칙 — 지금 제조 품목은 모두 1P 쇳가루 제거 → 2B 건조 → 3P 금속검출). 카드마다 그 배치의 일지 1건: 공정 이름·상태, 최근 측정(시각·측정시점·값·판정), 측정 수·지난 시간(오늘일 때만)·이탈·개선조치 수, [열기]. 측정이 하나도 없으면 "▲ 측정 없음", 이탈이 있으면 카드가 빨간 바탕 |
| **이탈·개선조치 칸** | 그 배치의 **이탈 표**(1.5.4). 펼친 배치 영역에 늘 있음 — 비면 "이탈·개선조치 없음" 한 줄 |
| **특이사항 칸** | 그 배치의 **특이사항 표**(1.5.5) — 이탈·개선조치 칸 아래 따로. 펼친 배치 영역에 늘 있음 — 비면 "✎ 특이사항 없음" 한 줄 |
| **② 개선조치 확인 대기** | 기준일 문서의 미확인 개선조치(CCP뿐 아니라 **모든 양식**). [확인]은 내가 확인자인 줄에만 |
| **확인자 없음 목록** | 확인자를 지정하지 않은 개선조치 — 확인 대상이 아니라 따로 셈("확인자 없음 n건"을 누르면 펼침, 버튼 없음) |
| **다른 날 줄** | 다른 작업일의 **내** 확인 대기(최근 10개 날짜, 넘으면 "외 n건"). 날짜를 누르면 기준일이 그 날로. 미래 작업일 문서는 [문서 열기] |
| **확인 창** | [확인]을 누르면 뜨는 창(1.5.4) |

배치 영역 순서는 **생산중 → 생산 전 → 생산 종료**(수불 배치 상태), 같으면 **생산 시작 일시가 빠른 순**입니다(시작 전이면 뒤, 그다음 품목명·배치번호). 배치 이름 아래에 생산 상태 배지(생산중 초록 · 생산 전 회색 · 생산 종료 파랑)와 **생산 정보** 한 줄이 붙습니다 — `계획 1,200 kg · 산출 1,150 kg · 시작 13:01`. 수량은 수불 배치의 기본 단위이고, 산출은 산출량이 기록된 뒤에만, 시작은 생산 시작 전이면 "시작 전"으로 나옵니다. 그날 배치가 없으면 "이날 생산 배치 없음".

#### 1.5.2 배지

| 배지 | 색 | 뜻 | 어디에 |
|---|---|---|---|
| **⚠ 이탈 n** | 빨강 | 한계기준을 벗어난 측정 행 수(3P 제품 통과 요약의 검출량 > 0 포함) | 전체 요약 줄·영역 머리·공정 카드·배치 요약 줄 |
| **⚠ 개선조치 없음 n** | 빨강 | 이탈 행인데 개선조치를 아직 안 쓴 것 — **가장 먼저 처리할 것** | 전체 요약 줄·영역 머리·이탈·개선조치 칸·배치 요약 줄 |
| **● 확인 대기 n** | 주황 | 개선조치를 썼고 확인자가 아직 [확인]하지 않은 것 | 같은 곳 |
| **▲ 측정 없음** | 주황 | 공정 일지에 측정 행이 하나도 없음 | 전체 요약 줄·영역 머리·공정 카드·배치 요약 줄 |
| **작성 필요 n** | 회색 | 작성중·반려·정정 중인 일지(문서함의 "작성 필요"와 같은 기준) | 같은 곳 |
| **✎ 특이사항 n** / ✎ | 파랑 | 비고·특이사항이 적힌 행 수 — 알림용(확인할 일 아님) | 전체 요약 줄·영역 머리·이탈·개선조치 칸·배치 요약 줄 / 공정 카드의 ✎(마우스를 올리면 내용) |
| **✓ 적합** | 초록 | 그 공정 일지에 이탈이 없고 최근 측정이 적합(옆에 문서 상태 배지가 함께 나옴 — 작성중이면 아직 작성 필요) | 배치 요약 줄 |
| 상태 배지 | 문서 상태 색 | 작성중·작성완료·결재중·승인·반려·정정 중 | 공정 카드·배치 요약 줄 |
| **생산중 / 생산 전 / 생산 종료** | 초록 / 회색 / 파랑 | 수불의 생산 배치 상태(정렬 기준) | 배치 요약 줄·영역 머리(배치 이름 아래) |
| **확인됨** | 초록 글자 | 확인자가 확인함(누가·언제) | 이탈 표 |
| **확인자 없음** | 회색 | 확인자를 지정하지 않음 — 확인 대상 아님 | 이탈 표·확인자 없음 목록 |
| **검출 n** | 빨강 | 3P 제품 통과 요약의 검출량 합계 | 공정 카드(3P) |
| 사이드바 숫자 | — | **내** 확인 대기 수(날짜와 상관없이 전체). 사용자를 고르지 않으면 숨김 | 사이드바 [CCP 대시보드] |

- 숫자가 0인 배지는 보이지 않습니다. 모두 0이면 전체 요약 줄에 "이상 없음"(초록).
- **접혀서 안 보이는 부분의 문제도 배지로 보입니다**: 배치 영역을 접어도 배치 요약 줄에, 이탈·개선조치 칸을 접어도 칸 머리에, 모든 배치를 접어도 전체 요약 줄에 남습니다.

#### 1.5.3 접기·펼치기

| 무엇 | 어떻게 | 처음 모양 |
|---|---|---|
| **배치 영역** | 영역 머리의 ▾ 또는 배치 요약 줄(▸ 아무 곳)을 누름 | ⚠ 개선조치 없음 또는 ● 확인 대기가 있는 배치만 펼침, 나머지는 접힘 |
| **모든 배치** | 전체 요약 줄의 [모두 펼치기]·[모두 접기] | — |
| **이탈·개선조치 칸** | 칸 머리("이탈·개선조치 n")를 누름 | 개선조치 없음·확인 대기가 있으면 펼침. 모두 확인됨·확인자 없음이면 접힘 비어 있으면 "이탈·개선조치 없음" 한 줄(누를 것 없음) |
| **특이사항 칸** | 칸 머리("✎ 특이사항 n")를 누름 | **늘 펼침**(이탈이 없어도). 비어 있으면 "✎ 특이사항 없음" 한 줄 |

- 직접 펼치거나 접은 상태는 기준일을 바꾸거나 [새로 고침]해도 **그대로**입니다(이 화면을 연 동안만 — 다시 열면 처음 모양).
- 배치 수가 많아도 화면 높이는 제한하지 않습니다. 접어서 줄이고, 아래는 페이지를 내려 봅니다.

- **생산 기록 오가기**(P11 S5 r2): 펼친 배치 영역 배지 줄 오른쪽 [생산 기록 ↗] → 생산지시·실적의 그 배치. 생산 화면에서는 [연결 문서] → [CCP 대시보드에서 보기]로 들어옴(5.2)

#### 1.5.4 개선조치

**개선조치란**: 한계기준을 벗어난 측정(이탈)에 대해 무엇을 했는지 적는 기록입니다 — 한계기준 이탈내용, 개선조치 및 결과, 조치자, 확인자(여러 명 가능). 일지 상세 아래 **한계기준 이탈·개선조치** 영역에서 쓰고 고칩니다([2.5](#25-한계기준-이탈개선조치)).

**이탈 표** (배치 영역의 이탈·개선조치 칸)

| 열 | 내용 |
|---|---|
| 시각 | 이탈한 측정 행의 시각. 행 없이 문서 전체에 쓴 개선조치는 "–" |
| 공정 | 1P · 2B · 3P |
| 어긋난 값 | 벗어난 항목·값과 기준 — 예: `건조온도 73.5 (기준 68~72)`, `Fe 중 X (기준 ○)`, `검출량 1 (0 초과)`  이탈 행이 아닌 곳에 쓴 개선조치는 `행 지정 없음`(문서 전체) 또는 `관련 행 적합` |
| 개선조치 | 개선조치 및 결과(40자, 마우스를 올리면 전체) · 조치자 |
| 상태 | ⚠ 개선조치 없음 / ● 확인 대기(확인자) / 확인됨(확인자·시각) / 확인자 없음 |
| 버튼 | **[개선조치 쓰기]**(개선조치 없음 — 일지 상세를 열고 그 행을 관련 행으로 채운 추가 줄을 엶. 그 양식 역할이 없으면 흐리게 + 이유 — 점검자는 문서 상세에서 씀) · **[확인]**(확인 대기이고 내가 확인자이거나 HACCP팀장일 때) · **[열기]**(일지 상세) |

**확인**

- 확인자 중 **1명** 또는 **HACCP팀장**이 [확인]하면 끝입니다(팀장은 확인자 목록과 관계없이, 확인자 없는 개선조치도 — 대시보드 "확인자 없음 n건" 표에서). 확인 창에 대상·이탈·조치가 나오고, [확인]하면 **되돌릴 수 없습니다**(확인 뒤에 내용을 고쳐도 확인 기록은 남음).
- 확인은 대시보드(이탈 표·② 확인 대기 목록)나 일지 상세의 **확인** 칸에서 합니다. 일지 상세에서는 문서 상태와 상관없이 확인할 수 있습니다.
- ②와 사이드바 숫자에 나오는 때: **CCP 일지는 쓰자마자**, 다른 양식은 **작성완료 뒤부터**(작성 안 함 문서는 빠짐).
- 그사이 다른 사람이 먼저 처리했으면 아래 문구가 나오고 화면을 다시 불러옵니다.

| 문구 | 뜻 |
|---|---|
| 확인했습니다 | 성공 |
| 이미 확인되었습니다(staff n, HH:MM) | 다른 확인자가 먼저 확인 |
| 다른 사용자가 먼저 처리했습니다 | 그사이 개선조치 내용이 바뀜 |
| 확인자나 HACCP팀장만 확인할 수 있습니다 | 확인자도 팀장도 아님(그사이 확인자에서 빠짐 등) |
| 삭제된 개선조치입니다 | 그사이 개선조치나 문서가 삭제됨 |

- 확인과 결재는 따로입니다. 개선조치를 확인하지 않아도 일지를 상신·승인할 수 있습니다.

#### 1.5.5 특이사항

**특이사항이란**: CCP 일지에 적은 **비고·특이사항** 중 값이 있는 것입니다. 확인할 일이 아니라 알아 둘 정보라서 파란 배지로 보입니다.

| 일지 | 칸 |
|---|---|
| CCP-1P 쇳가루 제거 · CCP-2B 건조 | 측정 기록 행마다 **비고** |
| CCP-3P 금속검출 | 감도·통과 점검 행마다 **비고**, 제품 통과 요약 행마다 **특이사항** |

**특이사항 표** (배치 영역의 **특이사항 칸** — 이탈·개선조치 칸 아래 따로)

| 열 | 내용 |
|---|---|
| 시각 | 그 행의 측정·통과 시각. 3P 제품 통과 요약은 "요약"(맨 뒤) |
| 공정 | 1P · 2B · 3P |
| 내용 | 적은 글 |
| 칸 | 측정 기록 비고 / 감도·통과 점검 비고 / 제품 통과 요약 특이사항 |
| [열기] | 일지 상세 |

- 공정 카드의 최근 측정 옆 ✎에 마우스를 올리면 그 행의 비고가 보입니다.
- 특이사항 칸은 펼친 배치 영역에 늘 있습니다. 적힌 것이 있으면 펼친 채로, 없으면 "✎ 특이사항 없음" 한 줄입니다(배치 영역 자체가 접혀 있으면 배치 요약 줄의 ✎ 배지로 보임).

#### 1.5.6 처음 S5 화면에서 바뀐 점(r1)

| 처음 S5 | S5 r1 |
|---|---|
| ① 공정별 카드 3장(1P·2B·3P) 안에 배치 줄 | 배치 영역(품목명(배치번호)) 안에 그 품목의 적용 공정 순서대로 공정 카드, 접힌 줄은 공정 이름을 붙인 결과를 → 로 이음 |
| ② 한계기준 이탈 목록(전체) | 배치 영역의 이탈 표로 옮김 — ② 목록 없음 |
| ③ 개선조치 확인 대기 | ②로 번호만 바뀜, 대상 표시 `CCP-2B 유자차(PB-1019-03) · 2B` |
| 특이사항 없음 | 배치 영역의 특이사항 칸(따로, 늘 펼침), ✎ 배지 |
| 접기 없음 | 배치 영역·이탈·개선조치 칸·특이사항 칸 접기, 전체 요약 줄 |

> 확인: P11 S5 r1 클라우드 C1~C20(C3~C5e 배치 영역·접기·특이사항·공정 순서) · Mac S5 r1 R1-1~R1-6

### 1.6 역할과 권한

결재와 작성은 **역할**로 정합니다. 역할은 서버의 역할 설정 파일(운영: `HACCP_ROLES_FILE`, [deployment.md](deployment.md))에 있고, 화면 [역할 보기]에서 읽기만 할 수 있습니다. 로그인이 없으므로 역할은 **막는 장치가 아니라 실수 방지**입니다.

| 역할 | 누구 | 할 수 있는 것 |
|---|---|---|
| **HACCP팀장** | 설정의 팀장(여러 명) | 모든 양식 작성·상신, 팀장 결재 칸 처리, 남의 상신 취소, 정정 시작, 점검자 지정, 모든 개선조치 확인 |
| **담당자** | 양식마다 여러 명 | 그 양식 작성·상신, 담당자 칸 처리, 정정 시작, 점검자 지정 |
| **작성 권한자** | 양식마다(선택) | 그 양식 작성·상신·재상신만 — 결재 칸 후보가 아니고 정정 시작·점검자 지정은 안 됨 |
| **점검자** | 문서마다(담당자·팀장이 지정) | 그 문서 작성(특이사항·개선조치 포함) — 상신은 역할이 있을 때만 |
| **확인자** | 개선조치마다(자동) | 그 개선조치 확인·수정 |
| 역할 없음 | — | **읽기만**. 작성 요구 문서 만들기(입고·생산·주기)는 누구나 |

- 권한이 없는 버튼은 숨기지 않고 **흐리게 + 이유 한 줄 + [역할 보기]**로 보입니다(승인·반려·확인처럼 내 칸이 아닌 것은 숨김).
- 서버도 화면과 관계없이 같은 규칙으로 막습니다(API 403·409 — [13.3](#133-자주-보는-오류)).
- 역할 설정은 서버를 다시 시작할 때 반영됩니다. 직원 등록·비활성은 재시작 없이 바로 반영(비활성 직원은 역할에서 빠짐).
- 작성 요구로 만들어진 문서의 작성자는 "작성 요구(자동)" + 흐린 "실행 ○○"(누른 사람). 목록에서는 문서 하나짜리 줄에만 보이고, 입고일·주 묶음 줄의 작성자 칸은 "–".

> 확인: P14 S5 C1~C28 · S6 U-1~U-11 · Mac S5 M-1~M-23, S4d M-24~M-29, S6 M-30~M-37

## 2. 문서 작성·수정·삭제

### 2.1 새 문서

**사용 순서**: 문서함 → [+ 새 문서] → 양식 고르기 → 작업일·마감·내용 입력 → [저장].

**요구사항**
- 작성자는 저장한 현재 사용자로 자동 기록됩니다. 담당자는 문서마다 고르지 않고 **양식에 정해져** 있습니다(문서 머리에 표시 — [1.6](#16-역할과-권한)).
- 양식 목록에서는 내가 쓸 수 있는 양식만 [선택]이 켜집니다(나머지는 "작성 권한 없음").
- 작업일 = 업무를 실제로 한 날. 미래 날짜도 저장할 수 있습니다.
- **작성 요구로 만들어지는 양식**(시험성적서·원산지 증빙·육안검사·CCP 일지·점검표)은 [새 문서]의 양식 목록에 나오지 않습니다. 이 문서들은 입고·생산·주기 규칙이 만듭니다([5장](#5-작성-요구--입고생산이-만드는-문서)·[9장](#9-주기-점검표--일반위생이물방충방서)).
- 저장할 때는 **형식만** 검사합니다(숫자 칸에 글자 등). 필수값이 비어도 저장됩니다 — 필수값은 작성완료 때 검사합니다.

> 확인: P1 S6-01·02·09, P4 S6-23

### 2.2 목록에서 찾기

- 기본 기간은 **최근 7일**. 양식·상태·기간·대상으로 거르고 [조회]합니다.
- 상태 필터에는 `작성 안 함`, `정정 진행 중 전체`도 있습니다.
- **묶음 줄**: 육안검사(D03)는 입고일마다, 점검표 D10·D12는 주(월~금)마다 한 줄로 묶여 보입니다. 줄을 누르면 묶음 상세로 갑니다([6장](#6-육안검사와-일괄-결재)·[9장](#9-주기-점검표--일반위생이물방충방서)).
- 점검표 주 묶음 줄은 그 주의 **가장 늦은 작업일** 자리에 정렬돼, 기본 목록 첫 쪽에서 이번 주 줄이 보입니다.
- [육안검사 오늘] 버튼: 오늘 입고 육안검사만 바로 봅니다.

> 확인: P1 S6-06, P7 S6 M-04·M-13, P8 S5 P1

### 2.3 수정

**사용 순서**: 상세 → [수정] → 바꾸기 → [저장]. 노란색 = 바뀐 칸, 초록색 = 추가 행, 취소선 = 삭제 예정 행.

**요구사항**
- **바뀐 부분만** 저장됩니다(행 단위). 바꾸지 않은 행의 기록 시각·기록자는 그대로 남습니다.
- 수정할 수 있는 상태: 작성중, 반려, 정정 중. 작성완료·결재중·승인 문서는 수정 버튼이 없습니다.
- **작성 권한**([1.6](#16-역할과-권한)): 그 양식의 담당자·작성 권한자·HACCP팀장과 그 문서의 점검자만 수정·작성완료·작성 재개·삭제·작성 안 함·파일·정정 취소를 할 수 있습니다. 권한이 없으면 버튼이 흐리고 머리 아래 한 줄 안내 + [역할 보기](API는 403 `ROLE_REQUIRED`).
- 점검자 칸은 담당자·HACCP팀장만 바꿀 수 있습니다(점검자 본인은 이름만 보임).
- **동시 수정 감지**: 두 창에서 같은 문서를 고치면 나중에 저장한 쪽은 "다른 사용자가 먼저 수정했습니다"(409 `VERSION_CONFLICT`)를 받고 최신 내용을 다시 불러옵니다. 남의 변경을 모르고 덮어쓰지 않습니다.
- CCP 일지의 같은 측정시점 중복 입력은 막힙니다(`DUPLICATE_ROUND`) — 재측정은 재측정 표시로.
- CCP 측정 영역은 문서를 만들 때 시작·종료 기본행이 1개씩 생깁니다. 두 행은 구분 변경·삭제가 불가능하고, [행 추가]는 1P·2B의 `작업 중` 또는 3P의 `중간` 측정행만 만듭니다. 아직 측정값이 없는 기본행은 측정 건수에 포함되지 않습니다.
- CCP-3P의 **제품 통과 요약**은 측정 영역과 별개여서 필요한 만큼 행을 추가할 수 있습니다.
- CCP-1P는 자력 **8,000G 이상**이고 자석봉 청소가 **O**일 때 해당 행이 적합입니다. 현재 양식의 자석봉 규격은 **Φ42.7**이며, 이전에 작성완료·결재된 문서는 당시 양식과 판정을 유지합니다.
- CCP-2B는 각 행의 온도를 68~72℃로 판정합니다. 시작전·종료전 측정일시를 입력하면 종료전 행에만 총 건조시간과 시간 판정(115~125분)이 자동으로 표시됩니다. 작업중 행에는 건조시간 칸이 비어 있습니다.

> 확인: P1 S6-03·04·05·10

### 2.4 삭제

**요구사항**
- 삭제는 **기록을 남기는 삭제**(논리 삭제)입니다. 목록에서 사라지지만 DB에는 남습니다.
- 지울 수 있는 문서: 작성중이고 한 번도 상신하지 않은 문서.
- **입고·생산 작성 요구로 만들어진 문서는 지울 수 없습니다**(상세에 "작성 요구로 만들어진 문서입니다. 삭제할 수 없습니다."). 점검표(주기 문서)는 작성중·상신 전이면 지울 수 있지만, 필요 없는 날은 [작성 안 함]을 씁니다(9.3).

> 확인: P1 S6-07·08, P4 S6-28

### 2.5 한계기준 이탈·개선조치

모든 양식의 상세 화면 아래에 있습니다.

**사용 순서**: 상세 → [+ 추가](또는 부적합 줄의 [개선조치 추가]) → 이탈내용·조치자·개선조치 및 결과 → [저장].

**요구사항**
- 이탈내용은 필수, 나머지는 선택입니다.
- **문서 상태와 상관없이 언제든** 쓰고 고칠 수 있습니다(승인된 문서도). 문서 버전·결재에는 영향이 없습니다.
- 쓰기·삭제는 작성 권한이 있는 사람([2.3](#23-수정)), **수정**은 그 줄의 지정 확인자도 할 수 있습니다.
- **확인자는 고르지 않습니다**: 새 개선조치를 저장할 때 그 양식 담당자 + HACCP팀장으로 자동 저장됩니다(10명까지, 담당자 먼저). 정할 사람이 없으면 저장은 되고 "확인자를 정하지 못했습니다" 알림.
- 부적합 판정이 있는 문서는 개선조치가 **1건 이상** 있어야 작성완료됩니다.
- 상신한 순간의 개선조치는 결재 회차에 함께 남아, 나중에 고쳐도 "상신 당시" 내용을 결재 요청 상세에서 볼 수 있습니다.
- **확인** 칸: 확인됨 → `이름(코드) · MM-DD HH:MM` / 내가 확인자이거나 HACCP팀장 → [확인](확인 창, [1.5](#15-ccp-대시보드)와 같음) / 다른 확인자 → `대기` / 확인자 없음 → `–`. 문서 상태와 상관없이 확인할 수 있습니다. 줄을 고치고 저장하지 않았으면 먼저 저장하라고 안내합니다.

> 확인: P4 S6-22·24, P8 S6 U-4.4, P11 S5 C14

### 2.6 출력·인쇄

**사용 순서**: 문서 상세 → [출력] → 새 탭의 종이 양식 확인 → [인쇄](PDF는 인쇄 창에서 "PDF로 저장"). 묶음 종이는 입고일 묶음 상세 [출력]([6.2](#62-입고일-묶음-상세))·주 묶음 상세 [주 출력]([9.4](#94-주-묶음-상세))·문서 목록 [월 출력]([9장](#9-주기-점검표--일반위생이물방충방서))에서도 열립니다.

| 종이 | 단위 | 용지 | 여는 곳 |
|---|---|---|---|
| CCP-1P·2B·3P 모니터링일지 | 문서 1건 | A4 세로 | 문서 상세 [출력] |
| D03 육안검사일지 | 입고일 하루(쪽당 9줄) | A4 가로 | 문서 상세 [출력](그 입고일 종이) · 입고일 묶음 상세 [출력] |
| D10·D12 점검표 | 주(월~금 + 출력할 수 있는 주말 문서가 있는 요일) | A4 세로 | 문서 상세 [출력](그 주 종이) · 주 묶음 상세 [주 출력] |
| D11 방충방서점검표 | 달(그 달 월요일 수만큼 4~5주) | A4 가로 | 문서 상세 [출력](그 달 종이) · 문서 목록 [월 출력] |
| D01·D02 첨부 | 파일 원본 그대로(머리·결재 없음) | 사진은 A4 세로 한 쪽에 하나 | 증빙 파일 [인쇄]·[모두 인쇄]([8.2](#82-보기)) |

**요구사항**
- 칸 배치는 기준서 종이 양식(CCP-1P·2B·D03·D10·D12·D11)·캔디류 양식(CCP-3P) 그대로입니다. 넘치면 다음 쪽에 머리(제목·결재 칸)와 표 머리를 반복하고, 쪽 번호를 찍습니다.
- 출력할 수 있는 상태: 작성완료·결재중·승인·정정 중. 작성중·반려 문서는 상세 [출력]이 꺼져 있습니다("작성완료 뒤 출력할 수 있습니다"). 묶음 종이에서는 그런 문서의 줄·칸만 비거나 "미작성"(D03)으로 나옵니다. D10·D12의 미작성·작성 안 함 요일 칸은 현업 합의 전까지 빈칸입니다.
- 결재 칸에는 **승인한 칸만 이름**이 찍힙니다(날짜 없음). 결재중이면 승인한 칸만, 작성완료(상신 전·상신 취소 뒤)면 비어 있습니다. D10·D12·D11 머리 결재 칸은 칸마다 그 기간에 그 역할로 가장 최근 승인한 사람, D12는 요일마다 그날 결재 칸도 찍습니다.
- 모든 서명·확인·조치자 칸은 **이름만**입니다. 5자까지는 글씨를 줄여 한 줄에 넣습니다.
- **정정 중인 문서는 이전 승인본 값**과 그 결재 칸으로 찍힙니다(정정 표시 없음). 개선조치 표는 늘 지금 값이고, 개선조치가 없으면 빈 줄 2개입니다.
- CCP 서명 칸 = 그 측정 행을 기록한 사람, 2B 작성일자는 측정이 다음 날까지 이어지면 "~ 마지막 측정일". 점검자는 D10만 찍습니다(그 주 가장 늦은 요일 문서의 점검자). D03·D12·D11 종이에는 점검자 칸이 없습니다.
- 출력해도 문서·결재 기록은 바뀌지 않고, 출력 기록도 남지 않습니다. 현재 사용자를 고르지 않아도 열립니다.

> 확인: P12 S5 Mac M-1~M-6 · P12 Mac 확인 C·R·W·P·M·K·F 27항목(2026-10-21)

## 3. 작성완료와 작성 재개

**사용 순서**: 상세 → [작성완료] → 확인 창 [작성완료].

**요구사항**
- 작성완료 때 **필수값·행 개수·양식 규칙**을 검사합니다. 빠진 것이 있으면 항목 이름으로 목록을 보여 주고, [수정하러 가기]·[개선조치 입력하러 가기]·[파일 올리러 가기]로 바로 이동합니다.
  - CCP 일지: 미리 만들어진 시작·종료 행의 필수 측정값을 채워야 하고, 시작 행이 가장 이르고 종료 행이 가장 늦어야 합니다. CCP-2B는 종료전 행의 총 건조시간을 자동 계산하며 115~125분 밖이면 개선조치가 필요합니다.
  - 부적합(한계기준 이탈·불량·X)이 있으면 개선조치 1건 이상.
  - 시험성적서·원산지 증빙(D01·D02)은 증빙 파일 1개 이상.
- 작성완료된 문서는 **잠깁니다**. 고치려면 [작성 재개] → 작성중으로 돌아가고 작성완료 시각·사람은 지워집니다.
- **상신은 작성완료 문서에서만** 할 수 있습니다.
- 육안검사(D03)는 작성완료 순간 LOT 판정이 수불에 전달됩니다([5.4](#54-육안검사-판정-전달)).

> 확인: P4 S6-21·23, P8 S6 U-1.6·U-4.3

## 4. 결재 — 상신·승인·반려·재상신

### 4.1 상신

**사용 순서**: 작성완료 문서 상세 → 결재 영역의 결재선 미리 보기 확인 → [결재 상신] → 확인 창(결재선 표) [상신].

**요구사항**
- **상신할 수 있는 사람**: 그 양식의 담당자·작성 권한자·HACCP팀장(재상신도 같음). 아니면 [결재 상신]이 흐리고 이유 + [역할 보기](API 403 `ROLE_REQUIRED`). 역할 없는 사람이 섞인 일괄 상신은 그 문서에 "⚠ 상신 불가".
- **결재선은 자동**입니다(고르는 칸 없음): 양식마다 역할 설정의 결재 칸 — 담당자만 / 담당자 + HACCP팀장 / HACCP팀장만. 칸 이름은 양식 설정(예: D10 "작성자").
- 칸 **후보** = 상신 순간 그 역할을 가진 사람 전부. 후보 중 **1명**이 처리하면 그 칸은 끝. 칸 사이 처리 순서는 없고, 모든 칸이 승인하면 문서가 승인됩니다.
- 상신 뒤 역할이 바뀌어도 **그 회차 후보는 그대로**. 재상신은 그때 설정으로 새 결재선.
- 담당자이면서 HACCP팀장인 사람(겸직)은 한 회차의 두 칸을 각각 처리할 수 있습니다. 상신한 사람도 자기 칸 후보입니다.
- 칸을 처리할 사람이 0명이면 상신이 막힙니다(409 `NO_APPROVAL_LINE`), 역할 설정 파일 형식 오류면 모든 상신·정정 시작이 409 `ROLE_CONFIG_INVALID`([역할 보기]에 표시).
- 상신하면 문서가 잠깁니다(결재중). 상신 시점의 문서 내용이 **결재 회차 스냅샷**으로 저장됩니다.
- 결재선 변경은 없습니다. 상신을 거두려면 [상신 취소]([4.4](#44-상신-취소)).

### 4.2 승인·반려

**사용 순서**: 결재함(또는 문서 상세의 "내 결재 대기" 줄) → [승인] / [반려] → 의견(반려는 사유 필수) → 확인.

**요구사항**
- 승인 의견은 선택(500자), 반려 사유는 필수.
- 한 칸이라도 반려하면 그 회차는 끝나고, 남은 대기 칸은 "미처리 종료"가 됩니다. 문서는 **반려** 상태가 됩니다.
- 이미 끝난 회차의 칸을 처리하려 하면 "이 회차는 이미 끝났습니다(반려 또는 결재 완료)…"(`REQUEST_CLOSED`).
- 결재함: 대기·처리 완료 탭, 기간 기본 전체, 페이지 나눔. 입고일(육안검사) 필터로 대상 LOT 입고일 기준으로 거를 수 있습니다.
- 결재함·사이드바 숫자 = **내 칸**(내가 후보인 대기 칸). 겸직자는 같은 회차가 칸마다 한 줄(둘째 줄 흐리게)이고 칸마다 따로 승인합니다.
- 후보가 아닌 칸은 처리할 수 없습니다(403 `NOT_YOUR_SLOT`). 같은 칸을 다른 후보가 먼저 처리했으면 "이미 처리한 결재 칸입니다"(409 `ALREADY_DECIDED`) + 다시 조회(사이드바 숫자도 다시 셈).
- P14 전에 상신된 회차(옛 회차)는 칸 이름 그대로, 지정된 결재자만 처리합니다.
- 결재 요청 상세(D01·D02)의 **상신 당시 증빙 파일**: 상신 순간의 파일을 문서 상세와 같은 미리보기 카드·[인쇄]·[모두 인쇄]로 봅니다([8.2](#82-보기)). 상신 뒤 연결이 끊겨 지워진 파일은 "파일 없음"이고 인쇄에서 빠집니다. 결재함 [승인] 창(여러 건)에는 없습니다.

### 4.3 반려 뒤 재상신

**사용 순서**: 반려 문서 → [수정](반려 상태에서 바로 고칠 수 있음) → [작성완료] → [재상신](그때 역할 설정으로 결재선) → 승인.

**요구사항**
- 회차 번호가 늘고, 지난 회차(반려 사유·스냅샷)는 그대로 남습니다. 결재 영역에서 회차 기록을 볼 수 있습니다.
- 반려 뒤·상신 취소 뒤 다시 올리는 것은 모두 **재상신**입니다. 정정 회차는 꼬리표 `정정`.

> 확인: P3 S6-11~19, P4 S6-21, P8 S6 U-1.4·U-3.1~3.5

### 4.4 상신 취소

**사용 순서**: 결재중 문서 상세 → 결재 영역 [상신 취소] → 확인 창 [상신 취소].

**요구사항**
- **그 회차를 상신한 사람 또는 HACCP팀장**이 할 수 있습니다. 다른 사람에게는 흐린 버튼 + "상신한 사람(○○)…" 이유(API는 403 `NOT_REQUESTER`). 팀장이 남의 상신을 취소하면 확인 창에 "○○이 상신한 회차입니다. HACCP팀장으로 취소합니다." 역할 설정 파일 오류면 팀장 예외는 없습니다(상신자 본인은 됨).
- 결재자가 이미 승인한 칸이 있어도 회차가 진행 중이면 됩니다. 받은 승인은 기록에 남고 `무효`로 표시, 남은 대기 칸은 "미처리 종료".
- 문서는 **작성완료**로 돌아가고 회차는 "취소됨"으로 남습니다. 다시 올리면 새 회차([재상신]). 정정 재상신을 취소하면 정정 진행 상태는 그대로입니다.
- 사유는 받지 않습니다. 수불로 가는 신호는 없습니다.
- 그사이 결재가 끝났으면 "결재가 이미 끝났습니다" + [다시 열기].
- 상신 이력이 남으므로 취소한 문서도 삭제할 수 없습니다(반려 문서와 같음).
- 결재함 처리 완료 탭과 묶음 상세의 결재 칸에도 "취소됨"이 보입니다.

> 확인: P10 S5 C10~C14 · S6 U-3·U-4 · Mac S5 M-5, S6 M-4

## 5. 작성 요구 — 입고·생산이 만드는 문서

수불·생산 앱이 입고 등록·생산 시작 때 문서 쪽 함수를 부르면 필요한 문서가 **작성중**으로 미리 만들어집니다. 지금은 **작성 요구 [임시]** 화면이 그 호출을 흉내 냅니다.

### 5.1 입고(LOT 생성) → D01·D02·D03

**사용 순서**: 작성 요구 → [LOT 생성] → 품목·매입처·입고일·수량(·소비기한) → [입고 + 작성 요구]. (선택) "육안검사 함께 입력"에 검사 값을 넣으면 새 D03에 채워집니다.

**요구사항**
- 입고 LOT마다 **시험성적서(D01)·원산지 증빙(D02)·육안검사일지(D03) 각 1건**. 부자재 LOT에도 원산지 문서가 생깁니다(현업 확인 대기).
- 같은 LOT을 다시 호출해도 문서가 늘지 않습니다("이미 있음").
- 입고일은 오늘 이전(수불 규칙), LOT 번호는 수불 규칙으로 자동.
- 작성 요구 중 오류가 나면 **입고까지 함께 취소**됩니다(한 트랜잭션).
- 문서 상세 "대상"에 `LOT 번호 · 품명 · 매입처`, 작업일은 입고일로 고정입니다.

### 5.2 생산 시작 → CCP 일지

**사용 순서**: 작성 요구 → [생산 시작] → 품목·공정 유형(제조/포장)·생산일·생산량.

**요구사항**
- 제조 배치: CCP-1P(쇳가루 제거)·CCP-2B(건조)·CCP-3P(금속검출) 일지 3건. 포장 배치: 없음. 취소된 배치에는 만들지 않습니다.
- CCP 판정은 값을 넣는 즉시 양식의 한계기준으로 계산되어 표시되고, 서버가 저장합니다.

**생산 화면과 CCP 일지 오가기**(P11)
- [생산지시·실적] → 생산 목록에서 배치 → [연결 문서] 탭: CCP 일지마다 상태 · 최근 측정(시각·측정시점·판정, 측정 수) · 이탈·개선조치(⚠ 이탈 n · 개선조치 없음 n · ● 확인 대기 n · 확인됨 n, 없으면 "이상 없음"). [열기] → 문서 상세, 문서 상세 [뒤로] → 그 배치 [연결 문서] 탭.
- [CCP 대시보드에서 보기] → 기준일 = 그 배치 제조일, 그 배치 영역을 펼쳐 테두리로 표시.
- 반대로: CCP 대시보드 펼친 배치 영역의 [생산 기록 ↗] → 그 배치 [생산 진행·실적] 탭, CCP 문서 상세 머리의 배치 이름 → 그 배치 [연결 문서] 탭.
- 생산 시작 전(계획) 배치는 CCP 일지가 아직 없어 [연결 문서]에 "시작 전", CCP 대시보드에도 나오지 않습니다.
- 생산일지 양식이 설치돼 있으면 제조 배치 생산 시작 때 **생산일지 1건**도 함께 만들어집니다(결재 없음 — [10장](#10-생산일지와-생산-기준정보)). [연결 문서]의 "CCP 일지 n건"은 CCP 일지만 세고, 생산일지는 표 아래 한 줄(상태·[열기])로 따로 보입니다.

### 5.3 LOT별 연결 문서

- 작성 요구 화면 LOT 줄 [연결 문서], 또는 문서 상세의 LOT 링크 → 그 LOT의 D01·D02·D03과 상태, **최신 승인본 기준 판정**.
- 수불은 같은 내용을 함수 `docs_for_lot`로 받아 입고 취소 등을 판단합니다.

### 5.4 육안검사 판정 전달

**요구사항**
- 육안검사(D03)를 **작성완료하는 순간** 그 LOT의 판정(적합/부적합)을 수불 판정 함수에 전달합니다. 수불이 거부하면 작성완료 전체가 취소되고 화면에 LOT별 사유가 나옵니다(`INVENTORY_REJECTED`).
- 판정을 바꿔 다시 작성완료할 때는 "판정 변경 사유"(선택, 200자)를 함께 보냅니다. 정정 중이면 정정 사유가 쓰입니다.
- 승인·반려·작성 재개 때는 전달하지 않습니다. 문서는 LOT 상태를 저장·표시하지 않습니다(LOT 상태는 수불만 가짐).

> 확인: P5 S6-31~38, P6a S6a-1~5, P7 S6 A~E·M-01~03·M-08, P8 S6 U-1.1

## 6. 육안검사와 일괄 결재

### 6.1 육안검사(D03) 작성

**요구사항**
- LOT 1건 = D03 문서 1건. 입고 정보 7개(LOT·입고일·매입처·구분·품명·중량·소비기한)는 읽기 전용, 검사 = 성상 및 이물혼입·외/내포장·표시사항·시험성적서 + **최종판정은 작성자가 직접** 고릅니다(기본값 없음, 불량이 있는데 적합이면 안내).
- 시험성적서 유/무는 D01 파일 여부로 "무 (자동)"처럼 제안되고, 저장할 때 함께 저장됩니다.
- 점검자는 문서마다 필수입니다.
- 최종판정이 부적합인데 이탈·개선조치가 없으면, [작성완료]를 누를 때 판정 확인 창 없이 "부적합 항목이 있어 이탈·개선조치를 1건 이상 적으세요"가 먼저 나옵니다(ISS-027 ①).

> 확인: P10 S5 C15

### 6.2 입고일 묶음 상세

**사용 순서**: 문서 목록 → 입고일 묶음 줄(또는 [육안검사 오늘]) → 묶음 상세 → 줄 선택(머리 ☐ = 전체) → [점검자 지정] / [선택 상신] / [선택 승인].

**요구사항**
- 일괄 기능을 쓸 수 있는 양식: **D03, D10, D11, D12**(설정 `HACCP_BATCH_TYPES`). 다른 양식이 섞이면 요청 전체가 거부됩니다.
- 한 번에 **최대 50건**. **문서마다 따로 처리**되어 일부만 실패할 수 있고, 결과 창에 성공·실패 목록이 나옵니다.
- 선택 상신: 작성완료 문서만 대상(나머지는 "제외"로 표시). 결재선은 **문서마다 그 양식의 역할 설정으로 자동**, 내가 상신할 수 없는 문서는 미리 "⚠ 상신 불가".
- [점검자 지정]은 담당자·HACCP팀장만(아니면 흐리게 + 이유). [작성 안 함]은 작성 권한이 없는 문서를 "⚠ 작성 권한 없음"으로 뺍니다.
- 선택 승인: 내 칸이 있는 문서만(진행 칸 "▸ 내 칸"·"▸ 내 칸 2개"). 의견은 선택, 모든 칸에 같게. 반려는 일괄로 하지 않고 한 건씩.
- 결재함에서도 여러 건을 골라 승인할 수 있습니다.
- [출력]: 그 입고일의 육안검사일지 종이(A4 가로 — [2.6](#26-출력인쇄)).

> 확인: P7 S6 M-04~M-07, P8 S6 U-4.6~4.8

## 7. 정정 — 승인된 문서 고치기

승인된 문서에서 오류를 발견하면 "승인 취소"가 아니라 **정정**합니다.

**사용 순서**: 승인 문서 상세 → [정정 시작] → 정정 사유(필수, 200자) → [수정] → [작성완료] → [결재 상신](정정 회차 — 꼬리표 `정정`) → 승인.

**요구사항**
- 정정 중 상태(`정정 중`)가 되고, 배너에 정정 사유가 보입니다. **새 승인 전까지 이전 승인본이 유효**합니다(수불 판단·출력은 유효 승인본 기준).
- 정정 회차가 승인되면 이전 승인 회차는 "대체됨"으로 표시됩니다.
- **정정 취소**는 정정 시작 뒤 아무것도 고치지 않았을 때만 됩니다(승인 상태로 복귀). 고친 뒤에는 `CORRECTION_HAS_CHANGES` — 작성완료 후 재상신으로 끝냅니다.
- **정정 시작은 그 양식의 담당자·HACCP팀장만**(작성 권한자는 안 됨 — 흐린 버튼 + 이유). 기한은 추후.

> 확인: P7 S6 M-10·M-10b, 프리셋 WF-PS-14~22

## 8. 증빙 파일 (시험성적서·원산지 증빙)

시험성적서(D01)·원산지 증명/수입면장(D02) 상세의 **증빙 파일** 영역에서 씁니다.

### 8.1 올리기

**사용 순서**: D01·D02 상세 → 파일을 끌어 놓기 또는 [📎 파일 선택](여러 개 가능).

**요구사항**
- 형식 **PDF·JPG·PNG**, 파일당 **20MB 이하**. 확장자만 바꾼 파일(이름만 `.pdf`인 텍스트 등)은 내용 검사로 거절됩니다(`⚠ [FILE_REJECTED] 파일 내용이 확장자와 맞지 않습니다.`).
- 여러 개를 올리면 파일마다 따로 처리됩니다 — 실패한 파일만 ⚠, 나머지는 올라갑니다.
- 올릴 수 있는 상태: 작성중·반려·정정 중. 작성완료면 [작성 재개] 뒤, 결재중·승인이면 **보기만** 됩니다.
- 작성완료에는 파일 **1개 이상** 필요. D02는 "서류 종류"(원산지 증명/수입면장)도 필수입니다.

### 8.2 보기

- 줄의 [보기] → 새 탭에서 파일이 열립니다(PDF는 브라우저 보기).
- 파일 표 아래 **미리보기 카드**: 사진은 그림(누르면 새 탭에 원본), PDF는 화면 안에서 첫 쪽부터 스크롤. 문서 상태와 상관없이 파일만 있으면 보입니다.
- 카드마다 [인쇄], 머리에 [모두 인쇄]. 사진은 A4 세로 한 쪽에 하나(쪽에 맞춰 축소, 회전·쪽 번호 없음), PDF는 원본 그대로 인쇄 창. [모두 인쇄]는 사진을 한 번에 인쇄한 뒤 PDF를 파일마다 "다음 파일 인쇄" 확인으로 이어 갑니다.
- 결재 요청 상세에도 같은 카드가 있습니다([4.2](#42-승인반려)).

### 8.3 이전 파일 불러오기 (같은 성적서를 여러 LOT에)

**사용 순서**: D01·D02 상세 → [이전 파일 불러오기] → 품명·매입처(기본 = 이 문서 LOT 값)·기간(30·90·180·365일, 기본 90일) → [검색] → 고르기 → [연결 (n)].

**요구사항**
- **같은 양식**의 파일만 찾습니다. 파일을 복사하지 않고 이 문서에 **연결**합니다.
- 연결된 파일 줄에는 `다른 문서 n곳과 공유`가 표시되고, 결과 줄에 `#원본 문서에서 불러옴`이 나옵니다.
- 이미 연결된 파일은 고를 수 없습니다.

### 8.4 연결 끊기(✕)

**요구사항**
- 다른 문서도 쓰는 파일: "다른 문서도 쓰는 파일이라 **파일은 남습니다**." — 이 문서에서만 빠집니다.
- 마지막 연결이면 파일도 지웁니다. 단 **상신된 적 있는 파일은 보존**됩니다(결재 기록 증빙).
- 상신할 때 연결된 파일에 보존 표시가 붙습니다.

> 확인: P8 S5 F1~F7·M-6·M-7, P8 S6 U-1.2~1.8·U-2·U-3 · Mac M-2~M-5 · P12 Mac F-1~F-7

### 9.1 작성

**사용 순서**: 문서 상세 → [수정] → 점검표 표에서 결과 고르기 → 점검자 고르기 → [저장].

**요구사항**
- 표는 종이처럼 **주기·관리·검증 내용·결과** 칸, 같은 값이 이어지면 〃.
- 결과 = **O / X / 해당 없음** 버튼. 같은 버튼을 다시 누르면 빈칸.
- [매일 항목 모두 O]: 매일 항목의 **빈칸만** O로(이미 고른 값은 그대로).
- 새 문서에는 미리 채운 값이 있습니다(`미리` 표시): 입고 항목 O, 그날 해당 없는 주·월 항목은 해당 없음. 바꿀 수 있습니다.
- D10 연간 항목(용수검사·검교정)은 **실시일만** 적습니다(선택, 비워도 부적합 아님).
- D12 공정명은 직접 입력, 최근 값이 `최근: …`과 목록으로 제안됩니다.
- D11 점검일 기본값은 그 주 월요일, 그 주(월~일) 안에서 바꿀 수 있습니다.
- 점검자(머리)는 필수입니다.
- 상세 위에 `점검표: O n · X n · 해당 없음 n (빈칸 n)` 요약, `같은 주: 월 ✅ 화 ⊘ 수 ▢(지금) …` 줄과 [주 묶음 ▸].

### 9.2 X(불량)가 있을 때

**요구사항**
- 폼과 상세 모두 **X 줄만** 분홍 + 왼쪽 빨간 띠로 강조, 섹션 머리에 `⚠ 부적합`.
- 작성완료하려면 개선조치 1건 이상. 상세 X 줄의 [개선조치 추가]를 누르면 이탈내용에 `항목 문장 — 불량`이 미리 채워집니다.

### 9.3 작성 안 함 · 되돌리기

**사용 순서**: 작성중 문서 상세 → [작성 안 함] → 사유 빠른 선택 (휴무)(작업 없음) 또는 직접 입력(200자) → [작성 안 함]. 되돌리려면 → [되돌리기](확인 창 없음).

**요구사항**
- 주기 작성 요구 문서(작성중)만 작성 안 함으로 할 수 있습니다. 작성 안 함 문서는 회색 배지·사유·처리자가 보이고 수정·작성완료·결재가 숨겨집니다.
- 되돌리면 작성중, 써 둔 값은 그대로.
- 여러 날 한꺼번에: 주 묶음 상세에서 골라 [작성 안 함 (n)].
- 필요 없는 날은 작성 안 함으로. [삭제]는 날짜를 잘못 골라 만든 문서용입니다(작성중·상신 전) — 규칙상 만드는 평일을 지우면 다음 주기 생성(명령·[주기 문서 만들기]) 때 다시 만들어집니다.

### 9.4 주 묶음 상세

**사용 순서**: 문서 목록 → 양식 = 점검표 → 주 줄 → 주 묶음 상세(또는 상세의 [주 묶음 ▸]).

**요구사항**
- [◀ 전주]·[다음주 ▶], 요약(상태별 수·내 결재 대기), 월~금 줄(없는 날 `문서 없음`).
- 칸: 날짜(요일)·문서·상태·점검자·**점검 결과**(O·X·NA·빈칸 수, **작성 안 함 날은 `–`**)·판정(적합/부적합)·결재.
- 버튼: [점검자 지정 (n)]·[선택 상신 (n)]·[선택 승인 (n)]·[작성 안 함 (n)] — 괄호 숫자는 선택한 것 중 그 동작이 되는 문서 수. 작성 안 함 날은 상신·승인에서 빠집니다.
- [주 출력]: 그 주 점검표 종이(A4 세로, 출력할 수 있는 주말 문서가 있으면 그 요일 칸 추가, 아직 오지 않은 주는 꺼짐 — [2.6](#26-출력인쇄)).

## 10. 생산일지와 생산 기준정보

제조 배치마다 생산일지 1건(생산 시작 때 자동). **결재가 없습니다** — 작성중 ↔ 작성완료만. 기본정보·원료칭량은 수불 생산 기록에서 읽어 오고(연동), 공정은 템플릿을 불러오거나 직접 넣습니다.

### 10.1 찾기

- 문서함 [전체 문서] — 상태 옆 "결재 없음"
- 작성 요구 화면 배치 줄 "CCP-1P·2B·3P ✓ / 생산일지 ✓"
- CCP 대시보드 펼친 배치 영역 "생산일지 작성중 · 공정 n/m ↗"
- CCP 일지 머리 "생산일지 #n ↗ (그 공정 표시명)" — 생산일지 [뒤로] → 그 CCP 일지
- 수불 생산지시·실적 → 배치 → [연결 문서] 생산일지 줄 [열기]

### 10.2 작성

1. **기본정보**(연동, 읽기만): 제조일·LOT·[유형] 제품명·품목제조보고번호·생산지시량·실생산량. 수불이 산출을 등록하면 실생산량이 바뀝니다.
2. **작업 전 점검** 3항목(적합/부적합) + 점검자.
3. **원료칭량**(연동 + 일부 입력): BOM 줄 순서 · 비율(%, 소수 둘째 자리) · 투입량 · 사용량(수불 투입 합) · 대체 원료·원산지("A → B(대체)") · 미투입. 재고 관리 안 하는 원료(정제수 등)는 사용량을 직접 입력. 줄마다 작업자·비고, [모두 같은 사람].
4. **공정**: 공정이 없으면 [템플릿 고르기](같은 품목 지난 배치 템플릿 [바로 불러오기]) — 바꾸기/덧붙이기. [+ 공정 추가] — 기본 제공(쇳가루 제거·건조·금속검출기·내포장·외포장, 일지당 1개), 일반 공정, 직접 입력([공정 목록에도 등록]). ↑↓·삭제. 공정 카드: 작업일·작업자·소요기간·입력 방식에 따른 칸(판정·온도·시간·수량, 내포장 수량·규격, 외포장 포장재질·소비기한·완제품수량).
5. [저장]. 저장 안 한 변경이 있으면 화면 이동·창 닫기 때 확인 창.
6. [템플릿으로 저장] — 지금 공정 순서를 새 템플릿(같은 이름이면 [덮어쓰기]).

### 10.3 CCP 공정 값

- CCP 공정(쇳가루 제거·건조·금속검출기)은 **그 배치의 CCP 일지가 있을 때만** 넣을 수 있습니다.
- 결과 칸(1P·3P 적합/부적합, 2B 온도·시간)은 **읽기 전용** — [CCP 일지 값 가져오기]로만 채웁니다. [일지 열기 ↗]로 CCP 일지로.
- 카드 상태 줄: "CCP 일지가 아직 작성중입니다" / "CCP 일지 값과 다릅니다" / "✓ CCP 일지와 같음".

### 10.4 작성완료·작성 재개

- [작성완료]: 필수 칸과 함께 **CCP 공정마다 그 CCP 일지가 작성완료 이후(작성완료·결재중·승인)이고 값이 같은지** 검사합니다. 빠진 것은 맨 위 목록(누르면 그 칸, 빨간 테두리). 연동 값을 못 읽으면 작성완료할 수 없습니다.
- 작성완료하면 기본정보·원료칭량을 **그 시점 값으로 고정**해 보여 주고 칸이 잠깁니다. 그 뒤 수불 값이 바뀌면 노란 줄 "연동 값이 바뀌었습니다", CCP 일지가 다시 작성중이 되거나 값이 바뀌면 노란 줄 "CCP 일지가 바뀌었습니다" — [작성 재개]로 고칩니다(확인 창 없음).
- 취소된 배치의 생산일지는 회색 배너와 함께 읽기 전용입니다.
- 작성·작성완료는 역할 파일의 `PROD-LOG` 담당자와 HACCP팀장. 다른 사람은 버튼이 꺼지고 안내가 보입니다.

### 10.5 생산 기준정보 — 공정·공정 템플릿

사이드바 [생산 기준정보] — 탭 [공정] [공정 템플릿]. **누구나** 관리하고 모든 변경은 이력으로 남습니다.

- **공정**: 이름·기능(기본 제공 🔒/일반)·상태 조회, [+ 공정 추가](이름·입력 방식·설명·표준 소요기간). 같은 이름은 막고 비슷한 이름은 경고 [그래도 저장]. 템플릿에 쓰인 공정을 고치면 "덮어쓰지 않은 템플릿 n개에 반영(만든 일지는 그대로)", 입력 방식 변경은 한 번 더 확인. 기본 제공은 표시명·설명·소요기간만. [사용 중지/다시 사용] · [삭제](한 번도 안 쓴 일반 공정만) · [이력](누가·언제·전→후·생산일지 문서 번호).
- **공정 템플릿**: 목록(공정 수·CCP·만든 사람·최근 사용) · [편집](이름, 단계 ↑↓·빼기·넣기 — 같은 공정 두 번 불가, 최대 30개, 줄마다 "덮어쓸 값": 표시명·설명·입력 방식·소요기간·포장 정보) · [복제] · 사용 중지 · 삭제(한 번도 안 불러온 것만) · 이력. 편집 중 나가면 확인 창.
- 생산일지 화면에서도 [+ 공정 추가] "공정 목록 관리 ↗", 불러오기 창 "템플릿 관리 ↗"로 바로 갑니다.

### 10.6 출력

- 생산일지 머리 [출력] → 새 탭 인쇄 페이지 → [인쇄](PDF는 브라우저 "PDF로 저장"). **작성완료한 생산일지만**(작성중이면 버튼이 꺼지고 "작성완료 뒤 출력할 수 있습니다").
