# 문서 영역 개발 단계·기호 설명

문서 영역 커밋 메시지·결정 기록에 나오는 **C3, S6, P8, D-141, ISS-033** 같은 기호가 무엇을 뜻하는지 정리했습니다. 단계별 설계·확인 기록은 개인 개발 폴더(`dev-notes/`, Git 밖)에 있고, 저장소에는 결과만 들어갑니다. 이 문서는 커밋만 보고도 어느 단계의 무엇인지 알 수 있게 하는 다리입니다.

- 결정 내용: [document-decisions.md](document-decisions.md) · 기능 사용법: [document-user-guide.md](document-user-guide.md)

## 1. 한눈에 보기

```
스프린트 1 ── P1 문서 → P2 결재 → P3 워크플로우                     (2026-10-09 ~ 10-10)
스프린트 2 ── S0 준비 → P4 문서 확장 → P5 작성 요구
              → P6a 육안검사 구조 → P6 정정·판정 연동 → P7 일괄 결재  (10-11 ~ 10-13)

              구간 B  P8~P12 화면·기능 설계 (S1a·S1b·S2b)
              구간 C  수불 main 위에서 구현
                      C2 통합 → C3 P8 → C4 P9 → C5 P10 (10-13 ~ 10-15) → PR #16으로 main 병합
스프린트 4 ── 기능·이슈마다 작은 브랜치 + PR                         (10-19 ~)
              P11 → P14 역할 설계 → P12 → P14 구현 → V2 통합 테스트 → D04
```

### 4.1 스프린트 4 — 작은 브랜치로 구현과 수정을 함께 (D-161)

스프린트 3까지는 MVP를 빨리 만들려고 브랜치 하나(`feature/document-integration`)를 썼고, PR #16(`f479bdb`)으로 `main`에 병합했습니다. 스프린트 4부터는 구간 C 번호 대신 **브랜치·PR**로 단계를 나눕니다.

| 브랜치 | 단위 | 예 |
|---|---|---|
| `feature/…` | 기능 단위(P) 하나 — S4~S6은 커밋으로 나누고 PR 1개 | `feature/p11-ccp-dashboard` |
| `fix/iss-nnn-…` | 이슈 하나(또는 같은 화면의 작은 이슈 묶음) | `fix/iss-040-…` |
| `docs/…` | 저장소 문서만 | — |

- 순서: P11 → P14 역할 설계 → P12 → P14 구현 → V2 통합 사용 테스트(예전 C8) → D04
- 기능 단계 하나마다 수정 칸을 함께 둡니다(기능 7 : 수정 3). 업무가 막히는 이슈는 기능 작업을 멈추고 먼저 고칩니다
- 이슈 심각도: **차단**(업무 흐름이 막힘·데이터 틀림) · **주요**(우회는 되지만 확인 항목 실패) · **경미**(문구·배치) · **판단**(정책 질문)
- 이 문서와 사용설명서·결정 정리는 동작이 바뀌는 PR 안에서 함께 고칩니다
