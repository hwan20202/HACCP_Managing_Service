## 1. 로컬 DB 적용

Git으로 코드를 병합해도 기존 SQLite DB 구조는 자동으로 바뀌지 않는다. `migrate`는 코드에 포함된 마이그레이션을 실제 DB에 적용한다.

| 확인 항목 | 결과 |
|---|---|
| 적용 전 재고 마이그레이션 | `inventory.0001`~`0007` 적용 완료 |
| 적용 전 문서 마이그레이션 | `documents.0001`~`0003` 적용 완료 |
| 미적용 항목 | `approvals.0002_request_cancelled` |
| 백업 | SQLite backup API로 기존 DB 백업 |
| 적용 결과 | `approvals.0002_request_cancelled... OK` |

백업 파일: `data/db/app-before-approval0002-20261015-232640.sqlite3`.

실행 명령:

```powershell

```

이번 QA에서는 업무 데이터 생성용 개발 시드를 실행하지 않았다. 별도 브랜치 생성·커밋·push·main 병합도 수행하지 않았다.

### 실행 환경 관련 사항

첫 실행은 샌드박스의 로컬 네트워크 접근 제한(`WinError 10013`)으로 HTTP 회귀 테스트에서 중단됐다. localhost 통신이 가능한 권한으로 다시 실행한 결과 전체 검사가 통과했다. 임시 폴더는 쓰기 가능한 QA 산출물 디렉터리로 지정했다. 이 최초 중단을 제품 코드의 테스트 실패로 판단하지 않았다.

## 3. 파일 DB 동시성 검사

## 5. 확인된 준비 사항과 남은 QA

현재 로컬 DB의 `SEMI` 품목 수는 0개이며, 조회한 재고·배치 목록도 비어 있었다. 따라서 제조배치 화면이 열리는 것과 실제 제조 업무를 끝까지 수행할 수 있는 것은 구분해야 한다.

| 다음 확인 항목 | 필요한 준비 |
|---|---|
| 원료 입고와 문서 생성 | 소비기한 있음·없음 원료를 각각 입고하고 D01~D03 확인 |
| 제조배치 신규 생성 | 반제품 품목 및 필요한 BOM 준비 |
| 생산 시작 및 CCP 생성 | 시작 후 CCP-1P·2B·3P 연결 확인 |
| 원료 선택·투입·FEFO 추천 | 사용 가능한 원료 LOT 재고 준비 |
| 분할 산출·완료 | 같은 배치에서 두 번 산출 후 동일 LOT 누적 확인 |
| 재고·수불 결과 | 투입 차감·산출 증가, 개별 이동 내역 대조 |
| 문서 작성·결재 화면 | 사용자 선택 후 작성·상신·승인·상신 취소 확인 |
| 오류·취소 흐름 | 양식 누락 시 롤백, 결재 상태에 따른 입고 취소 제한 확인 |

업무 정책상 별도 후속 항목: CCP 이탈 시 HOLD 호출 시점, 입고·배치 취소 후 연결 문서 처리, 운영용 문서 양식 등록 절차. 이번 QA에서 해당 정책을 새로 확정하거나 구현하지 않았다.
