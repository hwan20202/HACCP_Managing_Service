# 제조배치 수동 보류·해제 화면

2026-10-24 · `fix/inventory-receipt-guidance` · 로컬 구현·검증

문서 결재와 별도로 담당자가 보류를 등록하고, 개선조치 확인 후 해제하는 현업 결정에 따라 제조배치 상세에 조작 화면을 연결했습니다. 보류 유형은 MANUAL이며 문서 id나 결재 완료를 요구하지 않습니다.

## 화면과 API

- 배치 목록에 보류 중 배지를 표시합니다. 목록 API는 미해제 배치 보류 수를 집계해 제공하며, 배치별 개별 조회를 추가하지 않습니다.
- 배치 상세 API에 `holds` 전체 이력과 `active_hold_count`를 추가했습니다. 배치에서 산출 LOT로 전파된 보류는 배치 보류 건수에 중복 집계하지 않습니다.
- 상세 상단의 제조배치 보류 패널에서 사유를 입력해 등록합니다. 해제 시에는 개선조치 완료·해제 가능 여부 확인 체크와 사유 입력이 필요합니다. 선택된 처리 담당자를 화면에 표시하고 변경 시 갱신합니다.
- 후속 화면 조정: 보류 이력이 없는 계획 배치에서는 보류 UI를 숨깁니다. 보류 이력이 없는 진행 배치는 작업 영역 하단의 접힌 ‘보류 관리’에서 등록합니다. 실제 보류 중인 배치는 상단 경고·해제 패널을 표시하며, 해제 후에는 상단에 접힌 이력만 표시합니다. 과거에 계획 상태에서 등록된 활성 보류는 해제할 수 있도록 경고를 유지합니다. 완료·취소 배치는 기존 이력만 확인하고 신규 등록 버튼은 표시하지 않습니다.
- 보류 사유·담당자·시각, 해제 내용·담당자·시각을 이력 표로 확인합니다. 다시 확인 버튼으로 최신 상태를 조회할 수 있습니다.
- 보류 중 생산 시작·원료 투입·산출·완료 입력 영역을 비활성화합니다. 기존 투입·산출 기록은 읽을 수 있고, 보류 해제 조작은 계속 가능합니다. 서버 차단 조건도 유지합니다.
- 서버에서 이미 해제된 보류를 재조회하면 열려 있던 해제 폼을 닫습니다. 실패한 요청은 입력 사유와 확인 상태를 유지해 재시도할 수 있습니다. 등록·해제 후에는 이전 원료 배분 초안을 비웁니다.
- 재고 수량은 보류·해제로 변경되지 않습니다. 배치에서 전파한 산출 LOT 보류만 함께 해제하며, LOT에 독립적으로 등록한 보류는 유지됩니다.

개선조치 확인 체크는 담당자의 화면 확인 절차입니다. 기존 서비스는 사유·담당자를 기록하며 문서의 개선조치·결재 상태를 검증하지 않습니다. 로그인·역할별 해제 권한은 기존 MVP의 담당자 선택 방식과 같습니다.
