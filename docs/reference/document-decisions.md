# 문서·결재(documents) 결정 사항

`backend/apps/documents`·`approvals`·`document_workflow`·`doc_requirements`·`doc_effects`(문서 영역)의 동작 기준을 주제별로 모았습니다. 결정 로그 D-001~D-173(2026-10-09 ~ 10-19)를 정리하고, P14 역할 기반 결재·작성 권한(D-179~D-207), P12 출력(D-208~D-230), CCP 측정행·건조시간·자력 기준(D-237~D-239), P15 생산일지(D-240~D-254)를 반영했습니다.

- **확정**: 합의되어 코드에 들어간 것 · **확정(구현 예정)**: 설계까지 합의, 구현 전 · **가정**: 합의 전 기본값으로 구현(바꿀 곳 표시) · **대기**: 결정이 나야 진행
- 오른쪽 "결정" 칸의 `D-nnn`은 커밋 메시지·개발 기록의 결정 번호입니다. 기호 설명은 [document-dev-process.md](../history/planning/document-dev-process.md), 화면 사용법은 [document-user-guide.md](document-user-guide.md), 생산·수불 연동 명세는 [document-inventory-interface.md](document-inventory-interface.md).

정리 기준: 2026-10-27. 아래는 현재 코드 기준이며, 과거 개발 단계 설명은 [개발 기록](../history/README.md)으로 구분했습니다.

## 1. 구조와 원칙 — 확정

| 항목 | 내용 | 결정 |
|---|---|---|
| 도메인 경계 | 문서(`documents`)·결재(`approvals`)는 서로 import하지 않음. 둘을 묶는 처리(상신·승인·반려·일괄)는 워크플로우(`document_workflow`)가 공개 서비스 함수만 불러 한 트랜잭션으로. 외부(수불·생산)가 부르는 진입점은 작성 요구(`doc_requirements`). 문서 → 외부 호출은 후속 처리(`doc_effects`, 테이블 없음)가 생명주기 신호를 받아 수행 — 다른 앱은 `doc_effects`를 import하지 않음. 경계는 import 검사 테스트로 확인 | D-004, D-079 |
| 문서는 기록 | 문서에는 문서가 판정한 내용만. LOT 상태는 수불만 가지며 문서는 저장·표시·조회하지 않음 | D-073 |
| 상태 변경 | 서비스 함수 안에서 조건부 UPDATE로 검사와 잠금을 함께. 문서 단위 버전(`document.version`)으로 동시 수정 감지 — 쓰기 요청은 `expected_version` 필수, 다르면 409 `VERSION_CONFLICT` | D-026, D-038 |
| 트랜잭션 | SQLite `transaction_mode: IMMEDIATE`(운영·테스트 같음). "트랜잭션 첫 SQL은 쓰기" 규칙(D-067)은 수불 병합 뒤 필요 없음 — 남은 코드는 무해해서 둠 | D-129 |
| 로그인 | MVP 범위 아님. 현재 사용자는 `X-Staff-Id` 헤더, 없는·비활성 직원은 거부. 역할(HACCP팀장·담당자·작성 권한자)은 DB 문서 권한(`admin_settings` 표, 화면 [문서 권한]에서 편집, 저장 즉시 반영 — P16. 전에는 설정 파일 `HACCP_ROLES_FILE`) — 로그인이 없어 막는 장치가 아니라 실수 방지. 사람 표시는 어디서나 "이름(코드)" | D-020, D-128, D-180, D-185, D-257 |
| 오류 응답 | `/api/v1/` 공통 `{code, message, details}`. 도메인 오류 코드 그대로 응답, 어긋난 데이터는 전체 롤백 후 409(자동 복구 없음) | D-038 |
| 시각 | UTC 저장, 응답은 +09:00 | D-021 |
| 개발 도구 | 개발 콘솔(`HACCP_DEV_CONSOLE`)·임시 메뉴(`HACCP_TEMP_ENTRY`)는 따로 켜고 끔. 운영 설정에서 개발 콘솔은 존재하지 않음. 임시 화면은 사이드바 "개발 검증 (임시)"(문서함·결재함 자리는 `HACCP_DOC_MENU` — P10 줄) | D-010, D-011 |

## 2. 문서 — 확정

| 항목 | 내용 | 결정 |
|---|---|---|
| 상태 | `draft` 작성중 / `completed` 작성완료 / `submitted` 결재중 / `approved` 승인 / `rejected` 반려 / `correcting` 정정 중 / `skipped` 작성 안 함 | D-048, D-076, D-106 |
| 작성자·담당자 | 작성자(`created_by`, 자동)와 담당자는 다름. **담당자는 양식에 있음**(문서 권한, 양식마다 여러 명) — 문서마다 고르지 않음(`assignee_id` 컬럼은 남기고 쓰지 않음, API 입력은 400). 작성 요구 문서의 작성자는 화면에 "작성 요구(자동) · 실행 ○○"(저장 값은 호출 인자 그대로). 작업일(`work_date`) = 실제 업무를 한 날, 미래 허용 | D-012, D-016, D-018, D-181, D-182, D-201 |
| 수정 | 바뀐 부분만(PATCH, 섹션 행 단위 추가·변경·삭제). 바뀌지 않은 행의 기록 시각·기록자 보존. 수정 가능 상태 = 작성중·반려·정정 중 | D-014, D-021 |
| 작성 권한 | 작성(새 문서·수정·작성완료·작성 재개·삭제·작성 안 함/되돌리기·파일·정정 취소)과 개선조치 쓰기·삭제 = 그 양식의 **담당자·작성 권한자·HACCP팀장 + 그 문서의 점검자**(R07). 역할 없는 사람은 읽기만. 점검자 지정·바꾸기 = 담당자·팀장(R08). 작성 요구 문서 만들기(입고·생산·주기)는 누구나. | D-201 |
| 저장과 검사 | 저장은 형식만 검사, 필수값·행 개수·양식 규칙은 **작성완료 때** 검사 | D-052 (C-2), D-055 |
| 작성완료 | 작성완료는 잠김, [작성 재개]로 작성중 복귀(작성완료 시각·사람 지움). 상신은 작성완료에서만 | D-054, D-055 |
| 삭제 | 논리 삭제만(`deleted_at`·`deleted_by`). 작성중이고 상신 이력 없을 때만(상신 취소 뒤에도 불가 — D-202). **입고·생산 작성 요구 문서는 삭제 불가**. 주기 문서(D10·D12·D11)는 삭제 가능 — 삭제 때 `record_key`를 비워 그 날짜를 다시 만들 수 있음(규칙 대상 날은 다음 주기 생성 때 다시 만들어짐) | D-017, D-021, D-052, D-149 |
| 목록 | 기본 기간 최근 7일. D03은 입고일마다, D10·D12는 주(월~금)마다 묶음 줄 하나. 주 묶음 줄 정렬 날짜 = 그 주 가장 늦은 작업일 | D-015, D-097, D-108, D-138 |
| 양식 | 양식 버전 내용(`schema_json`)은 만든 뒤 바꾸지 않음. 결재 스냅샷은 양식을 `template_id`·버전으로 참조. CCP-3P 캔디류 양식(v2) 전환 때는 기존 기록까지 변환(`documents/0004`); 시작·종료 기본행 변경은 새 버전(1P·2B v2, 3P v3)을 만들고 **작성중 문서만** 옮김(`documents/0005`). 2B 시간 자동 계산(`documents/0006`)과 1P 자력 8,000G 기준(`documents/0007`)도 각각 새 v3로 작성중 문서만 옮김. 이전 작성완료·결재 기록은 당시 양식으로 보존 | D-032, D-210, D-237, D-238, D-239 |
| CCP 일지 | 측정 행 = 날짜+시각, 날짜 기본값 = 작업일. 1P·2B·3P 측정 영역에 시작·종료 기본행을 문서 생성 때 각각 1개씩 만들고, 구분 변경·행 삭제를 막음. 행 추가는 중간 구분만 허용. 시작이 가장 이르고 종료가 가장 늦어야 작성완료(`phase_order`). 측정값 없는 기본행은 측정 건수에 넣지 않음. 3P 제품 통과 요약은 별도 반복 영역으로 행 추가 가능 | D-051, D-055, D-057, D-237 |
| CCP-2B 행 판정 | 현행 v3: 시작전·작업중·종료전 각 행의 온도는 68~72℃로 판정. 건조시간은 시작전과 종료전 측정일시의 차이로 계산하고 **종료전 행에만** 총 건조시간과 시간 판정(115~125분)을 표시. 두 판정 중 하나라도 부적합이면 개선조치가 필요. 사용자가 계산값을 직접 바꿀 수 없음. 이전 v1·v2 작성완료 문서는 당시 판정을 보존 | D-237, D-238 |
| CCP-1P 자력 기준 | 현행 v3: 자력 **8,000G 이상**과 자석봉 청소 O일 때 행 적합. 안내에는 자석봉 Φ42.7을 표시하고 ‘8개 사용’ 문구는 삭제. 인쇄물 규격 줄은 ‘자력 8,000가우스, Φ42.7’. 작성중 v2 문서만 v3로 옮겨 판정을 다시 계산하며, 완료·결재 기록과 이전 인쇄 문구는 보존 | D-239 |
| 개선조치 | 모든 양식에 있음. 문서 상태와 무관하게 언제든 쓰기·수정(작성 권한 R07, **수정은 지정 확인자도**), 논리 삭제. 조치자는 선택. **확인자는 저장 때 자동**(그 양식 담당자 + HACCP팀장, 10명까지 — 0명이면 저장 + 경고 `checker_warning`), 확인 = 확인자 1명 **또는 HACCP팀장**(확인자 없는 것도). 부적합이 있으면 작성완료에 1건 이상. 상신 당시 개선조치는 결재 요청 상세에 표시. 수불은 `source_document_id`(문서 참조)까지만 | D-049, D-054, D-055, D-063, D-199, D-202, D-205 |

## 3. 결재 — 확정

| 항목 | 내용 | 결정 |
|---|---|---|
| 결재선 | 병렬·칸형, 처리 순서 없음, 전원 승인이면 최종 승인. **문서 권한으로 자동**(고르는 칸 없음) — 양식마다 결재 칸 = 담당자만 / 담당자 + HACCP팀장 / HACCP팀장만, 칸 이름은 양식 설정. 칸 **후보** = 상신 순간의 역할 보유자(회차에 고정, `approval_candidate`), 후보 중 1명이 처리하면 칸 끝(처리자 = `approver_id`). 겸직자는 두 칸을 각각 처리. 상신자도 자기 칸 후보 | D-006, D-031, D-180, D-182, D-183, D-207 |
| 상신 | 그 양식의 **담당자·작성 권한자·HACCP팀장**(R01). 재상신도 그때 설정으로 새 결재선. 칸 후보 0명이면 409 `NO_APPROVAL_LINE`(P16부터 원본이 DB라 설정 파일 형식 오류 409 `ROLE_CONFIG_INVALID`는 없음) | D-182, D-191, D-198 |
| 승인·반려 | 처리 자격 = 그 칸 후보(옛 회차는 지정 결재자). 실패 순서 404 → 403 `NOT_YOUR_SLOT` → 409 `REQUEST_CLOSED` → 409 `ALREADY_DECIDED`. 승인 의견 선택(500자), 반려 사유 필수. 반려 시 남은 대기 칸은 미처리 종료(`skipped`). 끝난 회차 처리는 `REQUEST_CLOSED`("이 회차는 이미 끝났습니다…") | D-031, D-033, D-102 |
| 승인본 | 결재 회차마다 상신 시점 문서 스냅샷 보관(`approval_request.snapshot_json`). 회차는 만든 뒤 바꾸지 않음(예외: CCP-3P v2 변환 때 스냅샷도 v2로 — D-210) | D-007, D-210 |
| 회수·결재선 변경 | 지원하지 않음. 상신 취소는 P10 — **상신자 또는 HACCP팀장**(설정 오류면 팀장 예외 없음) | D-037, D-116, D-182 |
| 일괄 결재 | 묶음 상세·결재함에서 여러 건 일괄 승인·상신, 점검자 일괄 지정. 대상 양식 설정 `HACCP_BATCH_TYPES`(기본 D03·D10·D11·D12), 밖이 섞이면 요청 전체 400 `not_batchable`. 최대 50건, 한 요청 = 트랜잭션 1개 + 문서마다 세이브포인트(4xx는 그 항목만 실패, 응답 항상 200). 일괄 반려 없음. 일괄 상신 결재선은 문서마다 자동(상신할 수 없는 문서는 미리 "상신 불가"), 승인 의견은 모든 칸에 같게 | D-084, D-097, D-098, D-109, D-182 |
| 결재 대상 표시 | 상신 때 문서 대상 요약(`target_summary`, 예: `LOT … · 품명 · 매입처`)을 요청에 저장 | D-088, D-098 |

## 4. 작성 요구 (입고·생산) — 확정

| 항목 | 내용 | 결정 |
|---|---|---|
| 방식 | 사건형 문서는 수불·생산이 부르는 함수로만 생성(양식 선택에서 숨김 `requirement_only`, 작업일 고정). 같은 대상 재호출은 기존 문서 반환(`record_key` 유니크) | D-046, D-052 |
| 호출 규약 | 호출자(입고 등록·생산 시작) 트랜잭션 안에서만 동작. 문서 쪽 오류면 호출자 전체 롤백(필요 양식이 비활성·없음이어도 실패). 작성자 = 호출 인자 `staff_id` | D-050, D-052, D-066 |
| 입고 LOT | LOT마다 D01 시험성적서·D02 원산지 증빙·**D03 육안검사 각 1건**(D03은 LOT 단위 — 하루 일지 `#n`·상한 9는 없어짐) | D-052, D-084 |
| 생산 배치 | 제조 배치 = CCP-1P·2B·3P, 포장 배치 = 없음, 취소 배치(`CANCELLED`)는 만들지 않음 | D-065, D-066 |
| 수불 값 읽기 | 수불·생산 테이블을 직접 읽지 않고 뷰(`v_doc_incoming_lot`·`v_doc_batch`)로만, 사본 보관 없음 | D-066, D-069 |
| 수불용 조회 | `docs_for_lot`·`docs_for_batch`(연결 문서·상태·최신 승인본 기준 판정), 입고 검사 값 `require_for_lot(actor_id, lot_id, inspection=None)`. `get_source_document`·`ledger_approved_until`·`create_incoming_inspection`·`get_incoming_inspection_form`은 미구현 설계명이므로 호출하지 않음. 계약은 [document-inventory-interface.md](document-inventory-interface.md) | D-065, D-080, D-082, D-083 |
| 입고 취소 | 연결 문서 중 하나라도 결재중·승인·정정 중이면 **수불이** 입고 취소를 막음 | D-083 |

## 5. 육안검사와 판정 연동 — 확정

| 항목 | 내용 | 결정 |
|---|---|---|
