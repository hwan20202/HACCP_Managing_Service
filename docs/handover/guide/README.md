## 업무 흐름 한눈에

[주요 업무 사용 안내](../user-guide.md)의 다섯 단계를 한 줄씩 줄이고, 자세한 설명이 있는 장으로 이었습니다.

| 단계 | 하는 일 | 자세히 |
|---|---|---|
| 0. 시작 | 화면 오른쪽 위 **현재 사용자**(문서)·**담당자**(수불)를 고릅니다. 로그인이 없고, 고른 사람이 처리자로 남습니다. 문서는 역할에 따라 작성·결재 가능 여부가 달라집니다 | [문서 2장](document-guide.md#2-문서-작성수정작성완료) · [역할](document-guide.md#91-사람과-역할) |
| 1. 입고 | 수불대장 **[입고 등록]**(여러 건은 **[입고 일괄 업로드]**) → LOT이 생기고 입고 서류 3종(D01·D02·D03)이 함께 만들어집니다 | [수불 2장](inventory-guide.md#2-입고) · [D01~D03](document-guide.md#81-시험성적서-d01) |
| 2. 재고 확인 | 기간 입출고는 **수불 내역**, 지금 남은 양은 **현재고**, 과거 시점 잔량은 **품목 상세** | [수불 3장](inventory-guide.md#3-재고수불-보기) |
| 3. 생산 | BOM 확인 → 계획 등록(재고 차감 없음) → 생산 시작(CCP 일지·생산일지 생성) → 실제 원료 투입(재고 차감) → 산출 → 완료 | [수불 5장](inventory-guide.md#5-bom배합표) · [수불 6장](inventory-guide.md#6-생산) · [생산일지](document-guide.md#87-생산일지-prod-log) |
| 4. 보류·해제 | 문제가 생기면 배치 **보류 관리**에서 보류, 개선조치 확인 뒤 해제. 문서 결재와 따로 처리 | [수불 7장](inventory-guide.md#7-보류와-해제) · [개선조치](document-guide.md#4-ccp개선조치) |
| 5. 문서 | **문서함 › 작성 필요**에서 열기 → 쓰고 저장 → 작성완료 → 결재 올리기 → 결재함에서 승인·반려 → 출력. 생산일지는 결재 없이 작성완료로 끝 | [문서 2장](document-guide.md#2-문서-작성수정작성완료) · [3장](document-guide.md#3-결재) · [6장](document-guide.md#6-출력) |

**단계마다 자주 헷갈리는 것**

- 계획·시작만으로는 재고가 줄지 않습니다. 실제 투입을 등록할 때 줄어듭니다.
- 같은 배치에서 나눠 등록한 산출은 같은 LOT에 더해집니다.
- 현재고는 지금 값입니다. 과거 기간을 골라도 과거 재고로 바뀌지 않습니다.
- 입고 판정과 결재 승인은 다릅니다. 결재를 승인·반려해도 LOT 판정은 바뀌지 않습니다.
- 승인된 문서는 정정으로 고치고, 새 승인 전까지 이전 승인본이 유효합니다.
- 수불대장은 시스템 결재 없이 출력해서 따로 결재합니다.

## 읽는 법

- 기능마다 같은 틀입니다: 언제 쓰나 → 누가 할 수 있나 → 미리 필요한 것 → 사용 순서 → 이럴 때 막혀요 → 하고 나면 바뀌는 것 → 알아둘 점.
- 기능 끝의 작은 글씨 줄에 기능 ID(`F-INV-01`·`F-WF-01` 등)와 API·표 링크가 있습니다.
- **[테스트 버전]** 표시는 지금 버전에만 해당하는 내용, **관리자 참고** 상자는 설치·운영 담당자가 보는 내용입니다.
- 사용하기 전에 전달받은 버전이 실제 서버에 반영됐는지, 보고 있는 자료가 테스트 자료인지 실제 업무 자료인지 확인합니다.
- 화면과 문서가 다르면 화면(현재 코드)이 기준입니다. 다른 점은 [남은 작업](../remaining-work.md)에 알려 주세요.
- 화면이 없거나 버튼을 쓸 수 없으면 현재 사용자·문서 상태·역할 설정·메뉴 노출을 설치 담당자와 확인합니다. 문의할 때는 화면 이름, 시각, 하려던 일, 오류 문구를 함께 남깁니다.
