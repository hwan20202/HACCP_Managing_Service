## 읽는 법

- 기능마다 같은 틀입니다: 언제 쓰나 → 누가 할 수 있나 → 미리 필요한 것 → 사용 순서 → 이럴 때 막혀요 → 하고 나면 바뀌는 것 → 알아둘 점.
- **누가 할 수 있나**: 수불 쪽은 문서 쪽 같은 역할(담당자·HACCP팀장) 검사가 **없습니다**. 화면에서 고른 **담당자**(사용 중인 직원)가 기록에 남을 뿐입니다.
- **수량**은 품목의 **기준단위**(kg·g·개 …)로 저장합니다. 화면에서 kg/g를 바꿔 입력해도 기준단위로 바꿔 저장합니다(500g → 0.5kg).
- **[테스트 버전]** 표시는 지금 버전에만 해당하는 내용, **관리자 참고** 상자는 명령·설정처럼 설치·운영 담당자가 보는 내용입니다.
- 화면에 없는 기능(재고조정·반품·폐기·정정·기초재고 이관)은 **화면 없음 — 관리자가 API로**라고 적었습니다.

## 1. 처음 시작하기 — 기준정보·기초재고

품목·공급처·직원(기준정보)과 운영 시작 시점의 재고(기초재고)를 넣어야 입고·생산을 할 수 있습니다. **화면은 없고** 관리자가 명령으로 넣습니다. 별도 전달하는 v8 초기 DB를 사용하는 경우에는 품목·공급처·BOM이 이미 등록돼 있으므로 이 자료를 다시 등록하지 않고 실제 직원·역할을 설정합니다. 자세한 범위와 배치 절차는 [설치 안내 — v8 기준정보 초기 DB](../installation.md#별도-전달하는-v8-기준정보-초기-db)를 봅니다.

| | |
|---|---|
| **언제 쓰나** | 설치 직후, 운영 시작 전 한 번. 품목이 새로 생길 때 |
| **누가 할 수 있나** | 설치·운영 담당자(관리자) |
| **미리 필요한 것** | 전달 초기 DB 사용 여부 확인, 실제 직원·역할 정보, 운영 시작일의 LOT별 재고. 빈 DB에서 시작한다면 품목·공급처 목록(CSV)과 BOM도 필요 |

### 순서

1. 빈 DB에서 시작한다면 직원·공급처·품목을 CSV로 정리합니다(헤더 양식 `backend/apps/inventory/seed/templates/`). 품목은 품목코드·구분(원료·포장재·반제품·완제품)·품명·기준단위가 필수이고, LOT 약어·표준 중량·소비기한(개월 또는 일수 중 하나)·원산지·식품유형·품목제조보고번호·최소 재고·재고 관리 여부를 함께 넣습니다. 전달 초기 DB를 쓴다면 실제 직원 CSV만 준비하고 기존 품목·공급처 목록을 확인합니다.
2. 관리자가 기준정보 가져오기 명령을 먼저 미리 보기(`--dry-run`)로 돌려 오류를 확인한 뒤 실제로 넣습니다. 같은 코드의 기존 정보는 갱신되므로 전달 초기 DB에 전체 CSV를 다시 적재하지 않습니다. 명령은 [설치 안내 — 최초 업무 설정](../installation.md#최초-업무-설정)에 있습니다.
3. 빈 DB에서 시작한다면 BOM(배합표)을 등록합니다([5장](#5-bom배합표)). CSV 명령은 BOM을 가져오지 않습니다. 전달 초기 DB의 BOM은 등록 목록과 최종본 여부를 확인합니다.
4. 운영 시작일의 재고를 LOT별로 **기초재고 이관**으로 넣습니다(화면 없음, 필요하면 개발자가 이관 절차를 준비).
5. 수불대장 **현재고**에서 넣은 값을 확인합니다.

### 알아둘 점

- 정제수 같은 공정용수는 **재고 관리 안 함**(`is_stock_managed = 0`)으로 넣습니다. LOT·재고가 생기지 않고, 사용량은 생산일지에 직접 적습니다.
- LOT이 생긴 품목은 구분과 재고 관리 여부를 바꿀 수 없습니다(새 품목으로 등록).
- 기초재고로 넣은 LOT에는 입고 서류(D01~D03)가 생기지 않습니다.

> [!NOTE]
> **관리자 참고**
> - 기준정보: `backend/manage.py seed_master --staff … --suppliers … --items … --dry-run` → 확인 뒤 `--dry-run` 없이([설치 안내](../installation.md#최초-업무-설정), Windows 명령 포함). `seed_master --sample`·`seed_dev_*`·`seed_qa_*`는 테스트 자료용
> - 기초재고: API `POST /api/v1/inventory/movements/opening-balance/`([API](../api/inventory.md#inv-opening)). 반제품·완제품은 기존 LOT 번호가 필요합니다. 운영 이관 절차는 확인 필요
> - 정합성 점검: `python backend/manage.py check_inventory`(현재고와 수불 합계가 다르면 오류로 끝남)

### 2.1 입고 등록

원료·포장재·반제품이 들어온 것을 기록합니다. **입고 1건 = LOT 1개**이고, 저장하면 수불·재고와 입고 서류 3종(시험성적서·원산지 증빙·육안검사일지)이 함께 만들어집니다.

| | |
|---|---|
| **언제 쓰나** | 원료·포장재·구매 반제품을 받았을 때 |
| **누가 할 수 있나** | 누구나(화면에서 고른 **담당자**가 처리자로 남음) |
| **미리 필요한 것** | 품목·공급처·담당자가 기준정보에 있고 사용 중일 것. 재고 관리 품목일 것 |

#### 사용 순서

1. 왼쪽 메뉴 **원료 수불대장**(포장재는 **부자재 수불대장**, 반제품은 **완제품 수불대장**)에서 **[입고 등록]**을 누릅니다.
2. 품목 유형을 고르고 품목명·코드로 찾아 품목을 고릅니다.
3. 공급처·담당자·입고일·입고량(입력 단위 선택)을 넣습니다. EA(참고 개수)는 선택입니다.
4. **소비기한 유무**를 고릅니다. "있음"이면 소비기한 날짜가 필수입니다.
5. **입고 검사 판정**을 고릅니다: 적합(기본) / 미판정(문서함에서 육안검사 작성).
6. **[입고 저장]**을 누릅니다.

#### 이럴 때 막혀요

| 화면에 보이는 것 | 이유 | 이렇게 하세요 |
|---|---|---|
| "입고일이 오늘 이후일 수 없습니다." | 미래 날짜 | 실제 입고일로 고칩니다. |
| "소비기한이 제조일보다 빠를 수 없습니다." | 날짜 순서 | 날짜를 확인합니다. |
| "수량은 0보다 커야 합니다." · "수량을 확인하세요 … (소수점 6자리까지)" | 수량 형식 | 기준단위로 소수 6자리 이내 양수를 넣습니다. |
| "입고 대상 품목이 아닙니다" | 완제품 등 입고하지 않는 구분 | 품목 구분을 확인합니다. |
| "사용 중지된 품목(공급처·담당자)입니다" | 기준정보가 사용 중지 | 관리자에게 알립니다. |
| "입고 판정과 육안검사 최종판정이 다릅니다." | 판정 값이 서로 다름 | 판정을 하나로 맞춥니다. |
| 원료인데 소비기한 유무 오류 | 원료 LOT은 소비기한 유무(있음·없음)가 정해져야 LOT 번호를 만들 수 있음 | "있음" 또는 "없음"을 고릅니다. |

#### 하고 나면 바뀌는 것

- LOT이 만들어집니다. 원료 LOT 번호 = 약어 + 소비기한(없으면 입고일). 같은 기준일이 또 나오면 뒤에 `-2`, `-3`이 붙습니다.
- 입고 수불 기록이 생기고 현재고가 늘어납니다.
- **같은 저장 안에서** 그 LOT의 D01·D02·D03이 만들어집니다. 적합이면 D03을 검사값으로 채워 바로 작성완료를 시도하고(실패하면 작성중으로 남고 입고는 진행), 미판정이면 D03이 작성중으로 남아 육안검사일지를 써야 합니다 → [문서·결재 기능 안내 8.3](document-guide.md#83-원료부자재-육안검사일지-d03)
- LOT 상태: 적합 → **사용 가능**, 부적합 → **부적합**, 미판정 → **판정 대기**(D03 작성완료 때 정해짐).

#### 알아둘 점

- 기준단위가 kg인 원료를 500g 입고하면 0.5kg으로 저장됩니다.
- 기본으로 채워진 입고일·적합 판정이 실제와 맞는지 꼭 확인합니다.
- 결재 승인·반려는 LOT 판정을 바꾸지 않습니다. 판정을 바꾸려면 육안검사일지를 고쳐 다시 작성완료합니다.
- 서류 쪽 처리가 실패하면 입고 전체가 저장되지 않습니다.

### 2.2 입고 일괄 업로드

입고 여러 건(1~500건)을 CSV 파일로 한 번에 넣습니다.

| | |
|---|---|
| **언제 쓰나** | 같은 날 입고가 많을 때, 지난 입고를 옮길 때 |
| **누가 할 수 있나** | 누구나(고른 담당자가 처리자) |
| **미리 필요한 것** | 품목코드·공급처코드가 기준정보에 있을 것 |

#### 사용 순서

1. 수불대장에서 **[입고 일괄 업로드]** → 담당자를 고릅니다.
2. **[CSV 양식 다운로드]**로 양식을 받아 엑셀에서 채우고 **CSV UTF-8**로 저장합니다.
   - 필수: `item_code`·`supplier_code`·`received_date`·`quantity`·`expiration_status`(KNOWN/NONE)·`expiration_date`(KNOWN일 때)
   - 선택: `unit`(비우면 기준단위)·`judgment`(PASS/FAIL, 비우면 적합)·`ea_count`·`supplier_lot_number`. 날짜는 YYYY-MM-DD
3. 파일을 고르고 **[검증·미리보기]**로 줄마다 오류를 확인합니다.
4. **[확인한 입고 일괄 등록]**을 누릅니다.

#### 이럴 때 막혀요

| 화면에 보이는 것 | 이유 | 이렇게 하세요 |
|---|---|---|
| "입고 내역은 한 번에 1~500건 업로드하세요." | 건수 | 파일을 나눕니다. |
| "n행: 등록된 품목코드·공급처코드를 입력하세요." | 기준정보에 없는 코드 | 코드를 고치거나 기준정보를 먼저 넣습니다. |
| "n행: …" | 그 줄의 입고 오류(2.1 표와 같음) | 그 줄을 고쳐 다시 미리 봅니다. |

#### 하고 나면 바뀌는 것

- 줄마다 2.1과 같습니다. **오류가 한 줄이라도 있으면 전체를 저장하지 않습니다.**

### 2.3 입고 취소

잘못 넣은 입고를 취소합니다. 입고·수불 이력은 남고, 남은 입고 수량이 빠지며, 입고 서류 3종이 함께 삭제됩니다.

| | |
|---|---|
| **언제 쓰나** | 입고를 잘못 넣었고 아직 쓰지 않았을 때 |
| **누가 할 수 있나** | 누구나(고른 담당자가 처리자) |
| **미리 필요한 것** | 그 LOT을 생산에 쓰거나 조정하지 않았을 것. 입고 서류가 결재 중·승인·정정 중이 아닐 것 |

#### 사용 순서

1. 수불대장에서 **[입고 취소]** → 취소할 입고를 고릅니다(또는 입고 상세의 **[입고 취소]**).
2. 담당자와 **취소 사유**를 넣고 **[입고 취소 확인]**을 누릅니다.

#### 이럴 때 막혀요

| 화면에 보이는 것 | 이유 | 이렇게 하세요 |
|---|---|---|
| "이미 사용·조정된 LOT은 입고 취소할 수 없습니다." | 생산 투입·조정 기록이 있음 | 취소하지 않고 수불 정정으로 고칩니다(4장, 관리자). |
| "결재 중이거나 결재된 문서가 있는 LOT은 입고 취소할 수 없습니다: …" | D01~D03 중 결재 진행·승인·정정 중인 문서가 있음 | 문서 쪽에서 상신 취소 등으로 먼저 정리합니다. |
| "취소 사유를 입력하세요." | 사유 없음 | 사유를 넣습니다. |

#### 하고 나면 바뀌는 것

- 입고가 **취소됨**으로 바뀌고 남은 입고 수량만큼 정정 기록이 생겨 현재고가 줄어듭니다.
- 그 LOT의 D01·D02·D03이 삭제 처리되어 문서함·묶음에서 사라집니다(기록은 남음).

<sub>`F-INV-03` · 현재 기준 2026-10-27 · API [`POST receipts/{id}/cancel/`](../api/inventory.md#inv-receipts-cancel) · 결정 D-178</sub>

메뉴는 **원료 수불대장**(원료) · **부자재 수불대장**(포장재) · **완제품 수불대장**(반제품·완제품)으로 나뉩니다.

| | |

| **누가 할 수 있나** | 누구나 |

### 3.3 품목 상세

**사용 순서**: 품목명 클릭 → LOT별 기간 요약(이월·기간 입고 합계·기간 출고 합계·조회 종료일 잔량) · LOT 수불 이력 · **[입고 연결 문서]**.

- 지난달 말 같은 **과거 시점 잔량**은 여기 "조회 종료일 잔량"으로 봅니다.
- 상세창에서 인쇄하면 그 상세창의 조회 조건을 따릅니다.

## 5. BOM(배합표)

제품(반제품)의 기준 배합표입니다. 생산 계획의 원료 소요량과 생산일지 원료칭량의 기준이 됩니다.

| | |
|---|---|
| **언제 쓰나** | 새 반제품을 만들 때, 배합이 바뀔 때 |
| **누가 할 수 있나** | 누구나(고른 담당자가 기록) |
| **미리 필요한 것** | 만드는 품목과 원료가 기준정보에 있을 것 |

#### 사용 순서

1. **생산지시 · 실적** → **[BOM 관리]** → **[새 BOM 등록]**. 있는 BOM을 고칠 때는 목록의 **[조회·수정]**, 있는 BOM을 바탕으로 새 버전을 만들 때는 **[새 버전]**(복사).
2. 만드는 품목(사용 중인 반제품)·적용 시작일·기준 생산량과 단위를 넣습니다.
3. **[원료 추가]**로 원료와 기준 생산량당 소요량을 넣고, 필요하면 원료마다 **대체 원료**를 넣습니다.
4. **[저장]**. 생산에 쓰인 BOM이면 버튼이 **[새 버전 저장]**으로 바뀝니다.

#### 이럴 때 막혀요

| 화면에 보이는 것 | 이유 | 이렇게 하세요 |
|---|---|---|
| "구성 원료를 1~200개 입력하세요." | 원료 수 | 원료를 넣습니다. |
| "구성 품목이 없거나 중복되거나 생산 품목과 같습니다." | 같은 원료 두 번 · 자기 품목 | 줄을 정리합니다. |
| "대체 원료가 중복되거나 생산·기본 원료와 같습니다." · "대체 원료는 기본 원료와 환산 가능한 단위여야 합니다." | 대체 원료 조건 | 다른 원료를 고르거나 단위를 맞춥니다. |
| "품목 기준단위 또는 kg/g 단위를 사용하세요." | 단위 | 기준단위나 kg/g로 넣습니다. |
| "BOM 저장이 충돌했습니다. 새로고침 후 다시 시도하세요." | 그사이 다른 사람이 저장 | 새로 고친 뒤 다시 합니다. |

#### 하고 나면 바뀌는 것

- 새 BOM 또는 새 버전(복사)이 생깁니다. **생산에 쓰인 버전은 고칠 수 없고** 새 버전으로 저장되어, 이미 만든 생산 기록의 기준이 보존됩니다.
- 생산에 쓰이지 않은 BOM은 **[삭제]**, 쓰인 BOM은 **[사용 중지]**만 할 수 있습니다.

<sub>`F-PRD-01` · 현재 기준 2026-10-27 · API [`boms/`](../api/inventory.md#inv-boms) · 표 [`boms`](../erd/inventory.md#boms)</sub>

## 6. 생산

흐름: **계획 등록 → 생산 시작 → 원료 투입 → 산출 등록 → 완료**(또는 취소). 메뉴 **생산지시 · 실적**에서 합니다. 화면 위에서 **담당자**를 먼저 고릅니다.

| 하고 싶은 일 | 기능 |
|---|---|
| [생산 계획을 등록하기](#61-생산-계획-등록) | `F-PRD-02` |
| [생산을 시작하기](#62-생산-시작) | `F-PRD-03` |
| [실제 사용한 원료를 투입하기](#63-원료-투입) | `F-PRD-04` |
| [만든 양을 등록하기](#64-산출-등록) | `F-PRD-05` |
| [생산을 완료하기](#65-완료) | `F-PRD-06` |
| [생산을 취소하기](#66-취소) | `F-PRD-07` |

### 6.1 생산 계획 등록

| | |
|---|---|
| **언제 쓰나** | 만들 반제품과 양이 정해졌을 때(사후 입력도 가능) |
| **미리 필요한 것** | 그 반제품의 BOM |

**사용 순서**: **[+ 새 생산 계획]** → 품목·계획 수량·계획일 → 필요한 원료와 가용재고를 미리 확인 → **[계획 등록]**.

- **계획 등록 때는 재고를 예약·차감하지 않습니다.** 생산 시작 뒤 실제 사용량을 확인해 투입할 때 차감합니다.
- 제조 배치만 만들 수 있습니다(포장 배치는 이번 범위 밖).
- 막힘: "품목과 0보다 큰 계획 수량을 입력하세요." · "이 품목의 BOM이 아닙니다." · "공정 구분은 MANUFACTURE(제조)만 가능합니다."

### 6.2 생산 시작

**사용 순서**: 배치 상세 → **제조일(생산 시작일)** 확인 → **[생산 시작]**.

- 제조일로 **산출 LOT 번호와 소비기한**이 정해집니다(소비기한 = 품목에 등록된 기간).
- **같은 처리 안에서 CCP-1P·2B·3P 일지**가 만들어지고, 생산일지 양식이 설치돼 있으면 **생산일지**도 만들어집니다 → 배치 상세 **[연결 문서]** 탭, [문서·결재 기능 안내 8장](document-guide.md#ccp-모니터링일지-공통)
- 막힘: "계획 상태의 배치만 시작할 수 있습니다" · "보류 중인 배치는 시작할 수 없습니다." · "제조일이 오늘 이후일 수 없습니다." · "시작된 배치인데 연결된 CCP 일지가 없습니다. 문서 담당자에게 확인하세요."

### 6.3 원료 투입

**사용 순서**: **생산 진행 · 실적** 탭 BOM 표에서 원료의 **[투입량 확인]** → 이번 실제 투입량 → LOT 자동 배분(소비기한 빠른 순) 확인·수정 → 투입. 남은 원료를 한 번에 넣을 때는 **[남은 원료 일괄 투입]** → **[배분 확인 · 일괄 투입]** → **[확인한 원료 일괄 등록]**.

- **자동 추천은 실제 사용량을 대신하지 않습니다.** 실제로 쓴 LOT과 양으로 고쳐서 등록합니다. 등록하면 재고가 차감됩니다.
- BOM 원료 또는 등록된 대체 원료만 넣을 수 있습니다.
- 막힘: "생산을 시작한 뒤 투입할 수 있습니다." · "선택 LOT 합계가 이번 투입 총량과 다릅니다." · "해당 BOM의 원료 또는 등록된 대체 원료만 투입할 수 있습니다." · "같은 LOT은 한 번만 선택하세요." · 재고 부족·사용 불가 LOT · "확인한 BOM 원료와 수량을 다시 조회하세요."(그사이 바뀜)

### 6.4 산출 등록

**사용 순서**: **산출 (벌크)** 영역에서 생산량(EA 참고 개수 선택) → **[산출 등록]**.

- 한 배치의 산출 LOT은 **하나**입니다. 0.4kg과 0.6kg을 나눠 등록하면 같은 LOT에 1kg이 쌓입니다.
- EA는 참고 개수일 뿐 무게와 환산하지 않고, 일부만 넣은 개수를 전체 재고 개수로 보지 않습니다.
- 막힘: "생산을 시작한 뒤 산출할 수 있습니다." · "산출일이 제조일(생산 시작일)보다 빠를 수 없습니다."

### 6.5 완료

**사용 순서**: **[완료]**. 완료하면 투입·산출을 더 추가할 수 없습니다.

- 막힘: "필수 원료 투입 누락: …" · "산출이 없는 배치는 완료할 수 없습니다. 산출을 먼저 등록하세요." · "보류 중인 배치는 완료할 수 없습니다." · "BOM 구성 없이 생산을 완료할 수 없습니다."
- 완료한 뒤 고칠 것은 수불 정정으로 합니다(4장).

### 6.6 취소

**사용 순서**: **[배치 취소]** → 취소 사유.

- **투입·산출이 있으면 먼저 정정해야** 합니다. 완료된 배치는 취소할 수 없습니다("완료된 배치는 취소할 수 없습니다. 투입·산출을 정정하세요.").
- 배치는 지우지 않고 취소로 남습니다.
- 취소 뒤 연결된 CCP 일지·생산일지 처리는 아직 정해지지 않았습니다(생산일지는 읽기 전용이 됨) — [남은 작업](../remaining-work.md).

### 생산 화면에서 함께 보는 것

- **[연결 문서]** 탭: CCP 일지마다 상태·최근 측정·이탈·개선조치, 생산일지 한 줄. **[CCP 대시보드에서 보기]**
- **[재고 · 수불 이력]** 탭: 투입·산출로 움직인 LOT의 현재고와 수불 기록
- 목록의 **[인쇄 / PDF]**(여러 배치 선택) · 상세의 **[이 배치 인쇄 / PDF]**

## 7. 보류와 해제

진행 중인 생산에 문제가 생기면 배치를 **보류**해 그 뒤 작업을 막고, 개선조치를 확인한 뒤 **해제**합니다.

| | |
|---|---|
| **언제 쓰나** | 생산 중 이상이 생겼을 때(예: CCP 이탈) |
| **누가 할 수 있나** | 누구나(고른 담당자가 처리자) |
| **미리 필요한 것** | 진행 중인 배치 |

#### 사용 순서

1. 배치 상세 **보류 관리** → **[보류 등록]** → 보류 사유 → **[보류 등록]**.
2. 해제할 때: **[개선조치 확인 · 해제]** → 개선조치 내용 및 해제 사유 → "개선조치가 완료되었고 보류를 해제해도 되는지 확인했습니다." 체크 → **[보류 해제]**.

#### 하고 나면 바뀌는 것

- 보류 중에는 **생산 시작·원료 투입·산출 등록·완료**가 막히고(화면과 서버 모두), 그 배치의 **산출 LOT에도 보류가 걸립니다**. 재고 수량은 바뀌지 않습니다.
- 해제하면 이 배치에서 전파된 산출 LOT 보류도 함께 풀립니다. 다른 사유로 LOT에 따로 건 보류는 남습니다.
- 보류·해제 이력이 배치 상세에 남습니다.

#### 알아둘 점

- **문서 결재와 따로** 처리합니다. CCP 이탈을 적거나 문서가 승인돼도 보류가 자동으로 걸리거나 풀리지 않습니다 — [개요](../overview.md#생산-보류와-문서-결재는-각각-처리합니다)
- 화면에서 거는 보류는 수동(`MANUAL`) 배치 보류이고, 해제 처분은 "해제(정상 사용)"입니다. LOT 단위 보류, 근거 문서가 필요한 원인(CCP·입고 검사·완제품 실험), 재작업·반품·폐기 처분은 **화면 없음 — 관리자가 API로**([API](../api/inventory.md#inv-holds-post)).

## 8. 품목 삭제

잘못 만들었거나 쓰지 않은 품목을 지웁니다. **입고만 있고 생산·BOM·보류·결재에 쓰이지 않은 품목만** 지울 수 있습니다.

**사용 순서**: 수불대장 **[품목 삭제]** → 담당자·지울 품목(1~500개) → 미리 보기에서 지울 수 있는 품목과 막힌 이유 확인 → 확정.

| 막힌 이유 | 뜻 |
|---|---|
| "생산·BOM·보류 또는 다른 재고 업무에 사용된 품목입니다." | 입고 말고 다른 기록이 있음 |
| "결재·정정 등에 사용된 문서가 있어 삭제할 수 없습니다." · "첨부파일이 등록된 문서가 있어 삭제할 수 없습니다." · "다른 업무와 공유하는 문서가 있어 삭제할 수 없습니다." | 입고 서류가 이미 쓰임 |

- 지우면 그 품목의 입고·수불 기록과 입고 서류도 함께 지워집니다(되돌릴 수 없음). 미리 보기를 꼭 확인합니다.

## 9. 용어

| 말 | 뜻 |
|---|---|
| **기준단위** | 품목마다 정한 수량 단위(kg·g·개·장). 모든 수량이 이 단위로 저장됨 |
| **LOT** | 같은 입고 한 건, 또는 같은 배치에서 나온 물량. 번호는 품목 안에서만 유일 |
| **LOT 상태** | 품질 판정만: 판정 대기 · 사용 가능(적합) · 부적합. 재고가 남았는지와는 별개 |
| **소비기한 유무** | 있음(날짜 필수) · 없음(확인함) · 미확인(옮겨 온 LOT 등) |
| **재고 관리 안 함** | 정제수 같은 공정용수. LOT·재고가 없고 사용량은 생산일지에 적음 |
| **수불** | 재고의 들어옴·나감 기록. 고치지 않고 정정 기록을 더함 |
| **현재고 / 과거 잔량** | 현재고는 지금 값, 과거 시점 잔량은 품목 상세의 "조회 종료일 잔량" |
| **BOM** | 기준 배합표. 생산에 쓰인 버전은 고치지 않고 새 버전을 만듦 |
| **대체 원료** | BOM 원료 대신 넣을 수 있게 등록한 원료 |
| **제조 배치** | 생산 한 건(계획·진행·완료·취소) |
| **제조일(생산 시작일)** | 산출 LOT 번호·소비기한의 기준일 |
| **보류 / 전파 보류** | 사용을 막는 표시. 배치 보류는 산출 LOT에 전파됨 |
| **EA** | 참고 개수. 무게와 환산하지 않음 |

사람과 역할(담당자·HACCP팀장 등)은 [문서·결재 기능 안내 9장](document-guide.md#9-용어집)을 봅니다. 수불 쪽은 역할 검사가 없습니다.
