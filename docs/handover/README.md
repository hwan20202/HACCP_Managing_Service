2026-10-27 정리 · 전달 기준: 프로젝트 종료 시 최종 변경을 병합한 `main`

## 함께 전달할 것

- 소스: 최종 변경을 병합한 `main`을 바이오닷 계정·조직으로 fork하여 인수하는 방식을 기본으로 고려. fork 가능 여부와 인수 계정은 당사자 간 확인하며 커밋 이력은 별도 자료로 전달하지 않음
- 초기 DB: v8 기준정보를 등록한 `biodot-master-v8-20261027.zip` 별도 전달. 원료·반제품·포장재 273품목과 반제품 BOM 85개·322행 포함. 실제 입고·생산지시·투입·산출·기초재고는 없음
- 기준 자료: 제공받은 `바이오닷_BOM_정리본_v8.xlsx` 원본과 등록 자료·확인사항을 초기 DB 전달 파일에 포함. 필요한 기준서 원본은 별도 전달
- QA 자료: 현재 남아 있는 DB는 QA용. 참고·재현이 필요하면 별도 보관하며, 실제 운영 시작 재고나 업무 이력으로 사용하지 않음
- 설치·운영 설정: 바이오닷이 지정한 담당자가 실제 환경 설정, 역할, 접속 주소, 서비스·인증서 및 백업을 준비. 기존 QA 설정을 참고로 넘길 경우 비밀값과 접속정보는 제한된 경로로 별도 전달
- 운영 담당: 설치·복구 담당자, 보관·백업 위치, 문의 방법은 바이오닷에서 지정

소스 저장소에는 대부분의 실제 업무 자료가 들어 있지 않습니다. [자료 보관 안내](../../data/README.md)를 확인하고, 어떤 자료를 넘겼는지 목록을 남깁니다.

## 초기 DB 준비와 실제 업무 시작

1. 개발팀이 제공받은 v8으로 별도 초기 DB에 기준정보를 등록했습니다. QA DB는 보존했고 테스트 거래를 복사하지 않았습니다.
2. 기준정보가 입력된 초기 DB와 BOM 원본·등록 자료 목록을 소스와 함께 전달합니다. DB 준비는 배포 환경 결정과 별도로 진행합니다.
3. 바이오닷이 배포 방식·설치 환경·설치 및 운영 담당자를 정합니다. 담당자는 전달받은 초기 DB를 배치하고 소스와 DB 구조의 호환성을 확인합니다. 추가 마이그레이션이 필요하면 백업 후 적용하고, 실제 직원·문서 권한(관리 설정 화면)·접속·백업 설정을 준비합니다.
4. 바이오닷이 운영 시작일과 기초재고 기준일을 정하고, 해당 기준일의 실제 재고를 등록합니다. 생산지시·입고·투입·산출은 실제 업무로 기록합니다.
5. 입고·생산·문서·출력을 별도 테스트 환경에서 확인한 뒤 실제 업무를 시작합니다. 설치 절차는 [설치 안내](installation.md)를 따릅니다.

## 확인 상태

v8 수령과 초기 DB 생성·기준정보 적재·정합성 검증은 완료했습니다. 원본 공란은 전달 파일과 설치 안내에 확인사항으로 남겼습니다. 현업과 합의된 원료 LOT 채번 기준은 소비기한 있음이면 품목 약어+소비기한, 없음으로 확인되면 품목 약어+입고일입니다. 실제 운영 장비에서의 설치·재시작·접속·복구 검증과 최종 사용 승인도 이후 확인합니다. 결과는 [남은 작업](remaining-work.md)에 기록합니다.

참고 명세와 개발 중 기록은 [전체 문서 목차](../README.md)에서 구분해 볼 수 있습니다.
