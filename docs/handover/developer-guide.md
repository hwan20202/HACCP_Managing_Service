# HACCP 프로젝트 기술 인수인계 자료

작성 기준: 2026-10-27 · 전달 예정: 2026-10-28 · 설치는 인수자가 지정한 담당자가 수행 · 외주 개발자 및 후속 개발·운영 담당자 참고용

이사님께서는 [프로그램 전달 안내](overview.md)를 먼저 읽으시면 됩니다. 이 문서는 필요할 때 개발자에게 전달할 상세 근거와 기술 확인사항을 모았습니다.

운영 인수 기준: 개발팀이 제공받은 v8과 main으로 QA DB와 별도의 새 DB를 만들어 273품목·BOM 85개/322행을 등록·검증했습니다. 원본 공란·LOT 규칙과 소스의 차이는 설치 안내와 전달 파일에 남겼습니다. 바이오닷이 배포 방식·설치 환경을 정하면 설치 담당자가 초기 DB를 배치하고 소스 호환성·필요한 추가 마이그레이션을 확인합니다. 운영 시작일·기초재고 기준일은 바이오닷이 정합니다. 실제 업무·QA 거래는 초기 DB에 넣지 않습니다.

저장소의 결정사항·변경 기록을 바탕으로 정리한 인수인계 초안입니다. 코드 기준은 현재 체크아웃 `fix/inventory-receipt-guidance`, 커밋 `8d931a3`입니다. **구현·검증 기록이 있다는 것과 전달받는 서버에서 사용할 수 있다는 것은 별도입니다.** 이번 정리에서는 원격 서버·GitHub의 현재 상태를 조회하거나 전체 기능 검사를 다시 실행하지 않았습니다.

## 1. 전달할 핵심 내용

입고 → 원료 투입 → 제조 벌크 산출 → 재고·수불 조회 흐름과, 관련 HACCP 문서 작성·결재·출력을 구현해 왔습니다. 생산에서는 BOM 기준량과 실제 투입량을 구분하고 원료 LOT와 산출 LOT의 연결을 남깁니다. 문서에서는 작성완료·상신·승인·정정 이력을 관리합니다.

이번 MVP의 범위는 **입고부터 제조 완료된 벌크 산출까지**입니다. 판매용 소분·포장·출하·고객 반품은 다음 범위로 남겼습니다. 실제 업무 전환에는 전달 서버의 버전·DB 반영 상태, 실제 기준정보·기초재고, 담당 역할과 운영 절차 확인이 필요합니다.

| 제조일·소비기한 | 제조일은 생산 시작일. 산출 소비기한 기본값은 제조일+품목 소비기한 기간−1일 | [확정·가정 구분](../reference/inventory-decisions.md) |

| 투입·재고 | 계획·시작은 재고 예약이 아님. 실제 투입 때 차감. 투입은 사용 가능 판정·보류·소비기한·잔량 조건을 확인 | [사용 안내](../history/changes/pm-user-qa-guide-20261019.md), [재고 사용 가능 정책](../reference/inventory-decisions.md#1016-재고-사용-가능-표시추천-순서-보완) |

| EA 참고 개수 | 선택 입력이며 무게와 자동 환산하지 않음. 일부 EA 입력의 합계를 전체 개수 재고로 간주하지 않음 | [피드백 반영](../history/changes/inventory-feedback-20261021.md) |
| 수불 소급·결재 | 과거 기록 소급 정정 허용, 기간 잠금 없음. 수불대장은 시스템 결재 없이 출력 후 별도 결재 | [수불 결정사항: 확정](../reference/inventory-decisions.md#확정) |
| 입고 검사·문서 | 입고 판정과 D03 작성완료가 LOT 판정에 연결됨. 문서 승인·반려가 LOT 판정을 바꾸지는 않음. PASS 입고는 검사값·점검자를 채우고 D03 작성완료 시도; 도메인 오류 시 작성중으로 남을 수 있음 | [최신 입고 연결 기록](../history/qa/qa-inventory-browsing-print-20261023.md) |
| 보류·해제 | 문서 결재와 독립. 담당자가 수동 보류하고 개선조치 확인 후 사유를 남겨 해제. CCP 이탈·승인에서 자동 보류/해제하지 않음 | [10/24 운영 기준](../reference/inventory-decisions.md#제조배치-보류해제-운영-기준-2026-10-24-공유) |
| 보류 중 처리 | 생산 시작·투입·산출·완료 차단. 배치 보류는 산출 LOT로 전파하며 독립 LOT 보류는 별도 유지 | [최신 보류 구현](../history/qa/qa-production-holds-ui-20261024.md), `backend/apps/inventory/production.py` |
| 문서 정정 | 승인본을 지우지 않고 정정 회차 생성. 새 승인 전까지 이전 승인본 유효 | [문서 정정 결정](../reference/document-decisions.md#6-정정--확정) |
| 역할·로그인 | 양식별 역할 설정에 따른 작성·결재 권한은 구현됨. 로그인은 미구현이고 현재 사용자 선택 방식. 역할 설정은 서버 파일에서 관리 | [역할·권한](../reference/document-decisions.md) |

CCP 최신 양식은 시작·종료 고정행, 1P 자력 8,000G 이상, 2B 온도 68~72℃ 및 총 건조시간 115~125분 판정을 반영했습니다. 2B 총 시간은 시작전~종료전 측정일시로 계산해 종료전 행에 표시합니다. 양식별 적용 버전과 완료 기록 보존 예외는 [문서 결정사항](../reference/document-decisions.md#2-문서--확정)을 따릅니다.

## 4. 남은 확인·협의 사항

다음 목록은 전달 시 확인할 사항입니다. 담당 구분은 협의를 위한 제안이며 확정 배정이 아닙니다.

| 우선순위 | 확인할 사항 | 확인 대상·완료 기준 |
|---|---|---|
| 전달 전 | 전달 서버가 어느 커밋·마이그레이션까지 반영됐는지 | 개발·배포 담당: 실행 커밋, DB 적용 목록, 배포 결과와 접속 확인 시각 기록 |
| 전달 전 | 실제 사용할 데이터와 화면 범위 | 개발·현업: 샘플/실자료 구분, 실제 저장 기능과 시제품 메뉴 구분, 첫 조회·출력 확인 |
| 업무 전환 전 | 새 운영 DB·실제 기준정보·기초재고 | 개발팀: v8 기준정보 초기 DB 준비·검증 완료. 바이오닷: 별도 전달 자료 수령·현업 확인. 설치 담당자: 바이오닷이 정한 환경에 초기 DB 설치. 바이오닷: 운영 시작일·재고 기준일 결정 및 실제 재고 확인 |
| 업무 전환 전 | 사용자·역할·운영 책임 | 현업·운영 담당: 양식별 담당자·팀장·작성 권한자 설정, 로그인 도입 및 접근 범위 결정 |
| 업무 전환 전 | 백업·복구·주기 문서 생성 | 운영 담당: DB+첨부+설정 백업과 복구 확인, 주기 생성 스케줄·실패 대응 확인 |
| 기능 확인 | 생산일지 현업 확인 | 문서 쪽 화면·출력은 구현됨(P15, 배합비 = BOM 줄 소요량 ÷ BOM 기준 생산량, 소수 둘째 자리). 현업: 실제 품목으로 작성 시간·출력 서식 확인. 수불은 비율 자체를 저장·계산하지 않음 |
| 기능 확인 | 취소와 연결 문서 처리 | 입고 취소는 사용·조정/결재 상태 차단 후 연결 문서 논리 삭제까지 구현됨. 제조배치 취소 문서 처리는 문서·수불 담당이 후속 확인 |
| 현업 확인 | 문서 입력·결재 흐름 적합성 | 현업·문서 담당: 성적서 재사용, 점검자·개선조치 입력 부담, 하루 문서/주 묶음 출력, 하루 50 LOT 초과 묶음 제약 확인 |
| 별도 범위 | 판매 포장·출하, 재고 예약, 수율·허용 오차, 정정/반품/폐기 입력 UX 확장 | 필요성·담당·일정을 별도 합의. 이번 MVP의 미완료 목록에 일괄 포함하지 않음 |

문서 결정사항의 ‘CCP 이탈 → 배치 보류 연동 대기’는 과거 협의 항목입니다. 이번 인수인계의 운영 기준은 **10/24 수동 보류·해제**이며, 자동 연동을 이번 완료 조건으로 되살리지 않습니다.

## 5. 배포·검증 기록을 읽는 기준

- 현재 브랜치는 `main`이 아닙니다. `8d931a3`에는 `origin/main` 병합 기록이 있으나, 이 사실만으로 전체 변경의 main 반영·서버 배포 완료를 판단하지 않습니다.
- 10/24 [선택 인쇄 검증](../history/qa/qa-bulk-print-20261024.md)은 당시 전체 검사에서 Django 1,052건 중 1,016건 통과·36건 건너뜀을 기록합니다. [BOM 목록 검증](../history/qa/qa-bom-grouping-20261024.md)에도 전체 검사 통과 기록이 있습니다. 이는 당시 실행 결과이며 이번 정리에서 재실행한 결과는 아닙니다.
- [생산일지 데이터 검증](../history/qa/qa-production-journal-sources-20261023.md)은 로컬 DB 백업·기존 값 보존 비교·마이그레이션 적용을 기록합니다. 원격 DB의 적용 증거로 사용하지 않습니다.
- [QA 자동 배포](../history/deployment/github-actions-qa-deployment.md)는 코드 전용 배포이며, 마이그레이션·SQL·의존성 변경을 거부하도록 설계됐습니다. `inventory.0008`·`0009` 및 `documents.0005`~`0007` 등의 적용 여부를 서버에서 대조하고 필요한 수동 절차를 준비해야 합니다. `0008` 전용 플래그가 다른 마이그레이션까지 허용한다고 가정하지 않습니다.
- 오래된 QA 문서의 접속 주소·포트·임시 계정·브랜치명은 작성 시점 정보입니다. 실제 전달 접속정보는 배포 담당자가 확인한 값으로 별도 전달합니다.

### 인수·설치 확인란

- [ ] 실행 서버 커밋 / 확인 시각: 미확인
- [ ] 적용 마이그레이션 / 미적용 목록: 미확인
- [ ] 접속 주소 / 접속정보 전달 경로: 미확인
- [ ] 데이터 구분(샘플·실자료) / 기초재고 기준일: 미확인
- [ ] 입고 → 생산 → 수불 → 연결 문서 → 출력 시연: 미확인
- [ ] 운영·문의 담당자 / 자료 보관 위치: 미확인
- [ ] 최근 백업 / 복구 확인 / 주기 문서 스케줄: 미확인

## 6. 인수자가 설치 후 확인할 흐름

1. 이번 범위가 제조 벌크 산출까지임을 먼저 설명합니다.
2. 원료 한 품목으로 기간 수불·현재고·LOT 상세를 보여 줍니다. 현재고와 과거 기간말 잔량의 차이를 설명합니다.
3. 테스트용 데이터에서 생산 계획 → 시작 → 실제 투입 → 산출 → 완료와 연결 수불을 확인합니다. 계획·시작만으로 재고가 차감되지 않음을 설명합니다.
4. 연결 문서 → 작성완료 → 결재 → 출력 흐름을 보여 줍니다. 사용자 선택 방식과 수동 보류·해제도 함께 설명합니다.
5. 현업 결정 사항과 설치 결과는 [남은 작업](remaining-work.md)에 기록합니다. 방문 시연을 필수 절차로 전제하지 않습니다.

화면별 설명은 [주요 업무 사용 안내](user-guide.md)와 [문서·결재 사용설명서](../reference/document-user-guide.md)를 참고합니다. 10/19 안내 이후 추가된 CSV 입고·BOM 관리·보류·선택 인쇄는 위 최신 변경 기록을 함께 봅니다. 전체 문서 탐색은 [문서 목차](../README.md)를 이용합니다.
