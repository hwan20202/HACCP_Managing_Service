# 운영·업데이트·복구 안내

바이오닷이 지정한 운영 담당자·외주 개발자가 사용하는 자료입니다. Windows 실행 예시는 [설치 안내](installation.md)에 있습니다. Ubuntu 등 다른 환경은 담당자가 해당 환경의 서비스·경로·예약 작업으로 맞춰야 합니다.

## 1. 운영을 시작하기 전에 남길 정보

개발팀은 제공받은 v8으로 기준정보만 담은 초기 DB를 준비했습니다. 전달 파일의 등록 목록과 확인사항을 대조합니다. 바이오닷이 배포 방식을 결정하면 설치 담당자가 전달 DB를 배치하고 소스 호환성·설정을 확인합니다. 운영 시작일과 기초재고 기준일은 바이오닷이 정하며 실제 재고·거래는 업무 시작에 맞춰 별도 등록합니다. QA DB와 테스트 거래는 승계하지 않습니다.

접속 주소, 설치 장비, 실행 코드 버전, 데이터·첨부·설정 경로, 서비스 이름, 백업 위치·주기, 문의·복구 담당자를 기록합니다. 개인별 로그인은 없으므로 접속 가능한 네트워크 범위와 앞단 접근 제한도 확인합니다. 사용자 역할 설정은 본인 인증과 구분합니다.

PC 재부팅 뒤 서비스가 자동 실행되는지, 문서 작성·결재에 실제 직원 코드가 사용되는지, 주기 점검표 생성 예약 작업이 실행되는지 확인합니다. 서비스 설치와 예약 작업은 문서만 전달한다고 자동 설정되지 않습니다.

## 2. 업데이트

1. 현재 버전과 새 버전, DB 구조·양식·의존성 변경 여부를 개발자가 확인합니다.
2. 앱 서비스와 별도 예약 작업 등 쓰기 작업을 멈추고 DB·첨부·설정을 백업합니다.
3. 기존 환경 설정과 데이터 경로를 보존한 채 코드·필요 의존성을 갱신합니다. 마이그레이션과 정적 파일 수집은 [설치 안내의 코드 업데이트](installation.md#4-코드-업데이트)를 따릅니다.
4. 서비스를 시작해 접속·문서·재고·첨부를 확인하고, 새 버전·백업 위치·확인 결과를 기록합니다. 중지한 예약 작업도 다시 활성화합니다.

기존 QA 자동 배포는 코드 변경용이며 DB 변경을 자동 처리하지 않습니다. [기존 QA 배포 기록](../history/deployment/github-actions-qa-deployment.md)은 그 서버를 이어받을 때만 현재 환경과 대조해 사용합니다. 새 운영 환경에서 자동 배포가 준비됐다고 가정하지 않습니다.

## 3. 백업

DB와 첨부를 같은 시점으로 보관해야 합니다. 앱뿐 아니라 주기 문서 생성·다른 쓰기 작업도 멈추고 [백업 명령](installation.md#5-db파일-백업과-복구)을 실행합니다.

- 명령으로 생성: `app.sqlite3`, `uploads.zip`, `manifest.json`
- 별도 보관: 환경 설정, 역할 파일, 주기 규칙을 별도 파일로 사용한다면 그 파일, 서비스·인증서 설정, 필요한 기준서·원본 자료, 호환되는 소스 버전
- 보관 위치: 실행 장비와 다른 저장소에도 사본 유지. 주기·보관 기간·성공 확인 담당자는 운영 시작 전에 지정

소스 저장소만 백업하면 재고·문서·첨부가 모두 보존되는 것은 아닙니다. 시제품의 브라우저 저장 내용도 DB 백업에 들어가지 않습니다.

## 4. 복구

현재 자료를 먼저 별도 보존하고, 같은 백업 묶음의 DB와 첨부를 호환되는 코드·설정으로 복구합니다. 실행 중인 DB 위에 파일을 덮어쓰지 않습니다. 구체적인 경로와 순서는 [복구 절차](installation.md#5-db파일-백업과-복구)를 따릅니다.

단순히 이전 코드로 바꾸는 것만으로 DB 변경까지 되돌아가는 것은 아닙니다. 개발자가 변경 내용을 검토한 뒤 복구 방식을 선택해야 합니다. 복구 후에는 접속, 주요 재고, 문서·승인 이력, 첨부 열기를 확인합니다. 실제 업무 시작 전에 테스트 환경에서 복구 연습을 수행합니다.

## 5. 문제가 생기면

| 증상 | 확인할 내용 |
|---|---|
| 사이트 접속 불가 | 서버 전원·네트워크·도메인·인증서, 앱·프록시 서비스와 로그 |
| 화면은 열리나 저장 실패 | 오류 문구, 현재 직원, DB 경로·디스크 용량, 적용되지 않은 DB 변경 |
| 입고·생산 시작 실패 | 필수 문서 양식 활성 상태·직원·입력값. 생산은 원료 가용량과 보류도 확인 |
| 작성·상신·결재 버튼 사용 불가 | 현재 직원·양식별 역할 파일·문서 상태·결재 칸 후보 |
| 새 화면이 반영되지 않음 | 실행 코드 버전, 정적 파일 수집·제공 경로, 브라우저 새로고침 |
| 첨부가 열리지 않음 | 파일 경로·권한, DB와 첨부가 같은 백업인지 |

업무 자료를 지우거나 샘플을 다시 넣기 전에 담당 개발자에게 오류 문구·시각·화면·최근 변경을 전달합니다.
